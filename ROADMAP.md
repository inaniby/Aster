# Aster — Roadmap

**Status as of v0.23.54-dev.** This roadmap is the forward-looking companion to
`VERSION_HISTORY.md` (what shipped) and `FEATURE_STATUS.md` (what exists today).
Every version listed here is a plan, not a promise; the history file is the only
record of what actually landed.

## Guiding principles

1. **One coherent theme per version.** Language features, tooling and packaging
   never mix in one release, so a regression can always be bisected to a single
   kind of change.
2. **Everything is proven by execution.** New features ship with negative cases,
   structural (ELF/disassembly) checks and qemu-run acceptance, all registered
   in `tests/smoke.sh`. A feature without a runtime test is not done.
3. **Byte-level reproducibility.** For every version that claims "no codegen
   change", the previous compiler's output for all `examples/*.ast` is compared
   byte-for-byte and the evidence is recorded in the validation report.
4. **Device-visible behavior closes only on hardware.** APK-level work is
   confirmed on the target device by the user before it is marked done.
5. **The single-file compiler stays single-file and dependency-free.** New
   capabilities are implemented inside `src/aster.cpp` with no external
   libraries; architecture documents describe what the code does today.

## Where we are

**v0.23.32-dev** gives `-g` a second section: **DWARF v4 `.debug_info`** beside the `.debug_line` it already wrote — a compilation unit anchored to `.text`, a `DW_TAG_subprogram` per function, and a `DW_TAG_variable` per global, local and parameter, each naming the type it was declared with. A debugger could already turn an address into a source line; now it can turn a frame slot into a name. **The frame base is free**: every Aster frame is a fixed 8192 bytes and SP does not move again inside a body, so `DW_AT_frame_base` is `DW_OP_breg31 + 0` and a slot is `DW_OP_fbreg(slot*8)` — no CFA rules, no `.eh_frame`. Every address is written as zero and carried by `.rela.debug_info` as `R_AARCH64_ABS64` **against the symbol it means**, which is what lets one encoder serve the object writer, both linkers and both shared-object paths, and gives a linked image one unit per object raised to that object's own text address. Strictly additive: 303/303 baseline rows byte-identical, 0 new. Covered by `tests/debug-info-checks.sh` [9/9].

**v0.23.31-dev** gives an array **a second subscript**: `T[N][M]`, with `a[i]` a **row** — the address of `M` elements — and `a[i][j]` the element, exactly as in C. Until now a subscript was the last thing you could do to an array, so a grid had to be flattened by hand with the row length re-derived at every use. The round adds **no new type**: an array name already decays to a `ptr` (v0.23.30-dev made that address reachable by name), so a row address is the same decay one level in — `a` is a ptr, `a[i]` is a ptr, `a[i][j]` is `i32` — and the whole feature is a question of **stride**: a subscript at dimension *k* strides by `dims[k+1] * … * dims[L-1] * sizeof(elem)`, which for the innermost subscript is the element size (the one stride a one-dimensional array has always had, which is why no pre-existing byte moves) and for an outer one is the product of the dimensions below it. Five places moved together: **`arrayDimList()` reads one `[N]` per dimension** at every declaration site while `dimsTotal()` bounds the total the way the one-dimensional spelling always did (`i32[1000][1000]` is still refused), and `count` stays the total element count so the frame reservation, the broadcast initializer, `.data`/`.bss` sizing and `layoutStruct` are untouched; **one chain shape** serves assignment and expression alike (the name on the innermost `Index`, each subscript above it another `Index`), so `a[i][j] = v` and `a[i][j]` reach the same address computation; **Sema walks the chain** (`indexChainOf`), checking *every* subscript and answering a row unless this is the innermost one; **codegen computes every subscript first and materializes the base after** in `emitIndexAddr()` (a subscript can materialize a global's address into X16, where the base is about to go) and scales by `emitElemStride`; and **a store to a row is refused**, including the single-subscript spelling, which arrives from the parser as itself and is told apart from a chain by the subscript count the parser records. The round found four holes in its own first draft — a row store accepted, an inner bool subscript unchecked, a scalar base's message hijacked by the ptr-chain check, and the one-dimensional bounds message regressed to its unnamed form — and each is a rejection-matrix row now. **288 of 288 pre-existing baseline rows are byte-identical** (300 → 303 with the new example). Covered by `tests/multi-dim-array-checks.sh` [9/9] — 12 behavioural cases, 4 gcc-differential pairs, 22 rejections, a 36-row coverage map, an 8-mutant layer (one re-creating the row-stride arithmetic, one dropping the per-level check so an inner bool literal compiles, one withdrawing the row-store refusal), and `examples/multi_dim_array.ast` exiting 255, equal to its C twin. Next: the debug-information slice (v0.23.32-dev), the fourth of the four candidates the user asked for at once.

**v0.23.30-dev** gives an array **an address**: `&buf` is a `ptr`, so a `T[N]` can be handed to a function by reference instead of having to live at file scope. `&` was defined for a struct lvalue and nothing else, so an array was the one thing in the language a function could not reach — which is why every array a function touches in the shipped corpus is a global. The round is small in bytes and large in consequence, and its shape is one observation: **the address was already there**. A local `T[N]`'s `Binding.ty` *is* `Ty::Ptr` (the array is decayed at declaration) and `gen(Var)` already emits `ADD Xd, SP, #slot*8`; a global `T[N]`'s `typeOf` answers `Ty::Ptr` and `emitGlobalAddress` materializes it. So there is **no parser change, no new instruction and no new encoding** — only the rule that lets `&` ask for an address that has always been computed. **Because a named array is decayed, "is this an array?" is a question about the length, not the type**: an `i32[4]` and a `ptr` are the same `Ty::Ptr`, so `Sema::arrayOperandOf()` answers by length in three arms — a local (`b->len`), a file-scope array (`arrayGlobals`), and a struct's array field (`arrayFieldOf`). **One honest restriction comes with it**: `p[i]` on a `ptr` is `*(p + i*4)` and Aster has no pointer type that carries a stride, so an array whose element is not four bytes wide is *refused* rather than silently mis-scaled — that admits `i32[N]`, `u32[N]`, `bool[N]` and an `S[N]` of size 4, and refuses `i64`, `u8`, `u16`, `ptr` and a 12-byte struct. `&arr` answers a plain `ptr`, because the address of an array is the address of its first element. **288 of 288 pre-existing baseline rows are byte-identical** (297 → 300 with the new example). Covered by `tests/array-address-checks.sh` [9/9] — 12 behavioural cases, 3 gcc-differential pairs, 14 rejections (six of them pinning rules that must *not* have moved), an 18-row coverage map, a 7-mutant layer (one re-creating the v0.22.50-dev frame-base bug, one making the local arm read the decayed type), 288/288 baseline rows, and the shipped example (exit 63, equal to its C twin `tests/array-address-twin.c`). Next: **multi-dimensional arrays** (`T[N][M]`), then the debug-info slice.

**v0.23.29-dev** lets a **struct field be an array** — `struct Buffers { nums: i32[4], flags: bool[3], ptrs: ptr[4], pts: Vec3[2] }` — which is the one item the previous round named as out of scope (*"a struct field is still not an array"*). The user asked for four candidate rounds at once — a struct array field, taking the address of an array, multi-dimensional arrays, and DWARF `.debug_info` — and answered *"这4项一起做"*; the roadmap's first rule is that a version is **one coherent theme**, so the four are three versions and not one: the three language features are v0.23.29-dev and v0.23.30-dev, and the debug-info slice follows as a toolchain round of its own. This one moves four things together. **`StructField` gained a length**, so `layoutStruct` reserves `sizeof(element) * len` bytes and every read, store and address computation reads it back from the field it named. **`.` and `[` are collected by one interleaved postfix loop**, because the old shape was a dot chain followed by a bracket chain and the first thing anyone writes is a bracket *followed by* a dot — `b.pts[1].a`. **The element address is composed** (`emitElemAddrField` = `emitStructAddr` over `emitElemIndex`), so a 12-byte element is scaled by a multiply here for the same reason it is inside a named array, with no second copy of that arithmetic. **Bounds checking split by what it knows** — a named array by name, a field by length. A struct containing an array field **cannot be built by a literal**, so a struct `let` may now carry no initializer at all and is zero-filled — and that zero-fill is where the round's real bug lived: it stored `x0` where it meant `XZR` (`Rt == 0` is `x0`, **not** 31), so every uninitialized struct local was filled with whatever `x0` held; the shipped example had been surviving by luck, and the `ptr` battery case is the first witness that can see it. **288 of 288 pre-existing baseline rows are byte-identical** (294 → 297 with the new example). Covered by `tests/struct-array-field-checks.sh` [9/9] — 8 behavioural cases, 2 gcc-differential pairs, 10 rejections, a 14-row coverage map, a 6-mutant layer (three re-aimed), 288/288 baseline rows, and the shipped example (exit 63, equal to its C twin `tests/struct-array-field-twin.c`). Next: **taking the address of a whole array** (`&arr` → `ptr`, so a `T[N]` can be passed by reference), which is v0.23.30-dev above, and after it **multi-dimensional arrays** (`T[N][M]`), then the debug-info slice.

**v0.23.28-dev** opened the array's element type: **`T[N]`'s element is `T`**, whatever `T` is. The user asked whether the basic types need扩充 (*"现在编译器基本类型有哪些，需要扩充完善没？"*); they do not — `i32` `u32` `i64` `u8` `u16` `ptr` `bool` and a struct are all there, with sizes, alignments and rules. What was missing is what a type means *inside an array*, where `T` could only ever be an integer. Three places disagreed with the sentence: **a local `bool[4]`, `Point[4]` or `ptr[4]` did not parse** (the `[N]` suffix was gated on the type being an integer, and a local `ptr[4]` had a refusal of its own); **a global `bool[4]` or `Point[4]` did not parse** (`globalDeclaration()`'s Bool and Struct branches never looked for a `[`, although the scalar branch below them did); and **`typeOf(a[i])` answered `i32`** whatever the element was, so `let q: Point = a[1];` was a type error against itself. Underneath sits one rule: **a struct element is scaled by a multiply, not by a shift**, because a struct's size need not be a power of two — `elemShiftOf` answers -1 and `emitElemIndex` falls back to `UMADDL`, *not* to `ADD Xt, XZR, Widx, UXTW #0`, whose `Rn == 31` is the stack pointer and not XZR. Every element address is now computed in one place (`emitElemAddr`), an element is an lvalue (`&a[i]`, `a[i].f = v`, a whole-element parameter), and a `bool` element is a condition. **288 of 288 pre-existing baseline rows are byte-identical** and the three new rows are the new example's output modes. Covered by `tests/array-elem-types-checks.sh` [9/9] — 24 behavioural cases, 6 gcc-differential pairs, 28 rejections, a 30-row coverage map, a 15-mutant layer (two of which had to be re-aimed at witnesses that can actually see the damage), 288/288 baseline rows, and the shipped example (exit 127, equal to its C twin). Deliberately not included: a struct *field* that is an array, an element type for a `ptr` local's subscript (`p[i]` still means `*(p + i*4)`), a whole struct element as a value, multi-dimensional arrays, and arrays as parameters or return values.

**v0.23.27-dev** closed the four places Aster read an expression differently from C — all four found by writing `docs/language-reference.md` down and running every claim in it against the binary, and three of them silent rather than loud. **`&&` now binds tighter than `||`** (they were one level, so `a || b && c` was `(a || b) && c`); **`-` `!` `~` `*` now take a `unary()` operand** (they took a `primary()` one, so `-s.v` was `(-s).v` and in practice rejected); **`a < b == c` compiles** (the anti-chaining gate now asks about a chain *within one level*, which is what the comment above `relational()` always promised); and **a local `let` is range-checked like a global one** (`let b: u8 = 300;` used to store 44). All four are parser or type rules, so the round carries no codegen at all: **288 of 288 pre-existing baseline rows are byte-identical** and the three new rows are the new example's output modes. Covered by `tests/precedence-checks.sh` [9/9] — 33 behavioural cases, 5 gcc-differential pairs, 16 rejections, a 33-row coverage map, and a 12-mutant layer whose last four mutants separate "the check exists" from "the check is reachable": two withdraw it from one pass only and must still be refused by its twin, two withdraw it from both and must accept.

**v0.23.26-dev** answered the question a pointer always asks first: **is this thing null?** Before it a `ptr` could not be tested at all — `if (p)` was refused (a ptr is not a truthy type, v0.23.25-dev's rule), `p == 0` was refused by three copies of "pointer comparison is not supported yet", and there was no way even to *write* a null, since `let p: ptr = 0;`, `f(0)` and `return 0;` from a `-> ptr` function were all type errors. The round is one idea: **the literal `0` in a pointer context is the null pointer constant**, as in C — it initializes a ptr, is assigned to one, is passed to one and is returned from one — and `==`/`!=` then answer *are these the same address* and *is this address nothing*, including `ptr<S>`. **No new instruction was needed**: `tyIs64` already counted a ptr, so the comparison path was already emitting `CMP Xn, Xm`; the round is entirely a matter of which programs the type rules admit, which is why the byte baseline holds by construction. Two boundaries are deliberate: ordering two addresses stays rejected, and `if (p)` stays rejected. The predicate's one subtlety is `false` — a Bool literal whose value is also 0 — so `isNullConstant` consults the `boolLit` flag, and mutant m3 proves the refusal is live. Covered by `tests/null-ptr-checks.sh` [9/9] — 19 behavioural cases, 5 gcc-differential cases, 26 rejections, a 22-row coverage map, an 8-mutant layer (two of which had to be re-aimed: a condition runs through `emitCondition`, not `genBool`, and allowing `p < q` requires withdrawing the rule from *both* passes), 288/288 baseline rows, and the shipped example (exit 33, equal to its C twin). Full CI: **83 passed / 0 skipped / 0 failed**.

**v0.23.25-dev** taught the control flow what every other language's does: conditions accept **any integer — 0 is false, non-zero is true** — and the language gained its first `bool` literals, `true` and `false`. Conditions had accepted exactly one form, a comparison, because a `bool` could only be produced by a comparison operator: `Expr::Num` was born carrying an `i32` and nothing else, so there was nothing to write `if (x)` with. The literal is a `Num` with a `boolLit` flag (the two `typeOf` twins answer `Ty::Bool` for it, the stored value stays 0/1), and the condition machine — already shared by `if`/`while`/`for` — now takes a comparison (the untouched `CMP`/branch fast path, which is why the byte baseline holds), a `bool` (measured against zero as a comparison's answer already was), or an integer tested against zero **at its own width** (`CMP Wn,#0` for the narrow types, the new `CMP Xn,#0` for `i64` — a 32-bit compare of a value past four billion reads as zero). The boundary is deliberate: `?:`, `&&`, `||` and `!` stay strictly `bool`, so truthiness lives in conditions and nowhere else. The literal exposed four gaps, all filled in the round: `genBool` had never handled `Field`/`Cond` (`if (s.b)`, `c ? a : b` died in codegen though sema typed them `bool`); arithmetic silently accepted `bool` operands (`1 + true`, `a[true]` compiled — now one `rejectBool` guard at all 16 sites); `constantInteger` folded `true` to `1`; and global/struct initializers had no type gate for the new literal. A drafted `isBoolConstant` branch for `boolLit` was withdrawn as unreachable by construction rather than shipped untestable. Full CI: **82 passed / 0 skipped / 0 failed**.

**v0.23.24-dev** shipped the round the candidate queue had named as "a language-design round of its own": **`op(x)` — a call through a `ptr` variable**. Taking a function's address had worked since the callback-table work, but every call site emitted a relocated `BL` and no `BLR` existed, so the address could be stored, passed and handed to C yet never *called* — the callback shape (`fn apply(op: ptr, x: i32) -> i32 { return op(x); }`) was one instruction away and unreachable. The language surface is one sentence (`fp(args)` with `fp` a `ptr` local, global or parameter) and needed **zero parser change** — `primary()` has always produced `Call{name}` for `Ident(` — so the feature is dispatch in the three call sites that already exist, and a function name in call position is still a direct call (the function always wins, the user-function-shadows-intrinsic rule). There is no function type, hence no signature, and that is the round's one real design decision: **every scalar argument rides at 64-bit width** (an `i32`-declaring callee reads the low half — exactly the bits a 32-bit stage would have put there — an `i64`-declaring one a properly extended full register, since AAPCS64 leaves a sub-64-bit argument's upper half unspecified) and the call answers `i32`. *(v0.23.37-dev shipped the function type — `fn(P1,..,Pn) -> R` — retiring this rule for typed callees; a bare `ptr` keeps it, unchanged.)* The callee's address is materialized into **X9** after the arguments are in their registers and before SP moves — X9–X15 hold nothing live, so no park/restore change and no risk to the direct path — and the global case loads what the global *holds* (the first cut loaded the global's own address and segfaulted; mutation m6 pins the fix). The second half is the static linker: `let fp: ptr = f;` used to fail to link ("global address relocation references a function symbol") — a `.so` restriction (its text cannot carry load-time relocations) that static images do not need, since they know function addresses at link time and ADRP/ADD is PC-relative; `linkObjects` now passes `funcAddrDirect=true` and the `.so` path is untouched. Sema refuses a non-`ptr` callee, an array, an undeclared name, a struct argument (no signature to lay one out) and an extern function's address. New resident suite `indirect-call-checks.sh` [7/7]: 19 gcc-differential cases (five callee forms including the `load_ptr(&struct)` dlsym shape, the full argument-shape matrix, the precedence case), a `.so` structural check, the shipped example run against its C twin (`examples/indirect_call.ast` exits 144, equal to the oracle), 10 rejections, a coverage map and an 8-mutant layer. Baseline 279 → 282 lines, the other 279 byte-identical. Candidate next rounds: **the debug-information slice** (`.debug_info` on top of the v0.23.12-dev line table), then the audit-ranked backlog.

**v0.23.23-dev** completed the raw-memory width ladder — the difficulty audit's first item and the round-4 narrow matrix's last cell: **`load_u16`/`store_u16` (`LDRH`/`STRH`) and `load_i64`/`store_i64` (`LDR X`/`STR X`)** now join `load_u8`/`store_u8`/`load_ptr`. An "API-missing" difficulty rather than a deep one — the encodings had existed since the stack-path work — which is exactly why it survived: nothing was broken, four names simply did not exist, and the `i64`-through-a-pointer read meant eight `load_u8`s, seven shifts and seven ors with a `<< 32` trap in the middle (on an `i32` the shift count wraps, so `1 << 32` is `1` — measured, and no self-comparison could have seen it). The contracts mirror the byte pair: the halfword pair is `i32` in / `i32` out (zero-extended read, low-16 store answering the *original* value — the byte pair's documented contract, not C's assignment-expression value), the quadword pair is `i64` in / `i64` out, and `store_i64` widens an `i32` by sign-extension (`gen(..., Ty::I64)`, the same rule as an `i64` local) while rejecting `bool`. Four intrinsics × three dispatch sites (`checkCall`, `callType`, `gen`), each behind the shadow guard — the user's function wins, always — now proven for eight intrinsic names. New resident suite `narrow-memory-checks.sh` [7/7]: 24 gcc-differential cases (every width round trip, truncation, zero-extension at both consumer widths, an unaligned offset, loops, helpers, cross-width aliasing, the sign-extension and narrowing edges, and six shadowing cases including a partial shadow), 8 rejections, a coverage map, and a 7-mutant layer that disables each dispatch / drops the `callType` i64 answer / reverts the widening call / removes a shadow guard and requires the battery to go red. Baseline 276 → 279 lines, the other 276 byte-identical. Candidate next rounds: **the debug-information slice** (`.debug_info` on top of the v0.23.12-dev line table) — function-pointer calls shipped in v0.23.24-dev (see the top of this section).

**v0.23.22-dev** closed the grammar's two most-felt gaps, both pure syntax relief with zero codegen delta: **`else` is optional** (`ifStatement`'s `need(TK::Else,…)` became `if(eat(TK::Else))` — an absent else leaves elseBody empty, `block({})` emits nothing, and sema's `definitelyReturns` already demanded both branches, so the 276-row byte baseline holds by construction) and **hexadecimal literals** (`0x`/`0X` + at least one hex digit in the lexer; `unsignedLiteral` picks base 16, so array lengths inherit hex for free). Both gaps had been ranked first by the round-4 difficulty audit and one was named directly by the user: `else` used to be mandatory, so `examples/icon_text_demo.ast` carries an `} else { }` whose only purpose is to satisfy the grammar, and `else { if … }` — the explicit spelling of what `else if` desugars to — did not parse unless the inner `if` dragged an else along. New resident suite `syntax-relief-checks.sh` [7/7]: 13 if/else shapes and 14 hex values, all gcc-differential (exit statuses compared, no hand-computed expectations), 5 rejections, source guards that fail if either old restriction returns, and a mutation layer that re-mandates `else` / disables the hex branch and requires the batteries to go red.

**v0.23.21-dev** gave the static ELF its own voice: `write(fd, buf, len)` is one `write(2)` system call (`x8 = 64`), so a single-file program prints without libc, a `.so`, or a `dlopen` host — `main`'s return was already `exit` (x8 = 93), and output had no reason to be different. Implementing it surfaced the round's real lesson: `x0/x1/x2` are simultaneously the syscall argument registers and the first three temporaries of the `w0–w15` pool, and three successive clobber failures fell out of that collision before the shipped version adopted `emitCallSeq`'s park-and-restore discipline. New resident suite `write-output-checks.sh` [4/4] (16 gcc-differential cases on three channels — stdout bytes, stderr bytes, exit status — including five that pin *user functions shadowing intrinsics*, a defect the first full CI run caught in `runtime-bounds-checks.sh` — plus 4 rejections and a coverage map pinning the three clobber regressions). Baseline 273 → 276 lines, the rest byte-identical. The `.so`+libc path is untouched and remains the Android story.

**v0.23.20-dev** closed the blind spot that let the v0.23.19-dev `u8`-parameter defect survive five releases. The repair in round 3 was correct, but no example in the tree had ever passed a narrow argument, so the 261-line A/B byte baseline was blind to the argument-passing path. This round adds four examples that carry `u8`/`u16`/`i64` values through calls, returns and a `.so` (baseline 261 → 273 lines, the rest byte-identical) and a new resident suite `narrow-value-coverage.sh` [4/4] whose expected values are generated by `aarch64-linux-gnu-gcc` at run time rather than hand-computed — the discipline round 4's own miscalculated expectations demanded. The round-4 probe of the other faces (`bool`, string/rodata, global-init order, struct-array fields, multi-file link signatures) found zero real defects and they stay covered by their suites. Next narrow-type item if any: none known — the matrix is closed.

**v0.23.19-dev** fixed the `u8`-parameter defect itself (see `VERSION_HISTORY.md`): an unscaled byte offset above 4095 set bit 22 and turned a `STRB` into a `LDRB`, so a `u8` argument was stored by loading it; `stackOffFits` + `loadStackOff`/`storeStackOff` range-check every offset per width and stage the address through `x16`/`x17` when it does not fit. Covered by `narrow-int-abi-checks.sh` [7/7].

**v0.23.1-dev** shipped run-time bounds checking behind `--bounds-check` (P1.5),
the other half of array safety: constant out-of-bounds indexes were already a
compile-time error, and now every *dynamic* index into a fixed-size array —
global or local, read or write — is compared against the array's length and
traps with `BRK #1` (SIGTRAP) when it is out of range. One unsigned comparison
covers both halves of the range, because a negative index is a huge unsigned
value. The flag is off by default, so a default build emits no test at all and
all 82 examples still compile byte-identically; constant indexes are skipped
(the compile-time fold already proved them in range), so even a flag-enabled
build of a constant-index program is unchanged. The same release fixed a latent
encoding bug: `CMP Wn, #0` was `SUBS` with `Rd = w0` instead of `Rd = WZR`,
silently overwriting a live expression temporary.

**v0.23.0-dev** shipped the standalone semantic pass (P3.1): every emitted
function is now type-checked over the AST — with its own scope stack and a
three-type lattice (`i32`, `ptr`, `bool`) — *before* any instruction is emitted,
instead of being checked as a side effect of code generation. Constant folding
and comparison classification were hoisted to file scope so the two passes share
one definition and cannot drift. Codegen keeps its checks as a defensive
backstop, so no rule can be silently dropped: all 82 examples still compile
byte-identically, and every pre-existing rejection still reports the same
message. The only intended behavior change is ordering — a type error is now
reported instead of a later codegen diagnostic.

**v0.22.51-dev** shipped the `bool` type, the logical operators `&&` / `||` /
`!` (short-circuiting), and `else if` chains (P1.3, P1.4): comparisons are now
ordinary bool expressions that can be stored, passed and returned; bool is a
type of its own with no implicit conversion to or from `i32`; and a bool value
is materialized with `CSET`. Comparisons used as conditions keep the original
`CMP` + conditional-branch shape, so every pre-existing example still compiles
byte-identically.

**v0.22.50-dev** shipped `for` loops and this governance document set, and
fixed a latent local-array frame-base encoding bug inherited from v0.22.49-dev
(the `ADD Xd, SP, #slot*8` immediate had its `sh` bit set, scaling the offset by
4096 — invisible while the array sits in slot 0, corrupting memory otherwise;
all three base materializations now use the `sh=0` encoding, guarded by a source
check and a dedicated qemu regression).

The compiler builds AArch64 ELF executables, static PIEs and shared objects
directly, links multi-object programs, and packages signed Android APKs — all
from one 2.5k-line C++17 file with zero dependencies. The language covers the
subset needed for native Android activities: i32/ptr/bool values, fixed-size
arrays (global and local), pointers with 4-byte-stride indexing, `if`/`else if`
chains, `while`, `for`, the logical operators `&&` / `||` / `!`, function calls
with up to 32 arguments, and global data with run-time initializers. Type
checking is a pass of its own (v0.23.0-dev) ahead of code generation, and array
indexes can be checked at run time as well as at compile time (v0.23.1-dev).

## Deliberately not planned

- **A general-purpose optimizing backend.** Aster emits straight-line code per
  expression; the 8 KiB frame and the w0–w15 temporary pool are part of the
  documented contract, and programs are small by construction.
- **A package manager or build system.** `link-obj` plus `extern` declarations
  cover multi-object programs; anything larger belongs outside the compiler.
- **A managed heap / garbage collection.** Memory is the frame, globals, and
  the raw `mmap`/`brk` the kernel offers (shipped v0.23.41-dev — an allocator
  built on them is the program's own, as `examples/arena.ast` demonstrates,
  and `stdlib/aster_std.ast` rides on the same primitives); what Aster will
  not own is a collector tracing it.
