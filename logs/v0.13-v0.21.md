# Version log: v0.13.1 – v0.21.0

These sections are reproduced verbatim, including their original `## ` headings. For the condensed per-version history, see `docs/VERSION_HISTORY.md`.

## v0.18.0 additions

v0.18.0 turns the shared object into a real dynamic library: it can be produced by linking objects, it
can call into and read/write data of another `.so`, and it names itself and its dependencies.

### New command surface

| command | meaning |
| --- | --- |
| `build-obj --pic SRC -o OBJ` | position-independent `ET_REL` object (GOT-slot global addressing, no `_start`, `main` is an ordinary function) |
| `link-so OBJ [OBJ...] -o LIB` | link one or more `--pic` objects into a shared object |
| `build-so SRC -o LIB --soname NAME` | write `DT_SONAME` |
| `build-so SRC -o LIB --needed DEP` | write `DT_NEEDED DEP` (repeatable) |
| `link-so OBJ... -o LIB --soname NAME --needed DEP` | same options for `link-so` |

Without any of the new options and without `extern` imports, `build-so` still writes the v0.17.0
byte layout.

### New ELF material

* `.plt` — one 16-byte stub per imported function: `ADRP x16,page(slot)` / `LDR x17,[x16,#lo12(slot)]` /
  `BR x17` / `NOP`.
* `.got.plt` — `GOT[0] = &_DYNAMIC` (an `R_AARCH64_RELATIVE` slot), `GOT[1..2]` reserved, then one
  `R_AARCH64_JUMP_SLOT` slot per imported function.
* `.got` — one slot per data address; `R_AARCH64_RELATIVE` for the object's own globals,
  `R_AARCH64_GLOB_DAT` for imported ones.
* `.rela.plt` plus `DT_JMPREL`/`DT_PLTRELSZ`/`DT_PLTREL`/`DT_PLTGOT`; `DT_BIND_NOW` and
  `DT_FLAGS = DF_BIND_NOW`.
* `DT_SONAME` and `DT_NEEDED` strings in `.dynstr`; every defined global added to `.dynsym` as a
  defined `STT_OBJECT`; `.hash` now covers exports *and* imports.

### New examples

| file | what it is |
| --- | --- |
| `examples/so_link_lib.ast` | exporting library: `counter`, `add`, `mul`, `bump`, `value` |
| `examples/so_link_import.ast` | imports `counter`, `add`, `mul`; defines `call_add`, `call_mul`, `read_counter`, `bump_counter`, `add_counter` |
| `examples/link_so_part_a.ast` | PIC part A: `base`, `add`, `scaled` |
| `examples/link_so_part_b.ast` | PIC part B: uses `base`/`add` from part A inside the same `.so` |
| `examples/link_so_client.ast` | a `.so` that imports from a `link-so` output |

### Verification, and which result comes from where

| evidence | where it comes from |
| --- | --- |
| `tests/so-dyn-checks.sh` (17) | python3 ELF reader **and** real binutils `readelf -d/-r`; no image is executed |
| `tests/e2e-so-import.sh` (21) | generated `.so` files are really `dlopen`ed/`dlsym`ed |
| `tests/run-on-device.sh` (63) | the device itself: real bionic loader, real `dlopen` |
| `tests/regression-symtab.sh` (13) | proves the legacy `.so`/`ET_EXEC`/`ET_REL` bytes did not move |

On a non-AArch64 build host the execution suites run under `qemu-aarch64` + glibc, which is what the
cloud self-test used; the checks that only a real device can settle are the bionic loader behaviour
(`/system/bin/linker64`), eager `JUMP_SLOT`/`GLOB_DAT` resolution and the real `dlopen`/`dlsym` call
sequence — those are exactly what `run-on-device.sh` runs.

### Device test steps

```sh
# on the phone, after unpacking aster-v0.18.0.zip (e.g. into /data/local/tmp/aster-v0.18.0)
CXX=g++ sh tests/run-on-device.sh        # or CXX=clang++
```

Expected output: one `PASS:` line per check, no `FAIL:` line, and these final lines:

```
PASS: device dynamic linker loaded 3 mutually dependent shared objects; all cross-.so PLT/GOT calls matched
PASS: v0.17.0 single-source shared object (DT_HASH + R_AARCH64_RELATIVE) still loads on the device
PASS: all Aster v0.18.0 shared-object device tests
PASS: all Aster v0.17.0 function, argument, recursion, global-variable, linked-object, and static-PIE device tests
```

That is **63 PASS** in total. The script builds the compiler, the examples and the `dlopen` hosts with
the device's own compiler, so it needs nothing but `sh`, a C/C++ compiler and the platform dynamic
linker; it sets `LD_LIBRARY_PATH` to the directory holding the freshly built `.so` files so that
`DT_NEEDED` resolution succeeds. If a specific device refuses `LD_LIBRARY_PATH` for the calling
process, pass an absolute path to `--needed` instead (the value is written verbatim into `.dynstr`).

The other suites that read images back with `readelf`/`nm` or with python3 are meant for a development
machine; they are not required on the phone.

## v0.17.0 additions

- Added a **source-level symbol table** to every final product. `ET_EXEC` (`build-elf`, `link-obj`), the static PIE (`build-pie`, `link-pie`) and the shared object (`build-so`) now emit `.symtab` + `.strtab`, and `ET_EXEC`/PIE gained the section header table they never had (v0.16.0 wrote `e_shoff = e_shnum = e_shstrndx = 0`). `.so` already had a section table and only gained two sections. See *Source-level symbol table*.
- Coverage is every source-level function (`STT_FUNC`) and every source-level global variable or array (`STT_OBJECT`), under its source name, including the v0.16.0 arrays. `st_value` is the final link address in `ET_EXEC`, an image offset in a static PIE (the same frame as `e_entry`), and the link-time virtual address in a `.so`; `st_size` is 4 for an `i32` scalar and `4 * length` for an `i32[length]`; `st_shndx` points at `.text`/`.data`/`.bss`, with `.bss` a `SHT_NOBITS` section; binding is `STB_GLOBAL` throughout. The entry function is published as `main` plus the ELF entry alias `_start`. Compiler-synthesized `__aster_init*` routines are deliberately not published.
- The new bytes are appended after the last loaded byte, so the program header table, the entry point, every segment's `FileSiz`/`MemSiz`/`VirtAddr`/`Flags`/`Align` and all pre-existing section contents are identical to v0.16.0; for `ET_EXEC`/PIE the whole v0.16.0 file is a byte-identical prefix once the four section-table header fields are masked. No executable semantics change. See *The redefined regression standard*.
- No debug information: no `.debug_*` section, no DWARF, no line numbers — a name table only.
- Added `tests/regression-symtab.sh` (the new-vs-old proof, with v0.16.0 fixtures in `tests/baseline/v0.16.0/` and an `ASTER_V16_DIR` mode that regenerates them from a real v0.16.0 compiler), `tests/symtab-checks.sh` (structural `.symtab` checks for all three products), `tests/e2e-symtab.sh` plus the target host `tests/sym-host.c` (executing every product that carries a `.symtab`, including three random-base runs of the PIE through `tests/pie-loader.c`, and reading the table back with real `readelf -s`).
- Added examples `symbols_demo` (function + `.data`/`.bss` scalar and array globals) and `symbols_init` (a run-time initializer together with an array).
- Restated two old file-shape assertions (`pie-so-checks.sh`, `linker-checks.sh`) under the new standard, keeping their coverage and their PASS counts; synchronised every version string to 0.17.0.

The static PIE carrying a `.symtab` also ran through `tests/pie-loader.c` at three freshly randomized bases with the same exit status, and the `.so` carrying a `.symtab` was `dlopen`ed and its `bump`/`main` resolved with `dlsym` and called with the expected results — which only holds if the appended sections disturbed neither the load segments nor the relative relocations.

Explicit limitation: everything above was executed on Linux (glibc) with `qemu-aarch64`, plus the host's own `binfmt_misc`-routed AArch64 execution path for `run-on-device.sh`. **Android's bionic loader itself is still not covered** — no product was loaded by bionic, and no APK/NDK packaging was attempted on a device. The Nubia NX789J test device's file channel was not available for this release, so the on-device run was done on the AArch64 Linux host instead. This is a carrying-forward item, not a claim of bionic support. What changed this round: the **lifecycle callback wiring** — the one remaining gap README previously flagged — is now proven **off-device**, because `tests/lifecycle-callbacks.sh` loads `examples/lifecycle.ast` as a shared object and drives all seven `ANativeActivityCallbacks` lifecycle slots through the same function pointers Android would call, under `qemu-aarch64` with a host liblog stub in place of liblog. Only the bionic *loader* (and a real-device APK/NDK run) stays open; the instruction stream the callbacks execute is the one a phone would run.

Still missing after v0.17.0:

- No DWARF and no `.debug_*` section; the symbol table carries names, sizes and addresses only.
- No symbols for function parameters or function-local variables.
- `__aster_init`/`__aster_init_next`/`__aster_init_end` remain unnamed in `.symtab` (deliberately: they are not source-level names). They are visible in an `ET_REL` object's symbol table and, for `__aster_init`, in a shared object's `.dynsym`.
- `link-so` (linking several `ET_REL` objects into a shared object) is still absent; `build-so` consumes a single source file.
- `DT_GNU_HASH`, `DT_SONAME`, `DT_NEEDED` and cross-`.so` imports are still absent.

## v0.16.0 additions

- Added fixed-length `i32` arrays: `let buf: i32[8] = <const>;`. The length follows the element type (`i32[length]`), keeping the element type next to its length and matching the existing `name: type` shape. `buf[index]` reads and writes one element; the subscript is any `i32` expression, scaled by the 4-byte element width, and the base is still materialized with the `ADRP`+`ADD` pair. Zero initializers go to `.bss`; a non-zero constant initializer is broadcast to every element in `.data`. There is **no bounds checking**. Arrays cannot be function parameters, return values, or used as a whole (`buf` without a subscript, or `buf = ...`, is rejected) — index them instead. Cross-object arrays use `extern let buf: i32[8];`. Local (stack) arrays are not implemented and are rejected with a diagnostic.
- Added run-time global initializers: a scalar global's initializer may be any expression (reading other globals, calling functions, arithmetic). Constant initializers still fold to a static value; non-constant ones are compiled into an internal `__aster_init` routine.
- Initialization model and order: the object that defines `main` places a `BL __aster_init` before the first user statement of `_start`, and `__aster_init` performs the unit's run-time assignments in **source declaration order**. Each object's routine chains through `__aster_init_next` to the next object's routine in **command-line link order** (`link-obj a.o b.o` runs `a.o`'s initializers, then `b.o`'s); the last one calls a synthesized `RET`. A static PIE has no loader that would run a `.init_array`, which is why the call is emitted explicitly in `_start`. Reading a global that a later object has not initialized yet observes zero — the compiler performs **no cross-object dependency inference**. The machinery is emitted **only** when at least one non-constant global initializer exists, so a program without run-time initializers produces the same code as v0.15.0 (verified for every v0.15.0 example in `build-elf`, `build-pie` and `build-obj`, and for the multi-object links).
- Shared objects have no `_start`, so `build-so` additionally publishes the generated routine through `DT_INIT_ARRAY`/`DT_INIT_ARRAYSZ` (with an `R_AARCH64_RELATIVE` relocation on the array); the loader runs it during `dlopen`.
- Added `@align(N)` on global declarations, e.g. `let buf: i32[8] @align(64) = 0;`. `N` must be a power of two, at most 4096; otherwise it is a compile error. Alignment is applied to the offset inside `.data`/`.bss`, the symbol's `st_value`, and the section's `sh_addralign`, and the linker aligns each input object's contribution to its section alignment so the layout survives linking.
- Added examples (`array_rw`, `array_sum`, `array_bss`, `array_index_expr`, `array_extern_main`/`array_extern_defs`, `runtime_init`, `runtime_init_order_main`/`runtime_init_order_defs`, `align_global`), the structural/diagnostic `tests/global-deep-checks.sh`, the execution suite `tests/e2e-global-deep.sh` (fixed-address, static PIE, and a `dlopen` host for the shared-object initializer), and extended `tests/run-on-device.sh`.
- The old `tests/global-checks.sh` "non-constant initializer rejected" case is replaced: a non-constant scalar initializer is now a run-time initializer and the program runs with the expected result.

## v0.15.0 additions

- Added `build-pie` and `link-pie`: a **static PIE** (`ET_DYN` executable) with `p_vaddr == p_offset`, a page-aligned segment layout, `e_entry` expressed as an offset, and no `PT_INTERP`, `PT_DYNAMIC`, or relocation records. `build-elf`/`link-obj` keep their `0x400000` link base and now go through a base/type-parameterised writer, so their output is byte-for-byte identical to v0.14.0 for all 33 examples.
- Added `build-so`: a **shared object** (`ET_DYN` `.so`) with `.dynamic`, `.dynsym`, `.dynstr`, a `DT_HASH` table, the `DT_RELA`/`DT_RELASZ`/`DT_RELAENT`/`DT_RELACOUNT` tags, and one `R_AARCH64_RELATIVE`-relocated `.got` address slot per defined global. Exported functions are resolvable with `dlopen`/`dlsym`.
- Added the `.got` section and a per-global GOT-style address sequence used only in shared-object mode, which makes the relative relocations load bearing.
- Factored relocation patching into `resolveRelocations`, shared by the executable linker and the shared-object writer, and parameterised `writeElfBytes`/`linkObjects` by link base and ELF type.
- Added shared-object diagnostics: `shared object mode cannot call external function: X`, `shared object mode cannot reference external global variable: X`, and `shared object must define at least one function`. Shared-object mode has no entry point, so `main` becomes an ordinary exported function there and may take parameters.
- Added examples `pie_global_rw`, `pie_modular_main`/`pie_modular_helper`, and `so_math`.
- Added `tests/pie-so-checks.sh` (static `ET_DYN` metadata, `DT_HASH` lookup, relative relocations, new-mode diagnostics), run from `smoke.sh`; added `tests/e2e-pie-so.sh` plus the target hosts `tests/pie-loader.c` and `tests/so-host.c` for the executed checks.
- Extended `tests/run-on-device.sh` with the static-PIE programs and synchronised the version strings in the test scripts.

## v0.14.0 additions

- Added file-scope global variable declarations `let name: i32 = <constant>;`, readable and writable from any function.
- Added `.data` (non-zero initializer) and `.bss` (zero initializer) section generation for both `ET_REL` objects and `ET_EXEC` executables.
- Added a second `R+W` `PT_LOAD` program header for executables with data; the fixed `0x401000` text layout, `_start` entry semantics, and the single-header output of global-free programs are unchanged.
- Added `STT_OBJECT` symbols with size 4 and correct `st_shndx` for globals, including undefined `extern let` references, and cross-object resolution of global-variable symbols.
- Added `R_AARCH64_ADR_PREL_PG_HI21` (275) and `R_AARCH64_ADD_ABS_LO12_NC` (277) relocation support alongside `R_AARCH64_CALL26` (283), with instruction-encoding validation and range checks in the linker.
- Added `extern let name: i32;` for declaring globals defined in another object file.
- Defined and tested the shadowing rule: parameters and locals shadow same-named globals and the global is restored when the scope ends.
- Added new examples (`global_rw`, `global_bss`, `global_mixed`, `global_shadow`, `global_shared_main`/`global_shared_defs`) and a new `tests/global-checks.sh` covering `.data`/`.bss` layout, object symbols, relocation types, cross-object global read/write, duplicate global definitions, non-constant initializers, unresolved global references, and shadowing.
- Extended `tests/run-on-device.sh` with the end-to-end global-variable programs.

## v0.13.1 additions

- Fixed a critical prologue bug: non-main functions now actually store `x30` (LR) at `[SP, #8184]`, matching the epilogue load. v0.13 had the restore but omitted the save, causing a segmentation fault on device function-call tests.
- Added typed `i32` parameters and argument lists with up to eight arguments.
- Added external function declarations for cross-object signatures.
- Added argument-count and duplicate-parameter diagnostics.
- Added AArch64 argument passing through `w0`–`w7` and parameter spills to stack slots.
- Added `x30` save/restore in non-entry functions to support nested calls and recursion.
- Added tests for nested calls, recursive factorial, and cross-object parameter passing.

## v0.18.1 robustness update

v0.18.1 hardens decimal literal parsing: excessively long integer literals, array lengths, and alignment values now produce a concise Aster diagnostic with source line/column instead of leaking the C++ standard library's `std::out_of_range` exception text. Values that fit the host integer type but exceed Aster's documented limit continue to receive the specific range diagnostic. This is a parser/error-quality patch; generated code and ELF layouts are unchanged.

## v0.19.1 GNU hash update

Shared objects now publish both SysV `DT_HASH` and GNU `DT_GNU_HASH`, including the GNU hash header, bloom filter, bucket and chain data. Keeping both tables preserves compatibility with older dynamic loaders while allowing GNU-hash-aware loaders to use the new table. The implementation bucket-sorts defined dynamic symbols, emits per-bucket chain terminators, sizes the Bloom filter to the defined-symbol set, and keeps undefined imports after the hashed range. Relocation symbol indices are now resolved by symbol name, so dynamic-symbol ordering can follow the GNU hash ABI rather than relying on fixed export/import positions. `tests/gnu-hash-checks.sh` independently verifies the hash metadata and is included in `tests/smoke.sh`. GNU RELRO is deferred until the writable segment layout can be split without accidentally making application data read-only.


### v0.19.1 GNU Hash hardening

The GNU hash table now uses multiple buckets and a sized Bloom filter. Defined dynamic symbols are sorted by `gnu_hash(name) % nbuckets`, each non-empty bucket has a correctly terminated chain, and undefined imports are placed after the hashable definitions. `R_AARCH64_JUMP_SLOT` and `R_AARCH64_GLOB_DAT` relocation symbol indices are derived from the final `.dynsym` mapping. The independent `tests/gnu-hash-checks.sh` validates bucket ordering, Bloom bits, chain values and termination, and continued SysV `DT_HASH` compatibility.

## v0.21.0 runtime GNU RELRO validation

Adds `tests/e2e-relro.sh` and a small C host that opens an Aster-generated shared object with `RTLD_NOW`, locates its `PT_GNU_RELRO` through `dl_iterate_phdr`, and checks `/proc/self/maps` to ensure every page in the RELRO range is actually non-writable after the loader has completed relocation. It separately resolves the exported `counter` data symbol and proves that ordinary `.data` remains writable and that the library's PLT/GOT-backed `value`/`bump` operations still work. This complements, rather than replaces, the static ELF layout checks in `tests/relro-checks.sh`.

Run on the Android/Termux AArch64 device with `sh tests/e2e-relro.sh`. On a cross-compiled host, set `HOSTCC` and `RUNNER` as in `tests/e2e-so-import.sh`. A passing structural check alone does not guarantee runtime protection; this new test makes the loader's actual page permissions the acceptance criterion.

## v0.20.0 GNU RELRO hardening

Both `build-so` and `link-so` now emit a `PT_GNU_RELRO` program header. Ordinary `.data` is kept before a page-aligned boundary; `.init_array`, GOT slots, and `.dynamic` are placed after that boundary and before a page-aligned RELRO end. The writable `PT_LOAD` includes file-backed zero padding through the RELRO end, while `.bss` begins on the following page, so page-granular loader protection does not make ordinary globals read-only or leave `.bss` sharing a protected page.

The `link-so` PLT already uses eager binding (`DT_BIND_NOW` / `DF_BIND_NOW`), which is important because `.got.plt` is included in RELRO. Lazy PLT binding is not supported by this output mode. Run `tests/relro-checks.sh` in addition to the existing smoke and shared-object suites. The structural tests verify ELF metadata; runtime page permissions and Android bionic loading still need device-side regression testing.
