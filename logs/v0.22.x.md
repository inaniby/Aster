# Version log: v0.22.x

These sections are reproduced verbatim, including their original `## ` headings. For the condensed per-version history, see `docs/VERSION_HISTORY.md`.

## v0.22.2 — AArch64 stack argument ABI coverage

Extends the C ABI test with exported `aster_sum12` and `aster_mix12`, each taking twelve `i32` arguments. The first eight arguments use `w0`–`w7`; arguments 9–12 exercise AAPCS64 stack argument slots. Call sites reserve a 16-byte-aligned outgoing argument area, place each stack argument in an 8-byte slot, call through `BL`, then restore `SP`. Callees load incoming stack arguments from the caller stack area after creating Aster's fixed 8192-byte frame. The argument limit is 32 for now, bounded by current immediate-offset and frame design constraints. `aster_call_sum12` also calls the 12-argument function from Aster, covering the outgoing stack-argument path. `aster_abs` continues to exercise Aster-to-Bionic PLT import of `abs(int)`.

Run `sh tests/c-abi-structural.sh` for host-side ELF structure checks and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-abi.sh` on an AArch64 Android/Termux device for actual loader and call validation. The host-side check does not execute the AArch64 shared object. The v0.22.3-dev pointer slice additionally supports a C caller passing one `ptr` argument to an Aster function that copies it through a local `ptr` binding and returns it; v0.22.4-dev adds i32 loads/stores and v0.22.5-dev adds byte-based pointer arithmetic. Aster-to-Aster pointer-signature calls are supported since v0.22.9-dev. Byte loads/stores are available through `load_u8`/`store_u8` intrinsics; allocator ownership, structs, floating-point, callbacks, and variadic ABI remain unsupported.

## v0.22.3-dev — initial pointer ABI slice

The compiler now recognizes `ptr` in function parameter, return, and local binding type positions. Pointer-valued locals use 64-bit `X`-register loads/stores and 8-byte-spaced local slots; `i32` locals keep 32-bit `W`-register accesses in the same 8-byte-spaced local layout. The per-function parameter/local limit is temporarily 500 to keep this layout separate from the existing 4-byte call scratch/spill region in the fixed 8 KiB frame. Return/local initialization type mismatches are rejected.

The first acceptance sample is `examples/c_ptr_echo.ast`: `aster_ptr_echo(p: ptr) : ptr` copies the input to a local `ptr` and returns it unchanged. `tests/c-ptr-host.c` checks pointer identity and a null pointer through `dlopen`/`dlsym`; `tests/c-ptr-structural.sh` performs host-safe checks, while `CXX=clang++ HOSTCC=clang sh tests/e2e-c-ptr.sh` runs the actual call on AArch64 Android/Termux. The container can compile the harness and inspect the AArch64 ELF but cannot execute that shared object, so the actual pointer round-trip requires device validation. This is not yet general pointer support: Aster-to-Aster calls to any pointer-signature function are explicitly rejected. The next milestone adds raw i32 dereference load/store, but pointer arithmetic, strings, and allocator support remain unsupported.

## v0.22.6-dev — unsigned byte memory access

Adds compiler intrinsics `load_u8(ptr) : i32` and `store_u8(ptr, i32) : i32`. `load_u8` emits AArch64 `LDRB Wt, [Xn]` and zero-extends bytes (for example, `0x80` becomes 128). `store_u8` emits `STRB Wt, [Xn]` and stores only the low 8 bits; it returns the original i32 value. These are explicit intrinsics, not yet a general `u8` source-language type.

`examples/c_ptr_u8.ast` and `tests/c-ptr-u8-host.c` exercise `0x80` zero-extension and low-byte truncation (`0x1ff` stores `0xff`). Run `sh tests/c-ptr-u8-structural.sh` for host-safe structural checks and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-ptr-u8.sh` on Android/Termux for actual runtime validation. Device runtime acceptance is pending user log.

## v0.22.5-dev — byte-based pointer arithmetic

Adds byte-based pointer arithmetic: `ptr + i32`, `i32 + ptr`, and `ptr - i32`. Offsets are signed byte offsets and are sign-extended from i32, so negative offsets work without truncating the 64-bit address. The generated AArch64 instructions are `ADD/SUB Xd, Xn, Wm, SXTW`. This is raw address arithmetic with no bounds or lifetime checks.

`examples/c_ptr_arithmetic.ast` exports `aster_ptr_add`, `aster_ptr_sub`, and `aster_ptr_add_reversed`. Run `sh tests/c-ptr-arithmetic-structural.sh` for strict compilation, AArch64 ELF/opcode checks and C harness compilation. On Android/Termux, run `CXX=clang++ HOSTCC=clang sh tests/e2e-c-ptr-arithmetic.sh` to execute pointer addition, subtraction, reversed addition and a negative offset through `dlopen`/`dlsym`. User-confirmed Android/Termux runtime acceptance: PASS for byte-based pointer addition/subtraction, signed offsets and reversed addition.

Expected device output includes `PASS: C -> Aster byte-based pointer addition/subtraction`, `PASS: signed i32 offsets and reversed addition`, and `PASS: Aster v0.22.5-dev pointer arithmetic ABI test`.

## v0.22.4-dev — raw i32 pointer memory access

Adds unary dereference `*p` as an i32 load and `*p = value;` as an i32 store. The operand must be a value of type `ptr`; storing a pointer through this i32 dereference is rejected. Code generation emits AArch64 `LDR Wt, [Xn]` and `STR Wt, [Xn]`, preserving the full 64-bit address in the base register while accessing a 32-bit payload.

`examples/c_ptr_memory.ast` exports `aster_ptr_load(ptr) : i32` and `aster_ptr_store(ptr, i32) : i32`. `sh tests/c-ptr-memory-structural.sh` checks strict compiler/harness compilation, AArch64 ELF exports and load/store opcodes, and rejects dereferencing an i32. On Android/Termux, run `CXX=clang++ HOSTCC=clang sh tests/e2e-c-ptr-memory.sh` to actually load the `.so`, read a C `int32_t`, write a new value through the pointer, and verify the memory changed. The current container can inspect the target ELF but cannot execute AArch64 Android output; device runtime validation is still required. This is unchecked raw memory access: null or invalid non-null pointers can crash the process, and there is no bounds/lifetime checking. Byte access, strings, and Aster-to-Aster pointer-signature calls remain unsupported in v0.22.4-dev; pointer arithmetic is added in v0.22.5-dev.

Expected successful device output includes `load=19088743`, `stored=-123456789 memory=-123456789`, and `PASS: C -> Aster i32 pointer dereference load/store`, followed by `PASS: Aster v0.22.4-dev pointer memory ABI test`. Exact output may include the compiler's shared-object emission line first.

## v0.22.7-dev: Bionic string routines

Aster can now call imported external functions whose declared parameters include `ptr`. `examples/c_libc_strings.ast` wraps Bionic `strlen` and `memcmp`; the C harness passes valid NUL-terminated strings into the Aster exports. The shared object imports both symbols through PLT and declares `DT_NEEDED libc.so`.

This release does **not** yet support string literal syntax in Aster source, nor first-class `u8`, `size_t`, allocation APIs, or pointer-signature Aster-to-Aster calls. Run `sh tests/c-libc-strings-structural.sh` for container checks and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-libc-strings.sh` on Android Termux for runtime acceptance.

## v0.22.8-dev: NUL-terminated string literals

Aster now accepts double-quoted string literals in expressions. A literal evaluates to `ptr`, is stored as static NUL-terminated bytes, and can be passed to an external pointer-argument function such as Bionic `strlen` or `memcmp`. Supported escapes are `\\`, `\"`, `\n`, `\r`, `\t`, and `\0`. Embedded `\0` terminates C-string operations early, as expected.

The v0.22.8-dev first implementation placed literal bytes in `.data`; v0.22.11-dev moves literals emitted by direct `build-so` into a dedicated read-only `.rodata` segment. Generated literal symbols still use the ELF global-symbol machinery. This release does not add first-class `u8`, string indexing, mutable string semantics guarantees, bounds checks, or Aster-to-Aster calls with pointer signatures. Run `sh tests/c-string-literals-structural.sh` for structural checks and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-string-literals.sh` on Android/Termux for runtime validation.

## v0.22.9-dev: internal pointer-signature calls

Aster functions can now call other Aster functions whose signatures include `ptr` parameters and/or a `ptr` return value. The same typed 64-bit pointer argument handling is used for internal calls as for imported functions, including AAPCS64 stack-passed arguments. This makes wrappers such as `strlen(aster_identity("Aster"))` possible. String literals still reside in `.data`, and pointers remain unchecked raw addresses with no bounds/lifetime analysis.

Run `sh tests/c-ptr-structural.sh` and `sh tests/c-string-literals-structural.sh` for host-safe checks, then `CXX=clang++ HOSTCC=clang sh tests/e2e-c-string-literals.sh` on Android/Termux for device execution.

## v0.22.10-dev: mixed pointer/integer ABI regression

Added `examples/c_mixed_ptr_stack.ast` and strict C harnesses that exercise ten alternating `ptr`/`i32` arguments, including stack-passed arguments, through an Aster-to-Aster call. One exported function returns the sum of integer arguments; another returns the ninth-position pointer to verify that stack-passed pointer values survive the nested call.

Run `sh tests/c-mixed-ptr-stack-structural.sh` for container-safe ELF/compiler checks and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-mixed-ptr-stack.sh` on Android/Termux for runtime ABI validation. User-confirmed Termux output: `mixed_sum=31`, with the stack-passed pointer matching the expected pointer. v0.22.11-dev moves literal storage into read-only `.rodata` for direct `build-so` output; v0.22.12-dev adds `.rodata` to PIC `build-obj` objects consumed by `link-so`, and v0.22.13-dev adds read-only `.rodata` load segments to `link-obj` and `link-pie`.

## v0.22.12-dev: relocatable read-only string literal data

PIC `build-obj` now emits literal bytes in an allocated, non-writable `.rodata` section, and `link-so` preserves that data in a dedicated read-only, non-executable `PT_LOAD` segment. The executable `link-obj` and `link-pie` paths still reject objects containing `.rodata` until their final ELF writer can map a separate read-only segment. Run `sh tests/c-string-literals-structural.sh` for structural checks and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-string-literals.sh` on Android/Termux; the e2e script checks both direct `build-so` and `build-obj --pic` + `link-so`.

## v0.22.11-dev: read-only string literal storage

Direct `build-so` output now emits string literal bytes in `.rodata` and maps that section through a dedicated `PT_LOAD` segment with `PF_R` only (no write or execute permission). Mutable globals remain in the separate `PF_R|PF_W` segment. GOT address slots for literals are relocated to the `.rodata` addresses, so literal pointers continue to work with Bionic and Aster internal pointer-signature calls.

Validation: `sh tests/c-string-literals-structural.sh` checks the ELF section and program-header layout, and `CXX=clang++ HOSTCC=clang sh tests/e2e-c-string-literals.sh` runs the Android/Termux test. PIC `build-obj` now emits `.rodata`, and `link-so` preserves it. The executable `link-obj`/`link-pie` writers still reject `.rodata` explicitly until a read-only load segment is implemented for those output types.

## v0.22.13-dev: executable-linker read-only data support

`link-obj` (ET_EXEC) and `link-pie` (static PIE / ET_DYN) now accept ET_REL objects containing `.rodata`. The final writer emits a separate page-aligned `PT_LOAD` segment with `PF_R` only, while `.text` remains R-X and mutable `.data`/`.bss` remain R-W. `tests/c-string-literals-structural.sh` checks ELF section/segment flags for direct `build-so`, `link-so`, `link-obj`, and `link-pie`; `CXX=clang++ HOSTCC=clang sh tests/e2e-c-string-literals.sh` runs shared-object string tests and executes linked ET_EXEC/static PIE programs that load the first byte of a string literal (expected process status 74 (ASCII `A` + mutable global value 9)). Android/Termux runtime validation is pending.

## v0.22.14-dev: executable output permissions

The executable ELF writer now closes the output and marks `build-elf`, `build-pie`, `link-obj`, and `link-pie` outputs executable (mode 0755 subject to the platform's umask/permissions policy). This fixes the case where valid ET_EXEC/static PIE files were written without execute permission and Termux returned status 126 before the program could run. Structural tests explicitly assert `test -x` for linked ET_EXEC and static PIE outputs. Runtime validation for v0.22.14-dev is pending.

## v0.22.15-dev: string literal escape regression coverage

The C ABI harness now checks an embedded-NUL literal (`"A\\0B"`) with `strlen` (expected length 1) and a literal containing an escaped quote and backslash (expected length 4). These cases exercise lexer escape decoding, byte preservation in `.rodata`, and runtime behavior through direct and linked shared objects. Container and Android/Termux status must be read from `VALIDATION-v0.22.15-dev.md`; no device pass is claimed before the e2e script is run on the target.

## v0.22.16-dev: multi-object read-only string data

Adds two separate PIC source examples and an end-to-end test that compiles each to ET_REL, then passes both objects to one `link-so` invocation. The test verifies that `.rodata` from both objects is merged into a read-only, non-executable load segment, per-object string symbols retain correct offsets, `strlen` imports resolve through `libc.so`, and a call from one Aster object to a function defined in the other resolves correctly. Expected runtime values are `multi_object_a=9`, `multi_object_helper=1`, and `multi_object_b=8`. See `VALIDATION-v0.22.16-dev.md` for the exact validation status.

## v0.22.17-dev: preserve live expression values across calls

Fixes an AArch64 register-move encoding bug in call expressions. When a call result needed to be copied from `w0`/`x0` into a nonzero temporary register, the emitted instruction previously reversed source and destination. This corrupted expressions such as `helper() + strlen("object-A")`, although isolated call tests passed. The multi-object regression expects `multi_object_a=9`, `multi_object_helper=1`, and `multi_object_b=8`. The end-to-end script now retains generated objects and the shared library if it fails, making `readelf`/disassembly inspection possible after a failure. See `VALIDATION-v0.22.17-dev.md`.

## v0.22.18-dev: three-object string data and call-chain coverage

Extends the multi-object regression from two to three independent PIC ET_REL objects. The objects deliberately reuse the compiler-generated private string symbol names, include an embedded-NUL string in each object, and resolve a call chain across object boundaries. The test checks `multi_object_a=10`, `multi_object_helper=2`, `multi_object_b=8`, `multi_object_c=8`, and `multi_object_chain_helper=1`. This is regression coverage for per-object private-symbol namespacing, merged `.rodata` offsets, external calls, and the corrected call-result register move. See `VALIDATION-v0.22.18-dev.md`.

## v0.22.22-dev: shared-object negative diagnostics

`tests/so-negative-checks.sh` verifies duplicate exported symbols are rejected by `link-so` and inspects fixtures for a deliberately missing `DT_NEEDED` provider and an undefined dynamic function. `tests/e2e-so-negative.sh` loads these fixtures with `RTLD_NOW` and requires `dlerror()` to mention the missing library or symbol. Runtime behavior must be confirmed on Android/Termux or an AArch64 runner; structural validation alone is not a runtime pass.

## v0.22.21-dev: dynamic imports from linked PIC objects

The `tests/so-dyn-checks.sh` suite now builds `examples/so_link_import.ast` both directly as a shared object and as PIC ET_REL followed by `link-so`. It independently checks that the latter retains `DT_NEEDED=libdyn.so`, `R_AARCH64_JUMP_SLOT` relocations for imported `add`/`mul`, and `R_AARCH64_GLOB_DAT` for imported `counter`, with relocation offsets landing in `.got.plt` and `.got`. The device end-to-end suite now runs the same `dlopen`/`dlsym` ABI harness against both importer paths, including reading and writing the imported global. Container structural validation and strict compilation are recorded in `VALIDATION-v0.22.21-dev.md`; Android/Termux runtime validation is pending until the updated e2e script is run on device.

## v0.22.20-dev: five-object mutation and link-order regression

Extends the regression to five independent PIC ET_REL objects. Object E mutates the `multi_shared` global defined by object D; object A observes the value both before and after the mutation. The C harness also links and loads two shared objects built from forward and reverse input-object order. Expected values are `a_before=50`, `helper=2`, `b=8`, `c=8`, `chain_helper=1`, `d_before=40`, `e_after_add=45`, `a_after=55`, and `d_after=45` for each order. These are expectations until observed on Android/Termux. See `VALIDATION-v0.22.20-dev.md`.

## v0.22.19-dev: four-object read-only and mutable data merge

Extends the multi-object regression to four independent PIC ET_REL objects. The first object references a mutable global defined by the fourth object, in addition to a three-object call chain and repeated private string literals. The harness expects `multi_object_a=50`, `multi_object_helper=2`, `multi_object_b=8`, `multi_object_c=8`, `multi_object_chain_helper=1`, and `multi_object_d=40`. This checks that `.rodata` namespacing remains correct while a cross-object GOT-style reference resolves to the merged writable data. Runtime validation is pending on Android/Termux.
