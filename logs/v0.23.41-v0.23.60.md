# Version log: v0.23.41-dev – v0.23.60-dev

Original order is newest first, as it was at the top of README.md. For the condensed per-version history, see `docs/VERSION_HISTORY.md`.

## v0.23.60-dev

*Source: README.md:45.*

v0.23.60-dev widens the **explicit cast `T(x)`** beyond the integer family. The cast now accepts `bool` and `ptr`/`ptr<S>` as targets, so a bool reinterprets as an integer (`i32(true)` is `1`), an integer reinterprets as a pointer (`ptr(0x10)` is the address; `i32(p)` reads the low 32 bits the way C does) and a typed pointer reinterprets as another typed pointer (`ptr<i32>(pp)` is a pure re-tag, nothing emitted). The one non-trivial direction is integer→bool, normalized to 0/1 at run time (`CSET W, ne`). Rejected, by design: a struct on either side, and the two bool↔ptr crossings (`bool(p)` / `ptr(b)`) — an address is neither a truthiness nor a number. `examples/cast-conversions.ast` (with `tests/cast-conversions-twin.c`, exit `255`) and `tests/cast-conversions-checks.sh` (9 layers: strict build, source guards, 11 qemu witnesses, gcc differential, 7-rejection matrix, coverage, 5-mutant layer, byte baseline, example e2e) are added; `tests/integer-cast-checks.sh`'s rejection matrix is realigned to the new boundaries (11 refusals) and the twelve byte-baseline suites gained `^cast-conversions\.` filters. Evidence in `VALIDATION-v0.23.60-dev.md`.

## v0.23.59-dev

*Source: README.md:47.*

v0.23.59-dev is a **linker bug-fix round for Android 16 KB pages**. `link-so` now passes `--page-size` through to the shared-object writer, so `--page-size 16384` produces `PT_LOAD` segments aligned to `0x4000` (and `0x4000`-aligned `p_vaddr`/`p_offset`); previously the flag was a silent no-op for `link-so` and every shared object it built stayed 4 KB-aligned, which would fail to load on Android 15+ (targetSdk >= 35). `link-obj`/`link-pie` already honored the flag; the fix is a one-line pass-through (`linkSharedObjects(...,pageSize)`). `tests/page-size-checks.sh` now includes `link-so` in its command matrix (4 KB + 16 KB alignment on every `PT_LOAD`); evidence in `VALIDATION-v0.23.59-dev.md`.

## v0.23.58-dev

*Source: README.md:49.*

v0.23.58-dev is the **`&` address-of completion round**. `&` now takes the address of a scalar variable (`&x` → `ptr<T>`), a scalar struct field (`&s.f` → `ptr<T>`), and an array element (`&a[i]` / `&w[k]` / `&p[i]`, any element width), where previously only a whole array (`&arr` → `ptr`) and a struct (`&s` → `ptr<S>`) were addressable. The type answer is `Ty::ptrTo(sid)` for a struct lvalue, otherwise `tyPtrToElem(inner)` — the same rule in both `exprType` and `typeOf` — and `emitStructAddr`'s `Index` branch now scales by the element width (a `ptr`-based element routes through `emitPtrElemAddr`), so `&p[i]` no longer falls through the struct-only gate. Still rejected: `&` on a `ptr`-typed operand (no stride can be named) and on a call result (not an lvalue). `tests/address-of-checks.sh` (guards, qemu self-checks with distinct element values proving the stride, a reject matrix, the `address_of.ast` checksum) and `tests/e2e-c-address-of.sh` (a gcc differential over `address_of_abi.ast`) are added and registered in `tests/ci.sh`; the nine byte-baseline suites gained `^address_of\.` / `^address_of_abi\.` filters and a `| sort` so glob order no longer breaks the 288-row byte-identity assert. Evidence in `VALIDATION-v0.23.58-dev.md`.

## v0.23.57-dev

*Source: README.md:51.*

v0.23.57-dev is the **pointer-difference feature round**. `p - q` between two pointers now returns the signed element count (an `i32`), striding at each pointer's element width — 4 bytes for `i32` / an untyped `ptr` (matching `p[i]`'s one-i32 stride), 1 for `u8`, 8 for `i64`, and the struct size for `ptr<S>`. The 64-bit byte gap is divided by that width: an arithmetic shift for a power-of-two stride, a signed divide (`SDIV`) for a struct stride that is not (read off `aarch64-linux-gnu-gcc`). Two pointers must share the same stride; a mismatch is refused. `ptr + ptr`, `i32 - ptr` and `ptr + ptr` stay rejected. `tests/pointer-difference-checks.sh` (guards, rejection matrix, qemu self-checks over every stride) and `tests/e2e-c-ptr-difference.sh` (a gcc differential) are added and registered in `tests/ci.sh`. Evidence in `VALIDATION-v0.23.57-dev.md`.

## v0.23.55-dev

*Source: README.md:55.*

v0.23.55-dev **completes** the Android 16 KB-page support: the `.so`'s offset *inside the APK* is now page-aligned too. v0.23.54-dev made the ELF load segments 16 KB-aligned, but Android **mmaps the packaged `.so` straight out of the archive**, so the `.so`'s data offset within the ZIP must also be congruent to the device page size — otherwise a 16 KB-page device still cannot load the app. `buildApk()` now takes `pageSize`, the ZIP `append()` lambda pads the `.so` entry to that size (the default `4096` reproduces the historical byte-for-byte APK; `16384` shifts the entry to a `0x4000`-aligned offset), and `validate_apk.py` gained `--page-size 4096|16384` to assert it. `tests/page-size-checks.sh` `[6/6]` builds a real NativeActivity APK at both sizes and confirms (a) the embedded `.so`'s `PT_LOAD` `Align` is `0x1000`/`0x4000`, (b) its ZIP data offset is `0 (mod 4096)` / `0 (mod 16384)`, (c) the two APKs differ, and (d) `validate_apk.py` accepts each at its own page size. Evidence in `VALIDATION-v0.23.55-dev.md`.

## v0.23.54-dev

*Source: README.md:57.*

v0.23.54-dev adds **Android 15+ 16 KB-page support** via a new `--page-size` flag. Android 15 (the rule is gated on `targetSdk >= 35`) ships devices whose kernel page size is 16 KB, and bionic's dynamic linker **rejects** any app whose ELF load segments are not aligned to that size — Aster's three ELF writers (`writeElfBytes`, `writeSharedObject`, `writeSharedObjectDyn`) had hard-coded `0x1000` (4 KB) for every `PT_LOAD`'s `p_align`/`p_vaddr`/`p_offset`. The new flag — `--page-size 4096|16384`, default **4096** — threads one `pageSize` parameter through `build-elf` / `build-pie` / `build-so` / `link-obj` / `link-pie` / `build-apk`, so Android builds pass `16384` and **every existing Linux output is byte-for-byte unchanged** (the default path is exactly the historical 4 KB layout; 348-row byte baseline, zero drift). The `ADRP` relocation encoding is 4 KB-granular (`&~0xfff` / `>> 12`) and 16 KB is a superset of 4 KB, so code generation is untouched. Covered by `tests/page-size-checks.sh`: default keeps `Align 0x1000`, `16384` switches every `PT_LOAD` to `Align 0x4000` with `p_vaddr`/`p_offset` `0x4000`-aligned across all five emit commands, the `16384` executables run under `qemu-aarch64`, and the `16384` image is asserted *not* byte-identical to the default — the round caught a missing `pageSize` forward into the `writeElfBytes` call that would otherwise have made the flag a silent no-op. Evidence in `VALIDATION-v0.23.54-dev.md`.

## v0.23.52-dev

*Source: README.md:62.*

v0.23.52-dev closes the **toolchain plan's Round E** — thread-local storage in a shared object. `tls let` now works in a `.so`: the block is split into `.tdata` and `.tbss` the way GNU ld does it, both `.so` writers emit a real `PT_TLS` segment, and an access is **initial-exec** — `MRS X16,TPIDR_EL0` / `ADRP` / `ADD` / `LDR` / `ADD`, with the offset in a GOT slot that one `R_AARCH64_TLS_TPREL64` per variable fills at load time (symbol `STN_UNDEF`, addend the block offset — the shape GNU ld emits, read off this machine). A dlopen witness calls the module from the main thread and two pthreads and each gets its own copy. There is **no compile-time size cap**: glibc 2.35+ allocates a dlopen'd module's block dynamically, so even a megabyte loads, and the loader still reports `cannot allocate memory in static TLS block` if it genuinely cannot. A static image keeps local-exec, and the two share one block-offset algorithm — E1 showed the addend is a pure block offset, with no `TCB_SIZE` added. `tls extern let` in a `.so` is still refused. `tests/tls-checks.sh` is rewritten **[9/9]**; the byte baseline moves **345 → 348 rows**, 342 of them byte-identical. Evidence in `VALIDATION-v0.23.52-dev.md`.

## v0.23.49-dev

*Source: README.md:66.*

v0.23.49-dev opens the **language-completion plan's Round B** — the multi-way branch **`switch`** (`case` / `default`) with **Pascal auto-break**, and the long-promised **labeled `break` / `continue`** that jump straight to a named enclosing loop (2 of 3). The control-flow shape the language lacked is now a first-class statement: a `switch (e) { case C: … default: … }` whose subject must be an integer type, whose case values must be compile-time integer constants that fit the subject and are unique, and whose every matching case body **self-ends** — no fall-through, and therefore no per-case `break`. `switch` does **not** push a loop context, so a `break` inside a `switch` still names the innermost loop. Codegen lowers the `switch` to the **comparison chain it would have been** (subject spilled to a slot; per case `load; load case; CMP; B.NE → skip; body; B → end`; a final `default` body; one `end`) — **zero new instructions**, **zero new label concepts** — which is why the byte baseline of every pre-existing example is unchanged. Labeled jumps (`break outer;` / `continue outer;`) resolve the target name innermost-first against a `loopNames` stack at compile time: a missing or misplaced label is a hard error, not a runtime `goto`. The round is **host-only by decision** — `bootstrap/aster.ast` and `tests/codegen-twin.c` refuse `switch` and labeled loops by comment, synchronized, so the bootstrap subset did not grow. New resident suite `tests/switch-checks.sh` **[9/9]**: 20 qemu behavioural cases, 3 gcc-differential pairs, 13 rejections, a coverage floor, a 3-mutant layer, and the byte baseline **333 → 336 rows**, the 288 pre-existing ones byte-identical. The shipped `examples/switch.ast` exits **212** under qemu, equal to its C twin `tests/switch-twin.c`.

## v0.23.48-dev

*Source: README.md:68.*

v0.23.48-dev opens the **language-completion plan's Round A** — the eighth integer type **`u64`** and the language's first explicit conversion, the function-shaped cast **`T(x)`**. The type lattice grows to `{ I32, U32, U8, U16, I64, U64, Ptr, Bool, Struct }`: `u64` shares `i64`'s 8-byte slots and X registers and differs only in the reading — `LO/LS/HI/HS` condition codes and `UDIV` (`tyIsUnsigned` learns `U64`) — while **`promoteInt` answers `U64` first**, ahead of the `tyIs64` branch, because `u64 + i64` answering `I64` would emit a signed comparison for exactly the values past 2^63−1 that `u64` exists for. The cast is six spellings at the primary level — `i32 i64 u8 u16 u32 u64` — recognized with **zero lookahead** (an integer keyword followed by `(` can be nothing else), integer operands only (`ptr`/`bool` are neither spellings nor operand types: `cannot cast ptr to u8`), a narrowing answering the target width's low bits (`u8(300)` is `44`) and a widening extending by the *source* type's signedness. That last rule is where the round found its one real defect: the `Cast` arm stopped at the source width, so `i64(i32(0 - 1))` answered **4294967295** instead of −1 — a zero-extended 32-bit register read at 64 bits. The fix honours the invariant every other producer already follows (**a producer answers at the width the consumer asked for**): the arm's `SXTW` re-extends an `i32` answer into a 64-bit consumer. The literal ceiling moves out of the parser and into the declaration: `primary()` now accepts anything up to 2^64−1 (`integer literal exceeds u64 range` past it) and `initializerFits` is what knows which slot a value was meant for, so `let x: i64 = 9223372036854775808;` is refused naming the **slot** (`local initializer does not fit in i64: x (…)`) where the old parser named the token. The round is **host-only by decision**: `bootstrap/aster.ast`'s subset did not grow, and `tests/codegen-twin.c` was synchronized with comments rather than code — its `TK_U64` refusal rides the same type-keyword-where-an-expression-is-expected rule bootstrap already had, and its `convert_num` i64-max saturation stays, pinned in a comment as the bootstrap subset's own ceiling rather than a gap to close. New resident suite `tests/integer-cast-checks.sh` **[10/10]**: 32 qemu behavioural cases (every cast direction × every scope, `ptr<u64>` strides, unsigned `UDIV`/compare), 13 rejections, three migrated cascade diagnostics, a coverage floor, and a **9-mutant layer** — one of which (`promoteInt` forgets `u64`) first shipped **blind**, because a comparison's signedness is taken from its *operand* types, not from `promoteInt`'s answer; the witness had to be re-aimed at a `u64` **sum**, whose type *is* that answer. The shipped `examples/integer_cast.ast` exits 255 under `qemu-aarch64`, equal to its from-specification C twin `tests/integer_cast-twin.c`, and the baseline grows **330 → 333 rows**, the 288 pre-existing ones byte-identical.

No new example, so the baseline is untouched: 330 lines, byte-identical.

## v0.23.44-dev

The contract was frozen before the code (`bootstrap/PARSER-SPEC.md`, 13 sections, 907 lines), and the node names are **data, not code**: `bootstrap/gen_parser_names.py` is the single source of truth emitting the Aster side's kind constants and the twin's `tests/parser_names.h`, cross-checked against `src/aster.cpp`'s `enum Kind` — the subset must be a subsequence of the host's, in the host's order, so drift fails the generator rather than the differential. ## v0.23.42-dev

*Source: README.md:78.*

v0.23.42-dev ships **the first slice of a standard library written in Aster itself** — `SELFHOSTING-PLAN.md` M2, and the round with **no compiler change at all** (the version constant is the only edit to `src/aster.cpp`). M0 gave a program the bytes in and M1 gave it somewhere to put them; this is what a bootstrap compiler *writes with*: thirteen routines in `stdlib/aster_std.ast` over the byte intrinsics — `memcpy`/`memset`/`memcmp`, `strlen`/`strcmp`/`strncpy`, `utoa`/`itoa`/`utohex`, and an open-addressing hash table (`hash_str`/`hash_put`/`hash_get`) over two global arrays. The delivery shape was decided by a rule from v0.23.13-dev: `include` shares **declarations only**, so a library is not an include — it ships as a relocatable object and the consumer declares `extern fn` (`aster build-obj stdlib/aster_std.ast -o std.o && aster build-obj app.ast -o app.o && aster link-obj app.o std.o -o app`). ## v0.23.41-dev

*Source: README.md:80.*

v0.23.41-dev adds **raw memory** — `mmap` and `brk`, the second hard blocker on the self-hosting route (`SELFHOSTING-PLAN.md` M1). M0's round ended *"No heap, no `argc`/`argv`"*, and the bootstrap's next need is bytes it can hand back: a compiler that reads a source file in has to put an AST somewhere. The design is deliberately allocator-free — two system calls, `mmap` (x8=222) and `brk` (x8=214), emitted as `SVC #0` exactly like the M0 four through the same factored `syscallInsn`, so Aster still owns **no allocator**; `examples/arena.ast` is the whole shape on top, a 25-line bump allocator over one 64 KiB mapping. `mmap(addr: ptr, length: i64, prot: i32, flags: i32, fd: i32, offset: i64) : ptr` is the **widest intrinsic the language has** (six arguments, two of them `i64`) and `brk(addr: ptr) : ptr` both *queries* (`brk(z)` answers the current break) and *grows* (a nonzero, page-aligned `addr` moves it). Two generalizations of `syscallInsn` carry the round, both forced by measurement: **a 64-bit result is read at full width** (`MOV Xd, X0` when the result type is `Ty::Ptr`/`Ty::I64`, the W half otherwise) — qemu hands out mappings near `0x4000_0081_2000` (~70 TB, high word nonzero), and a truncated read would collapse to `0x0081_2000` and fault on first access; and **an `i64` argument rides at full width** (the staging loop keys on `tyIs64`, not `== Ty::Ptr`) — a 4 GiB `length` staged through W becomes 0, and the kernel answers EINVAL. Codegen's `callType` learns the pair (`mmap`/`brk` answer `Ty::Ptr`), the first intrinsics besides `load_ptr` that do. The kernel's own rules *are* the contract: a failing call answers `-errno` in pointer form (an unaligned `offset` → `-22`, which is how the suite pinned that `mmap`'s offset must be page-aligned), and the null check is the program's job. Resident suite `tests/heap-checks.sh` [6/6]: 5 differential cases (a page poke at five offsets, a real 4 GiB mapping, openat→fstat→mmap-at-4096 of a real file, a `brk` query/grow/poke cycle, and `examples/arena.ast` against its C twin `tests/arena-twin.c`), 10 rejections, 2 shadow cases, and a 5-mutant layer. Baseline **324 → 327 lines**, the other 324 byte-identical.
