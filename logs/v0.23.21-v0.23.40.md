# Version log: v0.23.21-dev – v0.23.40-dev

Original order is newest first, as it was at the top of README.md. For the condensed per-version history, see `docs/VERSION_HISTORY.md`.

## v0.23.40-dev

*Source: README.md:82.*

v0.23.40-dev adds **raw system calls** — `read`, `openat`, `close`, `fstat` — the input side of self-hosting. Asked *"编译器距离自举还差什么？"* the honest answer was "~80% there in principle, but two hard blockers", and the first was blunt: `write`(x8=64) and `exit`(x8=93) were the *only* system calls the compiler emitted, so a program could print and quit but **never read a byte in**. This round adds the four system calls a bootstrap needs to pull a source file in and push an ELF out — all `SVC #0`, all zero-libc, dispatched exactly like `write` through one factored `syscallInsn` helper (park live temporaries, stage args, `MOV X8,#num; SVC #0`, read w0, restore). The numbers are the **AArch64** ones and getting them wrong was the bug that shipped: there is **no plain `open`** — 56 is `openat(dirfd, path, flags, mode)` (`AT_FDCWD=-100`) — and `fstat` is **80**, not 79 (79 is `newfstatat`); the differential suite caught both and the resident `m_fstat` probe pins 80 so it can never regress. Results are the **raw kernel return** (`-errno`, not libc's `-1`) because the intrinsic *is* the system call. No heap, no `argc`/`argv`: the bootstrap reads stdin and writes stdout, so the shell redirect supplies the filename. `SELFHOSTING-PLAN.md` is the roadmap this is milestone M0 of. Resident suite `tests/syscall-io-checks.sh`: 5 gcc-differential cases (a 256-byte stdin cat, a 7-byte-chunked cat, `openat`+`read` of a real file, an `fstat` `st_size` dump, `close` of a bad fd → raw `-EBADF`), 7 rejections, 2 mutation probes; shipped example `examples/copy.ast` equals its C twin `tests/copy-twin.c`. Baseline **321 → 324 lines**, the other 321 byte-identical.

## v0.23.39-dev

*Source: README.md:84.*

v0.23.39-dev adds a **discarded-call statement** — `foo();` and `h.onClick(41);` run the callee and drop the result — answering the three questions that followed the callback-table round (*"还需要一个变量来接收吗？"* / *"没返回值的函数也需要吗？"* / *"有什么优劣？"*): Aster had **no expression statement at all** and **no `void`**, so every call result had to land in a `let`, a `return`, or an arithmetic position. The new statement is deliberately narrow — only a `Call` or a `FieldCall` reaches it, so `x;` and `a+b;` stay refused (no meaningless expression statement) and the assignment/`++`/`+=` positions are untouched. `statement()` gains a `Stmt::Expr` kind behind an `isCallStatement()` peek that tells `h.onClick(41)` (discarded field call) from `h.field = v` (field store) without consuming a token; the type checker runs first (`typeOf(*s.expr)`), so a discarded `f(1,2);` is still refused for count and a discarded `h.tag(1);` still for being a non-function field; codegen emits the call then releases the result register. Resident suite `tests/discard-call-checks.sh` [8/8]: 9 gcc-differential cases (direct, field, i64/bool/ptr return, zero args, ten stack args, loop, a "harmless drop" proving no register corruption), the shipped example against its C twin (`examples/call-stmt.ast` exits 56, equal to `tests/call-stmt-twin.c`), 4 rejections, a coverage map and a 4-mutant layer. Baseline **318 → 321 lines**, the other 318 byte-identical.

## v0.23.38-dev

*Source: README.md:86.*

v0.23.38-dev opens the two positions v0.23.37-dev refused on purpose, and the round is a **callback table**: a struct field may now declare a function type — `struct Handlers { onClick: fn(i32) : i32, onMove: fn(i32, i32) : i32, tag: i32 }` — and the call is written where the field is, `h.onClick(41)`, checked (argument count, argument types) and staged (each argument at its declared width, the result read at the declared return type) by the field's own signature. The field is still eight bytes of pointer in the layout and the signature rides beside it, so every existing struct lays out byte-identically; what the signature buys is the **check at every store into the field** and the **widths at a call through it**. `h.onClick(x)` is its own expression kind (`Expr::FieldCall`), not a call with a flag, because every call site keys on a name and v0.23.24-dev's "the function always wins" rule would silently reroute a field whose name matches a function in scope — `fn onClick` beside `Handlers.onClick` must still call the field (42, not 100). The one new codegen decision: the field's callee is read into X9 **before** the arguments take X0–X7, because `emitStructAddr` needs a temporary and the temporary pool *is* X0–X15; an ordinary indirect call keeps its old instruction. **A function may also now return a function pointer** — `fn pick(which: i32) : fn(i32) : i32 { … return inc; }` — with the signature in the return slot: `return` is checked against it, and a call's result *answers* it, so `apply(pick(1), 20)` is one contract spanning two functions (which needed parameter signatures to be visible at every call site, not only inside the declaring function). `pick(0)(20)` is still refused — assign it first. Two resident suites, both [8/8]: `tests/callback-table-checks.sh` (12 gcc-differential cases, 8 rejections, 6 mutants; `examples/cb_table.ast` exits 87, equal to `tests/callback-table-twin.c`) and `tests/function-return-fn-checks.sh` (12 gcc-differential cases, 6 rejections, 6 mutants; `examples/fn_ret.ast` exits 108, equal to `tests/function-return-fn-twin.c`). `tests/function-type-checks.sh` is **re-pointed, not replaced** — its two retired refusals are now inverted guards (the text must *stay* retired) and its mutants pin the return-slot check and the array refusal. Baseline **312 → 318 lines**, the other 312 byte-identical: a bare `ptr` still stages every scalar at 64 bits and still answers `i32`.

## v0.23.37-dev

*Source: README.md:88.*

v0.23.37-dev gives a function pointer a **signature**: `let fp: fn(i32) : i32 = inc;` declares a *function type*, and an indirect call `fp(x)` through it is now checked and code-generated like the direct call it stands for — the argument count and each argument's type run through the same `checkArgument` a direct call uses, each argument is staged at the width its signature declares (an `i32` in a W register, an `i64` in a full X register — retiring the "every scalar rides at 64 bits" rule the v0.23.24-dev round had to adopt), a struct argument is laid out as a composite instead of being refused, and the result is read at the signature's return type (an `i64` return at full width, where the old rule answered `i32`). The signature rides **beside** the ptr, never inside `Ty`: the storage type stays `Ty::Ptr`, and a parallel `FuncSig` travels with the binding, the frame slot and the global — the same pattern array dimensions have used since v0.23.35-dev. That is why **a bare `ptr` is untouched**: its signature is null, the legacy 64-bit staging and `i32` answer stand, and `tests/indirect-call-checks.sh` — its guards re-pointed at the new staging signature, its bare-ptr fallback still pinned — passes unchanged; 309 of 309 pre-existing baseline rows are byte-identical and only the new example's three rows are added (309 → 312). A function pointer may be a local, a global (which may be left uninitialized — zero-fills into `.bss` — and assigned at run time), or a **parameter** (`fn apply(op: fn(i32) : i32, x: i32) : i32 { return op(x); }`). Two positions were refused with positioned diagnostics — a struct field of function type and a function returning a function type — and **both are opened by v0.23.38-dev** (a field carries the signature and is called as `h.onClick(x)`; a function returns one, and `return` is checked against it). New resident suite `tests/function-type-checks.sh` [8/8] — 15 gcc-differential cases (every callee form, the `i64`-width centrepiece, `i64`/`bool`/`u32` returns, zero/mixed/ten stack-travelling arguments, a struct by value, a loop, nesting), the shipped example against its C twin (`examples/fn_type.ast` exits 115, equal to `tests/function-type-twin.c`), 9 rejections, a coverage map and an 8-mutant layer. This closes the v0.23.24-dev *"no function type"* design decision.

## v0.23.36-dev

*Source: README.md:90.*

v0.23.36-dev makes **`--bounds-check` guard array *parameter* subscripts too**. The flag (since v0.23.1-dev) has trapped out-of-range local and global array accesses with a `BRK #1` (SIGTRAP, exit 133); a parameter was the one array shape it could not see, because the two length tables everything else reads from were never filled for a parameter. The round adds a third, narrow length table — `paramArrayLength[slot]`, filled from the parameter's dimensions and consulted *only* by the check sites — which is deliberately *not* `localArrayLength`, because `gen(Var)` keys off that map to decide whether a bare `a` resolves to the frame slot or to the decayed pointer (handing a parameter a `localArrayLength` entry would silently break every call that relies on the pointer). So `fn f(a: i32[4]) { a[i] }` and `a[i] = v` now emit the same `CMP widx, #len` + `B.LO` over `BRK #1` as a local/global array, a constant out-of-range subscript (`a[4]`) is still rejected at compile time flag or not, and a multi-dimensional parameter (`a[i][j]`) checks per dimension through the existing per-dimension path. A default build emits no test — `emitBoundsCheck` opens with `if(!boundsCheck) return;` — so **no pre-existing byte moves** (309 of 309 baseline rows, no new example) and the `--bounds-check` opt-in rule stands. New resident suite `tests/array-param-bounds-checks.sh` [8/9]: a strict rebuild, source guards, qemu acceptance (in-range read/write identical with/without the flag), trap acceptance (out-of-range read/write/negative → 133 under the flag, silent by default), multi-dimensional per-dimension checks, compile-time constant rejection, a gcc-differential twin (`tests/array-param-bounds-twin.c`, both exit 6), and a 2-mutant layer — closing the v0.23.34-dev/v0.23.35-dev *"parameter bounds check absent"* line.

## v0.23.35-dev

*Source: README.md:92.*

v0.23.35-dev lets a program **ask** the two numbers it used to have to hard-code: `sizeof` answers bytes — `sizeof(i32)` is 4, `sizeof(i32[4])` is 16, `sizeof(Row)` is the struct's laid-out size — and `len` answers the element count, the product of the dimensions, so `len(i64[2][3])` is 6 and not 2. Both accept a type and an expression (`sizeof(w)`, `len(row.cells)`, `sizeof(i32[4])`), both fold to an `i32` constant at compile time, and every downstream site sees an ordinary integer. The second half is what makes the first half answerable inside a function: since v0.23.34-dev an array may be a parameter, but the decay threw the length away, so `len(a)` had nothing to answer from — **`Function::paramDims` now carries the dimensions into the body** and `Sema::check` fills the binding with them, so `sizeof(a)` answers the array's 16 bytes and `len(a)` its 4 elements, while the parameter stays a pointer for every other purpose (`return a;` still refused, a subscript unchecked by default but now guarded under `--bounds-check` in v0.23.36-dev). One number is deliberately Aster's and not C's: `sizeof` on a decayed parameter in C is the pointer's 8; Aster answers the array the caller actually passed, and the C twin says so out loud by measuring a real array type. `len` refuses what has no element count — a scalar, a `ptr`, a scalar or struct *type* — each message naming the fix, and `sizeof` is total over the type grammar. **No program that compiled before changes by a byte**: 306 of 306 baseline rows reproduce, the 3 new ones belonging to `examples/sizeof_len.ast`; `tests/rebuild-baseline-v0.23.35.sh` asserts the pre-existing rows byte-identical before it writes anything. New resident suite `tests/sizeof-len-checks.sh` [9/9]: 25 behavioural cases (every spelling × every scope × both operators), 3 gcc-differential pairs, a 9-row rejection matrix, a coverage floor, a 5-mutant layer, and the shipped example exiting 255, equal to its C twin.

## v0.23.34-dev

*Source: README.md:94.*

v0.23.34-dev makes an array a **first-class thing a function can take and hand back**, and removes the last width limit on `&arr`. Until now `&buf` answered a plain `ptr` and `p[i]` on it always strode four bytes, so an `i64[4]` or `u8[4]` could not be reached by reference without mis-scaling or a rejection; and there was no way to pass a whole array to a function at all — every array a function touched was a global for exactly that reason. Three things move together. **An array parameter decays to a typed pointer** — `fn sum(a: i32[4]) : i32` reads `a[i]` at the element's real width, and `fn sum64(a: i64[4])` does the same at eight — so a local `T[N]` crosses a call boundary as the address it already was, and a struct array parameter `fn get(v: V3[2]) : i32` reaches `v[1].a`. **`&arr` is no longer width-gated**: `&buf` answers `ptr<i64>`, `ptr<u8>`, `ptr<V3>` … a `ptr<T>` carries its element's real byte width, and `p[i]` strides at that width in both Sema and Codegen (one `slotElemTypes` record, read by both passes, so they cannot disagree about the stride); `(&arr)[i]` indexes through the address directly. One honest guard comes with it: a strided pointer must not land in an **untyped** `ptr`, which would still index at four bytes and read the wrong element silently — `let p: ptr = &w;` on an `i64[2]` is refused and told to declare `ptr<i64>` or take the array as a parameter, and a `ptr<V3>` does not go into a `ptr<Q>`. **A function returns a typed pointer too** — `fn get(w: ptr<i64>) : ptr<i64> { return w; }` round-trips a `ptr<i64>` through a call — and `return a;` from an array parameter is still refused as a dangling frame pointer. The round also closes the carry-forward **Lifecycle example**: `examples/lifecycle.ast` fills the seven `ANativeActivityCallbacks` lifecycle slots — `onStart`/`onResume`/`onPause`/`onStop`/`onDestroy`/`onConfigurationChanged`/`onLowMemory` at offsets 0..48 — which `native_render.ast` and `native_touch.ast` left empty, and `tests/lifecycle-callbacks.sh` drives all seven under `qemu-aarch64` by loading the example as a shared object, calling `ANativeActivity_onCreate`, invoking each installed entry and reading the counters back. **No program that compiled before changes by a byte**: 306 of 306 baseline rows reproduce, the 3 new ones belonging to `examples/lifecycle.ast`; `tests/rebuild-baseline-v0.23.34.sh` asserts the 303 pre-existing rows byte-identical before it writes anything. Updated resident suite `tests/array-address-checks.sh` [9/9] (stride capability, rejection matrix, source guards, gcc differential, mutation layer) and new `tests/lifecycle-callbacks.sh` cover the round.

## v0.23.33-dev

*Source: README.md:95.*

v0.23.33-dev is the second half of the debug-information story: **`.eh_frame`** — so a debugger can *walk* a stack, not only print the frame it stopped in. `-g` now emits a DWARF v4 **`.eh_frame`** (and its `.eh_frame_hdr`) beside the `.debug_line` and `.debug_info` it already wrote. Aster's frames are uniform — every function's prologue is exactly `SUB SP, SP, #8192` and SP never moves again inside a body — so a whole function's unwind table is **six bytes of CFI**: the CFA is `r31 (sp) + 8192` one instruction past the prologue, and the return address is stored at `CFA - 8` by every body that returns (the entry, which *exits*, does not save `x30`). The **CIE is byte-for-byte the one `aarch64-linux-gnu-gcc` writes** — augmentation `zR`, code alignment 4, data alignment −8, return-address column 30, `pcrel sdata4` — and the table is resolved by the same patch-site mechanism as `.debug_info`: every address field is carried by `.rela.eh_frame` as `R_AARCH64_PREL32` (261) in an object, and written directly by `build-elf`/`build-pie`/both `.so` paths and the linkers, so linking two `-g` objects yields one raised table and a shared object keeps every function's. Both sections ride in their own `PT_LOAD` under a `PT_GNU_EH_FRAME`, the header sorted and reachable, because an unwinder reads them out of the running image. **The output is strictly additive**: 303 of 303 pre-existing baseline rows reproduce byte for byte, and `-g` cannot move a byte of `.text`. New resident suite `tests/eh-frame-checks.sh` [9/9] — with `tests/ehframe-decode.py`, a decoder that reads the CIE/FDE bytes straight out of the ELF and runs the CFI program — proves the CIE equals gcc's, one FDE per function agrees with the symbol table, the CFA and return-address rules land where `objdump` says the prologue ends, the `.eh_frame_hdr` is sorted and reachable under `PT_GNU_EH_FRAME` in its own `PT_LOAD`, two independent readers (`readelf` and `llvm-dwarfdump`) describe the same functions and rules, and the table survives `link-obj`/`link-so` and running under qemu unchanged.

## v0.23.31-dev

*Source: README.md:97.*

v0.23.31-dev gives an array **a second subscript**: `T[N][M]`, with `a[i]` a **row** — the address of `M` elements — and `a[i][j]` the element, exactly as in C. Until now a subscript was the last thing you could do to an array: `a[i]` *was* the element, and that was the end of the expression. **No new type carries it**: an array name already decays to a `ptr` (v0.23.30-dev made that address reachable by name), so a row address is the same decay one level in — `a` is a ptr, `a[i]` is a ptr, `a[i][j]` is `i32`. The whole round is therefore a question of **stride**: a subscript at dimension *k* strides by `dims[k+1] * … * dims[L-1] * sizeof(elem)`, which for the innermost subscript is the element size — the one stride a one-dimensional array has always had — and for an outer one is the product of the dimensions below it (12 for a row of a 2×3 `i32` grid, 24 for a row of a 2×3 `i64` one). Five places moved together. **`arrayDimList()` reads one `[N]` per dimension** at every declaration site — a local, a global in all three branches, a struct field — while `count` stays the *total* element count, so the frame reservation, the broadcast initializer, `.data`/`.bss` sizing and `layoutStruct` are untouched; `dimsTotal()` bounds the total the way the one-dimensional spelling always did, so `i32[1000][1000]` is still refused. **One chain shape** serves assignment and expression alike: the array's name rides on the innermost `Index` node and each subscript above it is another `Index`, which is why `a[i][j] = v` and `a[i][j]` reach the *same* address computation; a single subscript still comes back as itself, so the one-dimensional path is unchanged in every respect. **Sema walks the chain** (`indexChainOf`): dimension *k*'s bounds come from `dims[k]`, the answer is a row unless this is the innermost subscript, and *every* subscript in the chain is checked — an inner `a[true][0]` is as illegal as an outer one, which is the hole a per-level walk closed. **Codegen's `emitIndexAddr()` computes every subscript first and materializes the base address after**, because evaluating a subscript can materialize a global's address into X16 — where the base is about to go — and then scales each subscript by `emitElemStride` (a shift for a power-of-two stride, a 32-bit materialize plus `UMADLL` otherwise). **A chain that stops short of the elements addresses a row, and a store to a row is refused** in both assignment forms — including the single-subscript spelling, which arrives from the parser as itself and is told apart from a chain by the subscript count the parser records. **No program that compiled before changes by a byte**: 288 of 288 pre-existing baseline rows reproduce, and the chain path is only entered when a second subscript exists. New resident suite `tests/multi-dim-array-checks.sh` [9/9]: **12 behavioural cases** (every chain shape, both scopes, a struct-field grid, a 24-byte `i64` row, a 1-byte `u8` grid, and chains inside two nested `for` loops), **4 gcc-differential pairs** (the example against its C twin `tests/multi-dim-array-twin.c`, both exiting 255), a **22-row rejection matrix** (two of which pin the holes this round found in its own first draft), a **36-row coverage map**, and an **8-mutant layer** — one mutant re-creates the row-stride arithmetic, one drops the per-level check so an inner bool literal compiles, and one withdraws the row-store refusal so `a[1] = 5` is accepted.

## v0.23.30-dev

*Source: README.md:99.*

v0.23.30-dev gives an array **an address**: `&buf` is a `ptr`, so a `T[N]` can be handed to a function by reference instead of having to live at file scope. Until now `&` was defined for a struct lvalue and nothing else, so an array was the one thing in the language a function could not reach — every array a function touches in the shipped corpus is a global for exactly that reason. **The address was already there**, which is the whole shape of this round: a local `T[N]`'s `Binding.ty` *is* `Ty::Ptr` (the array is decayed at declaration) and `gen(Var)` already emits `ADD Xd, SP, #slot*8` for it, while a global `T[N]`'s `typeOf` answers `Ty::Ptr` and `emitGlobalAddress` materializes it. So there is **no parser change, no new instruction and no new encoding** — only the rule that lets `&` ask for an address that was always being computed. **And because a named array is decayed, "is this an array?" is a question about the length, not the type**: an `i32[4]` and a `ptr` are the same `Ty::Ptr`, so `Sema::arrayOperandOf()` answers by length in three arms — a local (`b->len`), a file-scope array (`arrayGlobals`), and a struct's array field (`arrayFieldOf()`). **One honest restriction comes with it**: `p[i]` on a `ptr` is `*(p + i*4)` and Aster has no pointer type that carries a stride, so an array whose element is not four bytes wide is *refused* rather than silently mis-scaled — `'&' on an array needs a 4-byte element type: this array's elements are i64, and a ptr indexes at 4 bytes`. That admits `i32[N]`, `u32[N]`, `bool[N]` (a 4-byte 0/1 slot an element) and an `S[N]` of size 4, and refuses `i64`, `u8`, `u16`, `ptr` and a 12-byte struct. **`&arr` answers a plain `ptr`**, not a `ptr<T>` — the address of an array is the address of its first element, and `ptr` is the type that indexes, stores and passes. **No program that compiled before changes by a byte**: 288 of 288 pre-existing baseline rows reproduce. New resident suite `tests/array-address-checks.sh` [9/9]: **12 behavioural cases**, **3 gcc-differential pairs** (the example against its C twin `tests/array-address-twin.c`, both exiting 63), a **14-row rejection matrix** (six of which pin rules that must *not* have moved), an **18-row coverage map**, and a **7-mutant layer** — one of which re-creates the v0.22.50-dev frame-base bug on purpose, and one of which makes the local arm read the decayed type, which is precisely the mistake the round's central insight exists to prevent.

## v0.23.29-dev

*Source: README.md:101.*

v0.23.29-dev lets a **struct field be an array**: `struct Buffers { nums: i32[4], flags: bool[3], ptrs: ptr[4], pts: Vec3[2] }`. Until now the field parser read `field: T` and stopped, so `nums: i32[4]` was a syntax error — and the previous round ended by naming exactly this as out of scope. Four things had to move together. **`StructField` gained a length**, so `layoutStruct` reserves `sizeof(element) * len` bytes and every later read, store and address computation reads the length back from the field it named. **`postfix()` interleaves `.` and `[`** in one loop, because the old shape was a dot chain followed by a bracket chain and the first thing anyone writes is a bracket *followed by* a dot — `b.pts[1].a`, `b.nums[i] = v`, `&b.pts[1]`. **The element address is composed, not written twice**: `emitElemAddrField` is `emitStructAddr` (local, global or behind a pointer) over `emitElemIndex` (the v0.23.28-dev scaling rule, a shift for a power of two and `UMADDL` otherwise), so a 12-byte struct element is scaled by a multiply here for the same reason it is inside a named array, and there is no second copy of that arithmetic to disagree. **Bounds checking split by what it knows** — a named array is checked by name, a field by length, since a `StructField`'s length is right there and there is no binding to look up. A struct containing an array field **cannot be built by a literal** (`S { … }` fills each field from one value and an array field needs N of them), so the shape that works is *declare it and write the elements* — and a struct `let` may now have **no initializer at all**, zero-filled. That zero-fill is where the round's one real bug lived: it emitted `STR X0, [SP, #imm]` where it meant `STR XZR` — the encoding had no `Rt`, and `Rt == 0` is `x0`, **not** XZR (31) — so every uninitialized struct local was filled with whatever `x0` happened to hold. The shipped example had been surviving by luck (the statement before it left `x0` at zero); the `ptr` battery case, which writes an address and then reads a *different* element, is the first witness that can see it. **No program that compiled before changes by a byte**: 288 of 288 pre-existing baseline rows reproduce. New resident suite `tests/struct-array-field-checks.sh` [9/9]: **8 behavioural cases**, **2 gcc-differential pairs** (the example against its C twin `tests/struct-array-field-twin.c`, both exiting 63), a **10-row rejection matrix**, a **14-row coverage map**, and a **6-mutant layer** — three of which had to be re-aimed, twice because the witness first chosen could not see the damage it was there to catch.

## v0.23.28-dev

*Source: README.md:103.*

v0.23.28-dev opens the array's element type: **`T[N]`'s element is `T`**, whatever `T` is. Until now it was `T = an integer`, and three places disagreed with the sentence. **A local `bool[4]`, `Point[4]` or `ptr[4]` did not parse** — `letStatement()` opened the `[N]` suffix only after an integer type, and a local `ptr[4]` carried a refusal of its own. **A global `bool[4]` or `Point[4]` did not parse either** — `globalDeclaration()`'s Bool and Struct branches never looked for a `[`, although the scalar branch below them did. **And the type checker answered `i32` for every subscript** whatever the element really was, while codegen loaded and stored at the element's real width: `let q: Point = a[1];` was a type error against itself. Underneath all three sits one rule: **a struct element is scaled by a multiply, not by a shift**, because a struct's size need not be a power of two (`{ i32, i32, i32 }` is 12) and the old `tyShift` answered 2 for anything it did not name. `elemShiftOf` answers -1 there and `emitElemIndex` falls back to `UMADDL` — not to `ADD Xt, XZR, Widx, UXTW #0`, whose `Rn == 31` is the **stack pointer** and not XZR, a spelling that walked every struct array read off the frame before it was caught. Every path that reaches an element now computes its address in **one** place (`emitElemAddr`), so they cannot disagree about the base, the scale or the bounds check again. **No program that compiled before changes by a byte**: 288 of 288 pre-existing baseline rows reproduce, and the three new rows are `examples/array_elem_types.ast`'s output modes. New resident suite `tests/array-elem-types-checks.sh` [9/9]: **24 behavioural cases**, **6 gcc-differential pairs** (the example against its C twin `tests/array-elem-types-example-twin.c`, both exiting 127), a **28-row rejection matrix**, a **30-row coverage map**, and a **15-mutant layer** in which each fix, withdrawn, is caught — two of those mutants needed re-aiming, and both for the same reason: the witness they were first given could not see the damage (an exit status carries one byte, and a store two bytes into a word does not change it).

## v0.23.27-dev

*Source: README.md:105.*

v0.23.27-dev closes **four places where Aster read an expression differently from C** — all four found by writing `docs/language-reference.md` down and checking every row in it against the binary, which is the only reason they surfaced: three of them were silent (a different answer, or a truncated value) rather than an error. **`&&` now binds tighter than `||`.** They were collected by one loop, so `a || b && c` was read `(a || b) && c` — a different answer, silently, and one `docs/language-spec.md` had been contradicting for releases. They are two levels now (`logicalAnd()` over `equality()`, `logical()` over that), as in C, and both still short-circuit. **`-` `!` `~` `*` now take a `unary()` operand.** They used to take `primary()`, so `-s.v` parsed as `(-s).v` and `*s.p` as `(*s).p` — in practice *rejected*, since `(-s)` is a struct. A new `unary()` level sits between `postfix()` and the multiplicative level, `&` moves onto it with the other four, and both dereference-assignment targets parse at that depth too. **`a < b == c` compiles.** The anti-chaining gate now asks whether the next operator is from the *same* level — which is what the comment above `relational()` had always promised — so `a < b < c` and `a == b == c` are still refused while a level crossing reads `(a < b) == c`. **A narrow local `let` is range-checked like a global one.** `let b: u8 = 300;` used to store 44 inside a function while the same line at file scope was an error; `initializerFits` now runs for a local scalar and for a local array's element initializer, in sema and again in codegen, and it is a *constant* check only — narrowing a value (`let b: i32 = <an i64>`) is still allowed, as it always was. **No program that compiled before changes by a byte.** No shipped example mixes `&&` with `||`, none writes `*x.y` or `-x.y`, `a < b == c` did not compile at all, and none of the 411 `let` declarations in `examples/` and `tests/` initializes a narrow local out of range — so the round is four parser/type rules and no codegen at all; the A/B baseline is **288 of 288 rows byte-identical**, with three new rows for the new example. New resident suite `tests/precedence-checks.sh` [9/9]: **33 behavioural cases**, **5 gcc-differential pairs** (including `examples/precedence.ast` against its C twin `tests/precedence-example-twin.c`, both returning 127), a **16-row rejection matrix**, a **33-row coverage map** naming which rule each case is there for, and a **12-mutant layer** in which each fix, withdrawn, is caught by a case above — two of those mutants withdraw only *one* of the two range-check passes, which is what proves the codegen twin is a live gate rather than dead code copied from sema, and one withdraws a check that is a *diagnostic* rather than a gate, so what it loses is not acceptance but the specific message.

## v0.23.26-dev

*Source: README.md:106.*

v0.23.26-dev answers the question a pointer always asks first: **is this thing null?** Before it, a `ptr` could not be tested at all — `if (p)` was refused (a ptr is not a truthy type), `p == 0` was refused by three copies of the same "pointer comparison is not supported yet", and there was no way even to *write* a null, since `let p: ptr = 0;`, `f(0)` and `return 0;` from a `: ptr` function were all type errors. Now **the literal `0` is the language's null pointer constant**, as in C: it initializes a ptr, is assigned to one, is passed to one and is returned from one — and `==`/`!=` answer two questions, *are these the same address* and *is this address nothing*. **The codegen needed no new instruction**: `tyIs64` already counted a ptr, so the comparison path was already emitting `CMP Xn, Xm` at full width — the entire round is a matter of which programs the type rules let through, which is why it is cheap and why the byte baseline holds by construction. The boundary is deliberate and two-sided: **ordering two addresses (`< <= > >=`) stays rejected** — which of two unrelated objects "came first" is not a question Aster answers — and **`if (p)` stays rejected**, because a ptr is an address, not a truth value (that boundary is v0.23.25-dev's, and it holds). Only the literal `0` crosses the integer/ptr line: `let p: ptr = 1;` and `p == 1` remain errors, and so does `let p: ptr = false;` — a Bool literal's value is also 0, and `isNullConstant` consults the `boolLit` flag for exactly that reason. Four gates admit the constant (a local, an assignment, an argument, a return) in both passes, because sema is the rule and codegen its defensive twin, and it works for `ptr<S>` too, where the null test has to survive the struct-id check in `ptrToAssignable`. New resident suite `tests/null-ptr-checks.sh` [9/9]: **19 behavioural cases** (every position the constant appears in, both equality directions including `0 == p`, a stored bool value, `&&`/`!` composition, the search shape hit and miss, a pointer loaded out of memory, `ptr<S>`, a loop driven by `p != 0`, a global null and an array name's address), **5 gcc-differential cases** (the search shape, two names for one object, null in and out of a function, a null test stored as a value, and the shipped example against its C twin — exit statuses compared, no hand-computed expectations), **26 rejections** (ordered comparisons at all four operators against both a ptr and 0, `p == 1`/`-1`/a variable, `false` and `true` in every ptr position, non-zero integer literals, a ptr into an `i32` slot, a struct against 0), a 22-row coverage map, and an **8-mutant layer** (drop the predicate, withdraw equality from either pass, let `false` be an address, allow ordering, allow `p == 1`, let any literal be null, withdraw the null return — each must turn a battery red). New example `examples/null_ptr.ast` — a search that answers an address or null, exit 33, equal to its C twin `tests/null-ptr-example-twin.c` — is recorded in the A/B baseline: **285 → 288 lines, the other 285 byte-identical**. Full CI: **83 passed / 0 skipped / 0 failed**.

## v0.23.25-dev

*Source: README.md:108.*

v0.23.25-dev teaches the control flow what every other language's does: **`if`/`while`/`for` conditions now take a comparison, a `bool` expression, or *any* integer — 0 is false, non-zero is true** — and the language finally has `true`/`false` as first-class `bool` literals. The literal gap was structural: `Expr::Num` was born with an `i32` value and nothing else, so a `bool` could only ever be manufactured by a comparison. The lexer now maps `true`/`false` to new keywords and `primary()` builds a `Num` carrying a `boolLit` flag, so every type rule (`typeOf`/`exprType`) answers `Ty::Bool` for it while the stored value stays 0/1 — the two `typeOf` twins are the only places a literal's type is decided. The truthiness rule is one shared machine: `emitCondition`/`checkCondition` accept a comparison (the pre-existing `CMP`/`B` fast path, untouched so the byte baseline holds), a `bool` (measured against zero exactly as a comparison's answer is), or an integer, whose zero test is width-aware — `i32`/`u8`/`u16`/`u32` answer `CMP Wn,#0` (already emitted by the comparison path) and `i64` needs the new `CMP Xn,#0` (`cmpZeroX`), because a 32-bit compare of an `i64` holding a value past 4 billion reads as zero. `ptr` and struct conditions stay rejected, and the boundary is deliberate: **`?:`, `&&`, `||` and `!` remain strictly `bool`** — truthiness lives in control-flow conditions and nowhere else, so `a && b` still means "both true", not "both non-zero". Promoting the literal surfaced four real gaps, all filled in the same round: **`genBool` had never handled `Field` or `Cond`**, so `if (s.b)` and `c ? a : b` died in codegen ("expected a bool expression") although sema had already typed them `bool` — a pre-existing defect the literal work made impossible to ignore; **arithmetic silently accepted `bool` operands** (`1 + true`, `~true`, `a[true]`) through the integer widening paths, now rejected by one `rejectBool` guard at all fifteen operator sites plus array indexing; `constantInteger` folded `true` to `1`, which let `let x: i32 = true` and `a[true]` compile — a `bool` is no longer a constant integer; and global/struct initializers had no type gate for the new literal, now checked against the declared type. Dead code was removed on sight: an `isBoolConstant` branch for `boolLit` was unreachable by construction (the function is consulted only when the type is *not* `Bool`, and a `boolLit`'s type always is), so it was withdrawn rather than shipped untestable. New resident suite `tests/condition-checks.sh` [9/9]: **21 behavioural cases** (every literal branch shape, `i32`/`i64`/`u8`/`u16`/`u32` truthiness, `while(0)`, negative values, `while(true)` with an early return, a call as a condition, a `bool` struct field, `?:` arms, `&&`/`||`/`!`), **4 gcc-differential cases** (wide zero, high-bit `u32`, literal branches, loop + `?:` conditions — exit statuses compared under qemu, no hand-computed expectations), **31 rejections** (bool in arithmetic at every operator, indexing, `?:`/`&&`/`||`/`!` coercion, ptr/struct conditions, misassigned literals), a coverage map, and a **7-mutant layer** (drop integer conditions, narrow the 64-bit zero test, fold the literal, drop an operator guard, bypass the global gate, void the struct field's value — each must turn a battery red). New example `examples/condition.ast` (integer-driven loop plus literal branches, exit 16, equal to its C twin `tests/condition-example-twin.c`) is recorded in the A/B baseline: **282 → 285 lines, the other 282 byte-identical**. Full CI: **82 passed / 0 skipped / 0 failed**.

## v0.23.24-dev

*Source: README.md:110.*

v0.23.24-dev ships the missing half of function values: **`op(x)` — a call through a `ptr` variable**. Taking a function's address had worked since the callback-table work (the address could be stored, passed as an argument and handed to C), but every call site the compiler emitted branched through a relocated `BL`, so the address could never be *called*: there was no `BLR` in the language. Now `fp(args)` with `fp` a `ptr` variable (local, global or parameter) compiles to a `BLR X9`, and the round's showcase is the callback shape — `fn apply(op: ptr, x: i32) : i32 { return op(x); }`. **Zero parser change**: `primary()` has always produced `Call{name}` for `Ident(`, so the whole feature is dispatch. There is no function type, hence no signature *(for a bare `ptr` — **typed** fn-pointers arrived in v0.23.37-dev)*, so **every scalar argument rides at 64-bit width** — an `i32`-declaring callee reads the low half (exactly the bits a 32-bit stage would have put there), an `i64`-declaring one reads a properly extended full register (AAPCS64 leaves a sub-64-bit argument's upper half unspecified) — and the call answers `i32`. The callee's address is materialized into **X9** after the arguments are in their registers and before SP moves: X0–X7 hold arguments, X8 is the hidden result pointer, X9–X15 hold nothing live (every temporary is parked in the frame, the stack copies touch only X16/X17), so no park/restore change is needed. A function name in call position is still a direct call — the function always wins, exactly as a user function shadows an intrinsic. The second half of the round is the linker: **`let fp: ptr = f;` at global scope used to fail to link** ("global address relocation references a function symbol") — a restriction that exists for `.so` output (its text cannot carry load-time relocations, so function addresses there always travel through GOT slots). Static images know function addresses at link time and ADRP/ADD is PC-relative, so `linkObjects` now passes `funcAddrDirect=true` and the static paths (`build-elf`/`build-pie`/`link-obj`/`link-pie`) may materialize one; `.so` output is untouched. New resident suite `tests/indirect-call-checks.sh` [7/7]: **19 gcc-differential cases** (a local callee, reassignment, a trampoline parameter, a runtime-initialized global, ten arguments with the ninth/tenth on the stack, a wide literal and an `i32` variable into `i64` parameters, a small negative literal, a `ptr` argument, a `bool`, a loop, a pointer read out of memory with `load_ptr` — the dlsym shape — nesting, zero arguments, mixed widths, negatives, a helper calling through the pointer twice, and a function-wins precedence case), a shared-object structural check (builds, branches through a register, keeps its text free of load-time relocations), the shipped example run against its C twin (`examples/indirect_call.ast` exits 144, equal to the oracle), **10 rejections** (non-`ptr` callees, arrays, an undeclared name, a struct argument, an extern function's address, a bool consumed from the result), a coverage map, and an **8-mutant layer** — including the global callee loading its own address (the bug the first cut shipped, caught by a segfault before the suite existed). Baseline **279 → 282 lines**, the other 279 byte-identical. Full CI: **81 passed / 0 skipped / 0 failed**.

## v0.23.23-dev

*Source: README.md:112.*

v0.23.23-dev completes the raw-memory width ladder: **`load_u16`/`store_u16` (LDRH/STRH) and `load_i64`/`store_i64` (LDR X/STR X)** join `load_u8`/`store_u8`/`load_ptr`. The byte pair made memory reachable one byte at a time, and the two widths real data actually arrives in were the gap that remained — the difficulty audit's first item, and an "API-missing" difficulty rather than a hard one: the LDRH/STRH/LDR X/STR X encodings had existed since the stack-path work, so the round's four intrinsics are dispatch and contract, not new instruction selection. Why `i64` matters most: assembling a quadword through the byte pair meant eight loads, seven shifts and seven ors — and `<< 32` on an `i32` is a 32-bit shift whose count wraps, so `1 << 32` is **1** (measured, not assumed), the high word silently lost, and no comparison against the same assembled value could see it. One `load_i64` is one `LDR` and cannot be wrong that way. The contracts mirror the byte pair exactly: `load_u16(p) : i32` zero-extends 0..65535; `store_u16(p, v) : i32` writes `v & 0xFFFF` and answers the **original** `v` (the byte pair's documented contract — *not* C's assignment-expression value, a distinction the suite's first twin got wrong before the compiler did); `load_i64(p) : i64` answers the full 64 bits; `store_i64(p, v) : i64` widens an `i32` `v` by sign-extension (`gen(..., Ty::I64)` — the same rule storing it into an `i64` local applies, so `-1` lands as eight `0xFF` bytes) and rejects `bool`, which no `i64` slot accepts either. Each intrinsic is dispatched in all three sites (`checkCall`, `callType`, `gen`) behind the v0.23.21-dev shadow guard — **the user's function wins, always**, pinned here by six shadowing cases including a same-signature `load_i64` and a partial shadow (store shadowed, load still intrinsic). New resident suite `tests/narrow-memory-checks.sh` [7/7]: 24 differential cases — every width round trip, truncation past 16 bits, zero-extension at both consumer widths, an unaligned offset, loops, helpers, cross-width aliasing, and the sign-extension/narrowing edges — each against an `aarch64-linux-gnu-gcc -O2 -fwrapv` oracle under qemu (exit statuses compared; no hand-computed expectation anywhere); 8 rejections pinning each argument contract; a coverage map of the contract regressions; and a 7-mutant layer that disables each dispatch, drops the `callType` i64 answer, reverts the widening call, or removes a shadow guard — and requires the battery to go red every time. New example `examples/narrow_mem.ast` is recorded in the A/B baseline: **276 → 279 lines, the other 276 byte-identical** (`struct-checks.sh` [4/8]). Full CI: **80 passed / 0 skipped / 0 failed**.

## v0.23.22-dev

*Source: README.md:114.*

v0.23.22-dev closes the grammar's two most-felt gaps, and the headline is one line: **`if (c) { … }` without an `else` used to be a compile error, and `0x` literals used to be a lexer error.** `else` was mandatory — `ifStatement()` ended in `need(TK::Else,"expected else branch")` — so real code carried filler (`examples/icon_text_demo.ast` still has an `} else { }` whose only job is to satisfy the grammar), and the explicit spelling of what `else if` desugars to, `else { if … }`, did not even parse unless the inner `if` dragged an else along too. Making else optional is a one-token change — `need` becomes `if(eat(TK::Else))` — because an absent else leaves `elseBody` empty, codegen's `block({})` emits nothing, and sema's `definitelyReturns` already demanded both branches, so a then-only return correctly stops proving the function returns (the "may fall through" diagnostic still fires). The hex gap was found the honest way: writing an `i64` test value, `0x0102030405060708`, failed with `expected ';'` — the number scan only ever accepted decimal digits. The lexer now takes an optional `0x`/`0X` prefix and at least one hex digit (a bare `0x` is a positioned lexer error), and `unsignedLiteral` selects base 16, so array lengths inherit hex for free. Both edits are parser/lexer-only: **no codegen path is touched, so the 276-row A/B byte baseline holds by construction** — and `struct-checks.sh` [4/8] proves it, passing byte for byte. New resident suite `tests/syntax-relief-checks.sh` [7/7]: 13 if/else shapes and 14 hex values, every one with a C twin compiled by `aarch64-linux-gnu-gcc -O2 -fwrapv` and run under qemu (exit statuses compared — no hand-computed expectation anywhere), 5 rejections (bare `0x`, hex past i64, `0x1G` adjacency, and the fall-through that optional else must *not* excuse), source guards that fail if either old restriction ever returns, and a mutation layer that re-mandates `else` / disables the hex branch and requires the batteries to go red. The first full CI run of the release came back **1 failed** — `bool-checks.sh` pinning `if without else not rejected`, a case asserting the very restriction this round lifts — which was inverted into an acceptance check in that suite's `[7/8]` on the record rather than quietly broken. Full CI: **79 passed / 0 skipped / 0 failed**.

## v0.23.21-dev

*Source: README.md:116.*

v0.23.21-dev gives an ELF program its own voice: the **`write(fd, buf, len)` output primitive**. Until now every Aster program that printed anything had to go through libc — which meant going through a `.so` and a host that `dlopen`ed it, because `build-elf` emits static, libc-free binaries by design. Yet `main`'s `return` was *already* a system call (`MOV X8, #93; SVC #0` — `exit`); output had no reason to be any different. `write` is one more system call (`x8 = 64`) with three arguments staged in the frame's scratch grid and moved into `x0/x1/x2`, so `aster build-elf examples/write_hello.ast -o write_hello && ./write_hello` prints **Hello, World!** from a single file, no host, no `DT_NEEDED`. The `.so`+libc path is untouched and still serves the Android NativeActivity host. Implementing it surfaced the round's real lesson: **`x0/x1/x2` are simultaneously the syscall argument registers and the first three temporaries of the `w0–w15` pool**, and three successive clobber failures fell out of that collision — the fd moved into `x0` and freed, then the buffer's `gen` reusing `w0` (the syscall ran with the buffer as the fd → `EBADF`); then the arguments staged through the stack but loaded *straight into* `x0`, clobbering the surrounding expression's own `w0` (`total = total + write(...)` summed the byte count with itself, 4 instead of 6); and the loop-carried variant of the same. The fix borrows `emitCallSeq`'s discipline wholesale — park every live temporary in the frame, stage and move, syscall, restore — because a syscall preserves every register but `x0`, so the argument loading is the only thing that can hurt. New resident suite `tests/write-output-checks.sh` [4/4]: 16 differential cases (stdout, stderr, zero length, a `.bss` buffer, pointer+offset, two literals, an `i64`-consumed count, the three clobber regressions, and five *shadowing* cases — a user-defined `fn write`/`fn load_u8`/`fn load_ptr`/`fn store_u8` must be an ordinary call, not the intrinsic) each run against an `aarch64-linux-gnu-gcc` oracle on **three channels — stdout bytes, stderr bytes and exit status**; 4 rejections pinning the argument contract; and a [4/4] coverage map that fails if a clobber regression is ever deleted. That last group earned its place the hard way: the first full CI run came back **2 failed of 78**, and one of them was `runtime-bounds-checks.sh` — whose own helper is literally called `write` — failing with `error: write expects (fd: i32, buf: ptr, len: i32)`. The intrinsic dispatch had been swallowing user-defined functions of the same name, a real design defect that the four-year history of the intrinsic family had never met because nothing had ever called one `write`. The fix is three guards (`callType`/`checkCall`/`gen` all ask `&&!arities.count(e.name)` first — **the user's function wins, always**), and `load_ptr`'s pointer-return registration became conditional on the same question. Baseline **273 → 276 lines, the other 273 byte-identical**. Full CI: **78 passed / 0 skipped / 0 failed**.
