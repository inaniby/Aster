## v0.23.70-dev

*Source: README.md:23.*

v0.23.70-dev closes the **`union`** row — the last of the audit's five language gaps, so all five are now closed. A `union` is the struct layout with one difference: every member sits at offset 0, the alignment is the widest member's and the size is the widest member rounded up to it. It stays a `Ty::Struct` and shares `g_structs` / `g_structIndex` (so it shares the struct tag namespace, as C does), which means field access, `sizeof`, constant folding and the whole AAPCS64 aggregate ABI (the ≤8 / 9..16 / >16 parameter and return paths) are inherited with no new machinery. A union literal takes **exactly one value**, initializes the **first** member and zeroes every other byte — C's `union U u = {5};` — at compile time through a zero-filled constant image and at run time through `STR XZR/WZR` stores; reading a member other than the last written is allowed (byte reinterpretation, no active-member tracking). `-g` emits a real `DW_TAG_union_type (0x17)` with an abbreviation that is **unconditionally** in the abbrev table, because the linker keeps only the first `.debug_abbrev`. One reserved word joins the lexer (`union`) — **32** now, `tls` still a context keyword. `tests/union-checks.sh` (9 layers: strict build, 24 source guards, a C-ABI interop witness — a C `main` links Aster's `pack`/`widen` union functions and exits 0 under qemu — a 6-case gcc differential, a 13-entry refusal matrix, the shipped `examples/union_layout.ast` against its C twin, coverage counting, six mutations, and the byte baseline pinning the three `union_layout` rows) is added and registered in `tests/ci.sh` (127 suites). **No byte change to any other example**: `tests/baseline/v0.23.70-dev/` is this version's snapshot at 375 rows and all 372 pre-existing rows are unchanged. ## v0.23.69-dev

*Source: README.md:25.*

v0.23.69-dev closes the **`char`** row of the audit's language-gap table. `char` is a **distinct unsigned 8-bit type** — declared `Ty::Char`, keyword token `char` (`TK::CharType`), *separate* from the `Char` *literal* token the lexer has carried since v0.23.50-dev. It reuses the entire `u8` codegen/width machinery (1-byte size, 1-byte alignment, `LDRB`/`STRB`, `UXTB`, zero-extending loads), so it is byte-for-byte ABI-identical to C `unsigned char` and never moves a single byte of any other example. ## v0.23.68-dev

*Source: README.md:27.*

v0.23.68-dev closes the **`void`** row of the audit's language-gap table. `void` is a **return-slot property only** — it names the absence of a result on a function, never a value you can hold. The compiler gains a `Ty::Void`; `parseType` accepts `void` only behind `needType`'s `allowVoid` gate (a function's `:` return and a `fn` type's `:`), so `void` can never reach a parameter, a local, a field, an alias, or an array element — each of those is refused with `void is only a function return type`. A `void` function may say `return;`, fall off the end of its body, or take arguments and loop; it still gets a prologue, an epilogue, and the same AAPCS64 ABI as any other function. The one rule that moves is the fall-through check: a `void` function may reach the end without a `return`, while a value-returning function still must. Every other refusal is singly-located and load-bearing — `return e;` in a `void` fn, a `void` result used as a value (`let x = f()`, `return f()`, `g(f())`, `f() + 1`), and `type V = void` — and `tests/void-checks.sh` (9 layers: strict build, 24 source guards, a C-ABI interop witness where a C `main` links and calls an Aster `void` function under qemu, a 5-case gcc differential, an 11-entry refusal matrix — five of the refusals a C twin shares, the rest are Aster-only — the shipped example against its C twin, coverage counting, six mutations, and the byte baseline pinning the three `void_return` rows) is added and registered in `tests/ci.sh`. **No byte change to the other 123 examples**: `tests/baseline/v0.23.68-dev/` is this version's snapshot and every pre-existing row is unchanged. Evidence in `VALIDATION-v0.23.68-dev.md`.

## v0.23.67-dev

*Source: README.md:29.*

v0.23.67-dev is the **"close the language gaps" round** — the audit's third part listed `typedef`/`const`/`void`/`char`/`union` as language gaps, in that order of cost-effectiveness, and asked for them to be closed in turn. This round closes the first two. `type Name = T ;` is a **type alias**: a name expanded by the very same `parseType` every declaration site uses, so it can stand for anything a type can be spelled as — a scalar, a struct, an enum, a `ptr<...>`, or a `fn(...) : ...` — and nothing downstream ever sees the name. A `Ty` is a `(kind, index)` pair with no room for a spelling, so the alias is gone before layout, Sema or codegen run; two names for `i32` are `i32`, and a value of one is a value of the other. The one thing a `Ty` cannot carry — a function signature — travels in the alias record and is handed back at every use, which is what makes `type Op = fn(i32) : i64;` a *real* signature at every declaration that names it (a bare function pointer would read the result at `i32` width and truncate a 64-bit answer). `const x : T = e ;` is a **read-only binding**, at file scope and in a function body, and every store is refused — `x = e`, `x += e`, `x++`, an element store `a[i] = e`, a field store `s.f = e`, and the address `&x`, because an Aster `ptr` carries no read-only bit of its own and `*p = v` would be the one way back in. This round adds two reserved words (`type`, `const`) — 29 now, `tls` still a context keyword — and rewrites none of the image: a const global occupies the same `.data` bytes a `let` global does. `tests/alias-const-checks.sh` (9 layers: strict build, 26 source guards pinning every piece of both features plus the reserved-word list, an independent reader that expands every alias out of the source by hand and requires **byte-identical** output, a **gcc differential over ten cases** — `typedef` and `const` are C spellings, so each behavioural case has a C twin and the two agree on the qemu exit status — a 16-entry refusal matrix, six of whose refusals gcc shares, the two shipped examples against their C twins, coverage counting, six mutations, and the byte baseline asserting every pre-existing row is unchanged) is added and registered in `tests/ci.sh`. **No byte change**: all 123 examples compile to the same bytes as v0.23.66-dev, so `tests/baseline/v0.23.67-dev/` is this version's snapshot. `void` stays queued. Evidence in `VALIDATION-v0.23.67-dev.md`.

## v0.23.66-dev

*Source: README.md:31.*

v0.23.66-dev is the **"the parts of an ELF image nobody runs" round** — the audit's second part had seven ELF/linker findings marked 「待验」(located by reading the source, never reproduced), and v0.23.65-dev had only taken the two that were already known. This round reproduces the rest and the score is **five real defects, one defensive gap, and one item where the *audit* was wrong**. The one that matters most is a memory-safety bug: `kRelTlsOff` fills a `MOVZ`/`MOVK` **pair** — 8 bytes — but `parseObject` only proved 4 bytes of `.text` were in bounds, so a relocation pointing at the last four bytes read and wrote past the end of the text vector. ASAN says so in as many words: `heap-buffer-overflow ... READ of size 1 ... in resolveRelocations`. No compiler-generated object puts a pair there, but `parseObject` reads whatever it is handed. The other four are fields: an object built with `-g` wrote its local `STT_SECTION` symbol for `.text` **in the middle of the globals** with `sh_info` left at 1 (readelf: *"local symbol 2 found at index >= .symtab's sh_info value of 1"*); `.hash` carried `sh_entsize` 0 where GNU ld writes 4; `.rela.plt` carried `sh_info` 0, i.e. "these relocations apply to nothing"; and `.bss`/`.tbss` (SHT_NOBITS) had `sh_offset` pinned to the end of whatever was written last, so with a thread-local block their offset disagreed with their address by the size of `.tbss`. **Where the audit was wrong**: it said `.rela.plt`'s `sh_info` should name `.plt`. GNU ld names **`.got.plt`** — a JUMP_SLOT fills a GOT slot, not a stub — and the suite's GNU ld differential is what settles it, the same way GNU ld settled the page-alignment question last round. The defensive gap is the PLT's `ADRP x16`, written with no ±4 GiB page-range check while the same instruction relocated anywhere else in the compiler has one. `tests/elf-metadata-checks.sh` (9 layers: strict build, 21 source guards, `readelf` plus a decoder as independent readers, a **GNU ld differential that fixes what "right" means from outside the project**, a refusal matrix under an ASAN build, qemu witnesses, coverage counting, three mutations, and the byte baseline) is added and registered in `tests/ci.sh`. **Only `.so` bytes move, and only inside the section header table**: all 121 examples build to files of exactly the same length, differing in at most four bytes — 116 of the 360 baseline rows change, every one of them a `.so`. Evidence in `VALIDATION-v0.23.66-dev.md`.

## v0.23.65-dev

*Source: README.md:33.*

v0.23.65-dev is the **"where the layout arithmetic runs out" round** — the audit's items 9 and 10, and the first round whose two fixes are the same bug wearing two costumes: **a layout number that silently wrapped instead of refusing**. `kRelTlsOff`, the internal relocation that writes a thread-local variable's block offset into the `MOVZ X17,#imm16` / `MOVK X17,#imm16,LSL#16` pair, masked the offset with `& 0xffffffffu`. The pair carries 32 bits, so a variable at offset 2^32 was quietly moved to offset 0 — onto another thread-local: 513 thread-locals of 8 MiB is a 10 KB source, and `g512[0] = 1; return g0[0];` returned **1** instead of 0, because the two had become the same eight bytes. `layoutStruct` accumulated field offsets in a `uint32_t`, so a struct of 8192 fields of `L1[512]` (L1 being 1024 bytes) reached exactly 2^32 and wrapped to **0** — and 0 passes the `size > 1024` check that ran afterwards, so a 4 GiB struct was accepted, `sizeof` reported 0 and every field access landed on whatever the zero-size slot sat on; a 4195-field variant wrapped to 712704 and was refused with a size that had never existed. Both are refusals now, and both name the number that did not fit. `layoutStruct` accumulates in 64 bits and enforces the 1024-byte limit **as fields are placed** (which is why `kMaxStructSize` moved to namespace scope), reporting the field that crossed it. `tests/layout-boundary-checks.sh` (9 layers: strict build, source guards, 7 qemu witnesses including the last thread-local offset the pair can carry, a 6-case C differential via `tests/layout-boundary-twin.c`, a 6-refusal matrix, coverage counting on both sides, a 3-mutant layer, the 360-row byte baseline, and one shape through all three modes) is added and registered in `tests/ci.sh`. **Item 9's other half was measured and found sound**: `tests/page-size-checks.sh` asserted that every `PT_LOAD` *starts* on a page boundary, but the contract is congruence (`p_vaddr == p_offset` mod `p_align`) — and GNU ld's own `-Wl,-z,max-page-size=16384` output settles it, emitting a second `PT_LOAD` at off `0x3e30` / vaddr `0x7e30` with `p_align 0x4000`. The stronger assertion could never have failed, because no image in the corpus carried a `.eh_frame`: `-g` is what makes the shared writers emit a fourth segment, at `0x10840` under 16 KB. The matrix now runs with `-g` too, the assertion is congruence, and the GNU ld differential is asserted beside it so the correction cannot rot into "anything goes". **No byte change**: all 121 examples compile to the same bytes as v0.23.64-dev, so `tests/baseline/v0.23.65-dev/` is the previous snapshot under this version's name. Evidence in `VALIDATION-v0.23.65-dev.md`.

## v0.23.64-dev

*Source: README.md:35.*

v0.23.64-dev is the **"every suite runs" round** — the audit's P1 follow-up, and a defect in the gate rather than in the compiler. `tests/ci-protocol-checks.sh` defined an orphan suite as one matching `tests/*-checks.sh` but absent from `DEFAULT_SUITES`. That is a **naming convention, not a property**, and four scripts fail the glob, so they had never run in CI: `c-ptr-memory-structural.sh`, `e2e-so-scope.sh`, `regression-symtab.sh` (all real suites) and `smoke.sh` (the driver `FEATURE_STATUS.md` credited with covering 32-argument calls, arithmetic, comparisons, `while`/`break`/`continue` and `build-elf`). The gate now enumerates **every** `tests/*.sh` and subtracts an explicit allowlist — `host-toolchain-probe.sh` and `guest-libc-alias.sh` (sourced libraries), `run-aarch64.sh` and `ci.sh` (the runner and its qemu prefix), `run-on-device.sh` (needs a real target) and `smoke.sh` — and each entry states its reason. A driver may only stay unregistered while **everything it invokes is registered**, which is now asserted too, so "it is just a driver" cannot become a way to add a suite nobody runs. Run for the first time, the three suites behaved as a suite that has never run tends to: `c-ptr-memory-structural.sh` and `e2e-so-scope.sh` pass; `regression-symtab.sh` fails, and the failure is **not** a regression — it asserts that each product's loaded image still matches a frozen v0.16.0 fixture byte for byte, which stopped being true when the frame was redesigned around 8-byte slots (`ARCHITECTURE.md`: "Scalars occupy one 8-byte slot each"), moving `hello.ast`'s `str w0,[sp,#4]` to `#8` and a `pie_global_rw.ast` spill from `str w0,[sp,#4080]` to `str x0,[sp,#4032]`. That assertion was never what the suite is named for, so it is replaced by the invariant it exists to hold and which still holds everywhere: the section table is **append-only** — `e_shoff` begins at or after the last byte any `PT_LOAD` occupies, so `.symtab`/`.strtab`/`.shstrtab` can never be overwritten by the program's own writes. `while` + unlabeled `break;`/`continue;` also gained the executed witnesses it never had (every resident case used the *labeled* form or put `continue` inside a `switch`), including the nested case that proves an unlabeled break leaves only the innermost loop. **No compiler change and no byte change**; 121 suites.

## v0.23.63-dev

*Source: README.md:37.*

v0.23.63-dev is the **semantic strictness round** — the audit's P1 batch, five defects of the quieter kind: not "computes the wrong answer" but "answers the wrong thing about a program". A wide integer reaching `<<`, `>>` or `~` **aborted the compiler** (`TypedIR MISMATCH kind=25`: the TypedIR exemption list had never been told about the shift family). Two different `enum`s compared equal, because nominal isolation stopped at the assignment and never reached a comparison. An enum slot accepted a constant no `i32` could hold, and an auto-incremented enumerator walked out of `i32` unnamed. And a value could **narrow implicitly**: `fn f() : u8 { let x: i64 = 300; return x; }` compiled and handed back `300 & 0xFF` — while an *argument* in the same slot was refused, so two positions in the language disagreed about what it says. Fixed: `Shl`/`Shr`/`BitNot` join the TypedIR exemption; two enums compare only when they are the same enum (an enum still compares against an `i32`, whose storage it shares); one predicate, `enumValueFits`, guards an explicit value, an auto-increment and a constant assigned into an enum slot; and the assignability rule `checkArgument` has always applied now also covers a `let`, an assignment, a global assignment and a `return` — with two positions deliberately left alone, both named in the source: an **arithmetic result** (Sema types every arithmetic node `i32`, so trusting it would refuse `fn add_u8(a: u8, b: u8) : u8 { return a + b; }`, which has compiled since narrow types existed) and a **store through a subscript or a field** (`bootstrap/aster.ast` stores an `i64` instruction word into an `i32[262144]` stream, and the bootstrap subset has no cast to spell that truncation with). `tests/type-strictness-checks.sh` (9 layers: strict build, source guards, 17 qemu witnesses, a 9-case gcc differential via `tests/type-strictness-twin.c`, a 13-refusal matrix, coverage counting on **both** sides, a 6-mutant layer, byte baseline, four shapes × three modes) is added and registered in `tests/ci.sh`; `tests/enum-checks.sh`'s cross-enum case moves from "legal" to "refused" and gains four more. **Zero bytes changed**: all 121 examples compile to the same bytes as v0.23.62-dev, so `tests/baseline/v0.23.63-dev/` is the previous snapshot under this version's name. Evidence in `VALIDATION-v0.23.63-dev.md`.

## v0.23.62-dev

*Source: README.md:39.*

v0.23.62-dev is an **evaluation-order and operand-width bug-fix round**, driven by the full source audit in `AUDIT-v0.23.61-dev.md`. Four P0 defects share one root mechanism: `X16` holds the address a store is about to write, and evaluating the right-hand side can materialize a **global**'s address into `X16` — so the store lands somewhere else entirely. Fixed: a multi-dimensional scalar element store (`arr[i][j] = g`) now generates the value **before** the address (the struct branch keeps addressing first, because `emitStructStore` parks its destination in the frame and reloads `X16` per field); a struct field's array subscript (`s.xs[i]`) is evaluated **before** the field's base address, the order `emitIndexAddr` already documents and uses; `*p = -5` on a `ptr<i64>` now generates the value at the element's own width, instead of sign-extending an `i32` into the low half and storing it with a 64-bit `STR` (which wrote `4294967291`); and an integer→`bool` cast compares at the operand's own width (`CMP X` for a 64-bit source), so `0x1_0000_0000` is no longer read as false. `tests/eval-order-checks.sh` (9 layers: strict build, 5 source guards, 19 qemu witnesses built over an operand-kind matrix of constant/local/global/call, a 9-case gcc differential via `tests/eval-order-twin.c`, a 4-rejection matrix proving the array bounds checks survive the reordering, coverage counting, a 4-mutant layer each restoring exactly one defect, byte baseline, example e2e) and `tests/eval-order-twin.c` are added and registered in `tests/ci.sh`. Three examples (`array_address`, `multi_dim_array`, `struct_array_field`) changed bytes in all three baseline modes — 9 of 360 rows — and `tests/baseline/v0.23.62-dev/` freezes the new snapshot; four version guards bumped. Evidence in `VALIDATION-v0.23.62-dev.md`.

## v0.23.61-dev — enumerations

*Source: README.md:41.*

v0.23.61-dev adds **enumerations**: `enum Name { … }` is a nominal `i32`-backed type whose enumerators are named `i32` constants (`enum Color { Red, Green, Blue }`, explicit `= value` allowed, auto-increment from 0). Enumerators fold into plain integers, so `Red + Green` is `i32` arithmetic; an enum value is a legal `if`/`while` condition and `sizeof` is `4`. The type is **nominal** — `enum Color` and `enum Dir` differ even at equal values: cross-enum assignment is refused, `i32 <- enum` is free, and `enum <- i32` is allowed only from a fitting compile-time constant (never from an `i32` variable). `examples/enum_demo.ast` (with `tests/enum-demo-twin.c`, exit `255`) and `tests/enum-checks.sh` (9 layers: strict build, source guards, 9 qemu witnesses, gcc differential, 5-rejection matrix, coverage, 2-mutant layer, byte baseline, example e2e) are added; the ten byte-baseline suites gained `^enum_demo\.` filters and the three version guards bumped to `0.23.61-dev`. Evidence in `VALIDATION-v0.23.61-dev.md`.

## v0.23.61-dev — correctness and security hardening

*Source: README.md:43.*

v0.23.61-dev is also a **correctness and security hardening round** driven by an adversarial source audit. The code generator now makes every width decision from one rule: 64-bit values and pointers spilled across calls use `STR X`/`LDR X`, struct returns store exactly `tySize` bytes, `u8`/`u16` returns truncate at the boundary, and dereference/assignment follow the pointee type (`LDRB`/`LDRH`/`LDRSW`/`LDR X`, `STRB`/`STRH`/`STR X`). Global assignment uses the same pointer rules as locals, `u32` literals are bounded to 32 bits, and the parser, Sema, constant folder and codegen all run behind recursion guards (256 for syntax, 2048 for expression walks) with include-cycle detection. On the untrusted-input side: `verify-apk` cross-checks each local header name against the central directory, rejects NUL/unsafe names, requires v1 to cover every payload entry and fails closed on compressed entries it cannot digest, consumes every v2 signer sequence completely, and bounds ZIP sizes; BigInt `divmod`/shifts are guarded and RSA keys below 2048 bits are refused; debug keys are written through `mkstemp` at 0600. The linker checks relocation addends for signed overflow/underflow, validates TLS markers, TPREL64 input relocations, `.eh_frame` CIE consistency and section alignment, and lays out `.data | .tdata | .tbss | .bss` so a TLS object's `.bss` no longer inflates the file. `build-apk` validates package/ABI/lib names, rejects duplicate resources and ZIP entries, and defaults `android:debuggable` to false. Evidence in `VALIDATION-v0.23.61-dev.md`.
