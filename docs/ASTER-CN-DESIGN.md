> **实现补记（2026-11-19，S4 全局声明增量，后续增补）**：中文与英文双语前端支持顶层可变标量变量、顶层标量常量、一维固定长度全局标量数组，以及标量结构体全局变量和常量。普通标量变量可省略初值并按类型归零；枚举变量取首个成员，字符串标量取空串；标量变量的显式初值通过已有全局启动初始化链在进入 `main` 前执行。全局字符串数组支持一维字面量初值、默认空串、下标读写和内容比较，同样通过启动初始化链逐元素写入。全局结构体数组支持一维固定长度声明、结构体常量字面量列表初始化、默认值及下标成员读写；结构体元素沿用常量结构体字段限制，不能在全局数组字面量初始化中含字符串字段，含字符串字段的结构体数组也不能省略初值。常量必须有可编译期求值且类型兼容的整数、枚举、布尔、浮点或空指针初值，后续赋值由统一语义分析拒绝。全局数组支持元素列表或一个编译期标量重复填充。结构体全局值支持嵌套字面量的编译期初始化；省略初值的结构体可含标量、指针、枚举和数组字段，但不能含字符串字段（字符串默认值需要空串指针）；未初始化的枚举字段取首个成员。结构体字面量暂不接受数组字段或指针/字符串字段。
> **实现补记（2026-11-22，双语外部全局）**：中文 `外部("ASCII符号") 变量 名: 类型` 与英文 `extern let name: type;` 归一为外部全局对象声明；中文映射名必须非空且为 ASCII，外部全局禁止初始化。对象文件保留未定义 `OBJECT` 符号，读取和写入沿用普通全局 ABI；包导入会保留外部符号映射。外部全局数组、字符串和函数指针字段沿用同一声明模型，实际定义由链接输入提供。

> **实现进度（2026-11-21，OOP 对象布局、创建、静态成员、继承、接口契约与运行时分派）**：双语解析器生成 `ClassDeclaration` 与 `InterfaceClassDeclaration` AST。类名映射为带类布局 ID 的强类型对象指针，实例字段进入现有 AAPCS64 布局表；已有结构/指针成员访问路径可读取、写入字段，结构字段、参数、返回值和顶层变量可使用类引用类型。`类名()` 现生成零参数工厂函数，调用标准库 arena 的 `alloc` 分配对象，并递归初始化字符串为空串、枚举为首成员、其他标量/指针为类型零值及嵌套结构字段；分配失败返回空指针。实例方法体生成普通 Aster 函数，隐藏的第一个参数是强类型 `this` 指针；`对象.方法(…)` 按直接调用 ABI 传入对象地址，方法体内可使用 `本对象/this.字段`。`@静态` 方法没有隐藏接收者，通过 `类名.方法(…)` 调用；`@静态` 字段使用独立共享存储，不进入对象布局，通过 `类名.字段` 读写。静态方法中的 `本对象/this` 与 `父对象/super` 非法，对象调用静态成员或类名调用实例成员会报错。单继承已接入：父类须先声明，父类实例字段保持在派生对象布局前缀；父类方法按静态派发继承调用，方法重写拒绝；`父对象/super` 作为父类类型视图，派生类引用可隐式上转为父类引用。接口声明与 `类 A : 接口名` 的编译期契约检查已接入，要求每个接口方法的名称、参数类型和返回类型完全匹配；接口引用现在使用 16 字节对象/方法表对，类值可隐式转换为接口值，接口方法经生成的适配 thunk 和方法表运行时分派，支持返回值、`void` 方法、接口参数和多实现类。父类实现接口时，派生类可继承该契约并转换为接口；复杂接口接收者先物化后分派，避免重复求值。接口值允许为空；调用接口方法前会检查对象指针与方法表指针，任一为空时触发 `BRK #1`（Linux 上为 `SIGTRAP`）。类引用也允许为空；调用空类引用的实例方法，读取或写入空类引用的实例字段，或用空类引用执行枚举循环，都会触发同样的 `BRK #1`。接口值作为结构聚合处理，不参与普通标量比较。字段与方法支持 `@隐藏`、`@受限`、`@受限.类`；默认公开，私有仅本类可见，类成员的 `@受限` 等价于 `protected`、可由声明类及其子类访问（顶层声明上的 `@受限` 才按声明源文件限制，见权限语义修订）。权限检查覆盖字段读写、数组字段访问、方法调用和枚举循环；类对象枚举只产生公开字段的元信息。类成员跨文件访问权限已使用声明源文件身份检查，并由包导入测试覆盖实例构造、方法调用、继承和受限成员。使用对象构造时须链接标准库对象。未初始化的类引用仍为空指针，不会隐式创建对象。带参构造按设计暂缓。

> **构造器增量（2026-11-21，覆盖上一段的暂缓状态）**：双语类方法支持 `@构造` / `@constructor`，每类最多一个，必须是返回 `空` / `void` 的实例方法。`类名(参数…)` 分配对象并执行字段默认初始化，然后自动调用构造器；未标记构造器的类仍只接受零参数。派生构造器可将 `父对象(参数…)` / `super(args)` 作为第一句显式调用父构造器；每级父参数表达式在对应构造器的参数作用域内求值，并按父构造器形参顺序传入。父构造器按祖先到子类顺序执行，虚表随构造阶段切换；缺少必需调用、参数数量错误或调用位置错误均在编译期拒绝。构造器遵守成员可见性，不能作为普通实例方法调用。`初始化` 仍是普通方法名。对应回归套件为 `tests/cn-constructor-checks.sh`。

> **重写与动态分派增量（2026-11-21，覆盖本文件较早的“无虚表/不做重写”草案状态）**：实例方法（不含静态方法和构造器）通过类对象虚表运行时分派。子类重写必须写 `@重写` / `@override`，并与继承方法保持相同返回类型、参数类型及函数参数签名；缺少标记、没有可重写的父方法、静态/构造器重写、签名不同或缩小可见性均在编译期拒绝。父类字段前缀包含唯一隐藏虚表指针，子类沿用父类槽位顺序并把新方法追加到末尾。`父对象/super.方法(…)` 保持直接父类调用。构造期间虚表按祖先到当前类逐段切换，避免父类构造器调用子类实现。接口仍使用独立的接口适配表。双语运行与签名诊断覆盖由 `tests/cn-override-checks.sh` 检查。

> **类字段初值增量（2026-11-21）**：中英文类字段支持声明处初值。对象创建时先递归写入所有字段默认值；随后每层构造 helper 按父类到子类顺序执行：先完成父类字段初值与父类构造器，再设置当前类虚表、按字段声明顺序计算当前类字段初值，最后调用当前类构造器。初值表达式可访问 `this/本对象`、当前可见类成员和顶层符号；构造器形参不在字段初值作用域中。固定长度数组字段目前只接受等长数组字面量，按元素顺序初始化。即使类未被实例化，也会检查初值表达式、字段访问权限和目标类型兼容性；检查复用整数常量范围与类引用上转规则，函数指针按完整签名匹配。字段类型不匹配诊断按声明文件语言分别显示中文或英文。对应双语运行、类型、权限、数组长度与包导入回归位于 `tests/cn-constructor-checks.sh`，语法 AST 对等位于 `tests/cn-parser-checks.sh`。

> **静态类字段增量（2026-11-22）**：中文与英文类字段均可用 `@静态` 声明类级存储。静态字段作为独立全局变量生成，不进入对象布局；用 `类名.字段` 读写，实例限定访问静态字段以及类名限定访问实例字段均在编译期拒绝。标量、枚举、指针、类引用、字符串、单个函数指针和单个结构体字段受支持；结构体字段支持显式字面量初值、全局规则默认值、嵌套读取及写入。函数指针字段可通过 `类名.字段(参数…)` 间接调用。此外支持元素为标量、字符串、结构体和函数指针的一维定长数组，通过 `类名.字段[下标]` 读写或调用，字符串数组默认填充空串，数组初值须是长度匹配的字面量数组；结构体数组元素支持嵌套字段读写，函数指针数组元素按完整签名检查。默认值遵循全局规则，字符串为空串、枚举取首成员；显式初值通过现有全局启动链在入口前初始化。派生类可访问继承的静态字段，权限检查按声明类与源文件执行。包导入会重写模块内部类的静态成员引用和继承引用。双语共享状态、对象/类限定错误、跨包读写、静态数组、静态函数指针、静态结构体、静态结构体数组和继承访问由 `tests/cn-override-checks.sh` 和 `tests/cn-module-checks.sh` 覆盖；未运行全量 CI。

> **函数指针数组字段增量（2026-11-22）**：普通实例类字段和结构体字段现在也支持一维定长函数指针数组。数组元素沿字段声明的完整函数签名检查，支持声明处数组字面量初值、默认值、下标赋值、读取和间接调用；实例字段通过对象布局保存，结构体字段沿用结构体布局，调用时不会退化为无签名的裸指针。静态字段、实例类字段和结构体字段的这三条路径共用相同的签名校验规则。

> **跨包函数值导入增量（2026-11-22）**：公开顶层方法除了可通过 `包别名.方法(参数…)` 直接调用，也可以写成 `包别名.方法` 作为函数指针初值或数组元素；导入重写会保留包符号并执行同一公开性检查。`@隐藏` / `@private` 方法以及受包文件权限限制的方法不能跨包取得函数值，诊断与跨包直接调用保持一致。

> **跨包接口与回调字段增量（2026-11-22）**：导入的接口类型可以作为方法参数接收包内实现类，类到接口的转换和接口方法表动态分派保持跨包有效。实现类的方法可以读取实例函数指针数组字段，再通过接口值调用；接口适配 thunk 只负责接收者和方法表转换，不会丢失字段函数签名。中英文调用方、接口转换和回调字段组合由 `tests/cn-module-checks.sh` 覆盖。

> **接口继承增量（2026-11-22）**：接口类现可用 `接口类 子接口 : 父接口` / `interface class Child: Parent` 单继承一个先声明的接口；子接口自动继承父接口方法签名，重复声明继承方法会报错。类实现子接口时同时实现其父接口契约，并可转换到子接口或祖先接口；接口方法表分别为每个祖先接口生成。实现方法必须公开，受限或隐藏方法不能实现公开接口方法；函数指针参数按完整签名参与契约匹配。跨包子接口可继承另一包的公开接口，双语运行、受限实现拒绝和函数签名不匹配由 `tests/cn-module-checks.sh` 覆盖，AST 对等由 `tests/cn-parser-checks.sh` 覆盖。

> **接口返回值上转型增量（2026-11-22）**：函数或接口方法返回的子接口值现在可直接作为父接口参数或返回值。表达式 lowering 保留接口对象/方法表的两字 ABI；对嵌套函数调用结果生成一次性转换函数，避免把无地址的结构体返回寄存器值误当作左值。父接口方法表布局保持子接口表的前缀，因此转换后父接口分派读取正确槽位。中英文、跨包和单次求值由 `tests/cn-module-checks.sh` 覆盖。

> **接口值字段与数组存储增量（2026-11-22）**：接口值的 16 字节对象/方法表对现可写入结构体字段、类实例字段及这些字段的一维定长数组元素；读取或赋值后仍保留对应方法表并执行接口动态分派。中英文赋值和调用回归由 `tests/cn-interface-checks.sh` 覆盖。

> **实现进度（2026-11-20，S4 双语入口与源码包导入）**：中文入口使用 `启动方法`，英文入口使用 `main`；中文源码写 `main` 会得到明确解析错误，`启动方法` 与 `main` 归一到同一个 AST/ABI 入口。当前没有入口类机制，若后续加入则中文名称为 `启动类`。中文枚举沿用块结构，以 `结束 枚举` 闭合；英文枚举继续使用花括号。源码包头允许 `包名 规范名 = 别名`，同包文件必须声明完全一致的别名表；索引按规范名合并源码，别名不按语言自动翻译，例如中英文文件共同声明 `包名 标准库.数学 = standard.math`，然后分别写 `@导入("标准库.数学")` 与 `@import("standard.math")`。包导入现支持顶层方法、标量全局变量/常量、结构、枚举、类和接口类；包符号按包名前缀重整，包内公开全局读写和函数调用可跨源文件工作，`@隐藏`/`@受限` 方法、全局和类型不从声明文件导出。导入的类支持构造、实例/静态调用、继承与成员权限检查；`@受限.类` 可按继承关系跨包访问。测试覆盖包内 `@静态`、类实现导入接口、枚举限定成员、跨文件受限访问、包名别名冲突与循环依赖。搜索路径仍需显式通过源目录、`--module-dir` 或项目目录提供，标准库源码目录目前由 `--module-dir` 加入。

> **实现补记（2026-11-19，S5）**：`字节/i8` 与 `短整数/i16` 已接入中文和英文前端、窄整数存储布局、符号扩展加载、显式转换、函数参数/返回、结构字段及数组元素，并写入有符号 DWARF 基础类型。枚举循环字段 Kind 为兼容既有编号，将 `i8` 与 `i16` 追加为 15 与 16。自动默认值为零；初始化常量按有符号范围检查。

> **实现补记（2026-11-19，S5 约束确认及后续实现）**：自动初始化不是“等待后续赋值”的临时状态。变量、结构体字段和字段数组元素在声明后即有确定默认值；即使程序从未再次赋值，也可以直接读取并参与表达式计算。`build-cn-obj` 现会在成功语义检查后提示自动初始化的局部变量、数组或结构体字段：若整个方法体没有再次赋值，则报告其值保持不变，并按源文件语言显示中文或英文提示。分析覆盖分支和循环；检测到显式取址或枚举循环暴露字段地址时会保守抑制相关提示。显式初始化的变量、常量和全局变量不在本提示范围内；现有旧前端构建命令也不受影响。测试覆盖只声明、不二次赋值的读取路径。

## 0.2 当前 Aster 真实语法（主树实读，`docs/language-reference.md` + `src/aster.cpp`）

- **声明**：`fn 名(参数: 类型) -> 返回类型 { … }`；`let 名: 类型 = 表达式;`（初始化强制，结构体例外可零填）；`const 名: 类型 = 表达式;`（v0.23.67-dev）；`struct 名 { 字段: 类型 }`；`enum`（i32 常量）；`union`；`type 别名 = 类型;`；`include "文件.ast";`（声明共享，循环依赖报错，菱形去重）。
- **块闭合**：一律花括号 `{ … }`。`if/while/for/switch/fn/struct` 全部以 `}` 闭合，没有任何“结束 X”形态。
- **语句结束**：分号强制。`let`、`return`、赋值、调用语句都以 `;` 结束；换行只是空白（`isspace`），**换行不结束语句**。裸表达式语句被拒绝，只有调用可作弃值语句。
- **控制流**：`if/else if/else`；`while (条件)`；`for (初始化; 条件; 步进)`（三段式，`continue` 落到步进）；`do { … } while (条件);`（v0.23.77-dev）；`switch (整数) { case 常量: … default: … }`（Pascal 语义、无贯穿、无需 break）；标签 `break/continue 标号;`。
- **类型系统**：`Ty` 是 `(Kind k, int sid)` 对（`src/aster.cpp` L648 起实读），当前 `Kind` 为 `I8 I16 I32 U32 U8 U16 I64 U64 Ptr Bool Enum Struct Char Void F32 F64`，指针元素另记 `(ekind, esid, ew)`。本节原始基线核查时尚无 `i8`/`i16`；现已按 §1.2 加入有符号 8/16 位类型，分别占 1/2 字节并按有符号值加载。`bool` 占 4 字节（非 C 的 1 字节）；`char` 为 1 字节无符号整数，与 `'a'` 字面量（折叠为 `i32`）是两个东西；`void` 只能出现在函数返回位置，不能作值、参数、局部、字段、别名或数组元素；**没有字符串类型**——字符串字面量是 `__aster_string_<n>` 静态符号，类型为 `ptr`，标准库用 `ptr` + `streq`/`str_dup` 等函数操作字符串；空指针就是字面量 `0`（C 惯例）。
- **运算符**：算术/比较/逻辑/位运算全部符号化；`&&`/`||`/`!`；`? :`；`++`/`--` 只作语句；`sizeof`/`len` 为上下文相关运算符；`T(x)` 为唯一显式转换。
- **回调形态**：函数指针类型 `fn(P) -> R`（8 字节，存为 `ptr`）；框架回调统一为显式 `(fn, ctx)` 对，即 `cb: fn(ptr) -> i32, user: ptr`（AsterUI `aui.ast` 实抽：`aui_button` 等登记点均为此形态）。§11f 明文：无变长定义、无闭包、无泛型、无 `include` 之外的模块系统、无托管堆，理由是同一组地基——AAPCS64 调用形态、`Ty` 无类型参数位置、无托管堆的内存模型。
- **属性/注解**：只有 `@embed("路径")`、`@embed_len("路径")`、`@align(N)` 三种属性形态（`@` 后名字上下文检查，非保留字）。没有通用注解系统，没有 `@导入`、`@隐藏`。

## §0 定位与分界

### §0.1 新设计是什么

一门**中英双语**的原生编程语言设计：源码用中文或英文关键字、中文或英文类型名书写；**语言模式是源文件的编译属性**（v0.1 §2）：每个源文件只能用一种结构性语法配置（`zh` 或 `en`），模式按优先级确定——命令行显式强制 > 文件声明 `// aster:language=zh|en` > `aster.proj` 的 `[language] default`（可加 `allowed` 限制）> 编译器默认（**默认 `zh`**，即无任何配置时按中文模式编译；**后果**：无声明的现有英文 Aster 源码不再能直接按默认编译，须补文件声明 `// aster:language=en` 或在 aster.proj 里设 `[language] default = "en"`，否则按中文模式解析会报错——见 §3.1 与 §5.1 S2 验收门）；项目强制模式与文件声明冲突时报错；**禁止按文件字符自动猜模式**。同一文件内禁止混用中英文结构性关键字（`如果 … end if` 非法，见 §2.5 与诊断 A-27）；标识符、字符串、注释、外部 API 名、库名可在文件内跨语言（`变量 userName: 字符串 = "张三"` 合法）。同一项目允许中英文源文件共存、互相调用（见 §2.12 与 v0.1 §13）。中文文件块闭合用 `结束 结构名`，英文文件用 `}`（见 §2.5：按文件模式单轨，不再双轨混用）；换行作语句分隔符（中文模式，见 §2.5；英文模式沿用既有分号与换行规则，见 v0.1 §7.3）。编译器前端为双语重写（双 Lexer/Parser，统一 AST，见 §3.0），代码生成复用现有 AArch64 后端（寄存器分配、AAPCS64 调用约定、ELF 写出、DWARF 写出器），最终产物仍是目标平台可执行代码，不经过 C/Java/Kotlin 转译。标准库采用统一实现、双语接口（见 §2.15）；API 名第一版保持 ASCII 的旧收窄已废止，改为 v0.1 的双语接口设计。

### §0.2 新设计不是什么

- **不是**旧线的简单延续：旧线也是双语（`fn` 仍在、`函数` 是它的中文别名），但旧线花括号仍在、`结束` 被明确否决、`循环` 指三段式计次循环、`方法` 被拒用；新设计同样双语，但关键字映射不同（`方法`/`fn` 为函数关键字，`函数` 不用；`循环`/`while` 为条件循环，`计次循环`/`for` 为计次循环，见 §2.8），且块闭合**按文件模式单轨**（中文文件 `结束 结构名`，英文文件 `}`，见 §2.5；v0.1 合并后不再允许同一文件内双轨混用）。两者源码**部分互通、部分不互通**：纯英文旧线程序若只用 `fn/if/while/for` 且用 `}` 闭合，在新设计下多数字符仍合法，但 `for` 的三段式形态与 `switch` 的旧形态在本设计下是语法错误（见 §1.1、§2.7）；中文旧线程序须按 §4 分歧表人工重审每一个 `循环`。
- **不是**结绳的复刻：只借草案已采纳的形态（`结束 结构名`、`本对象`、`假如/是`、四种循环），不借转译后端、不借“平台基础类自动订阅事件”、不借“异步方法不能声明返回类型”等结绳专属限制。
- **不是**一门新运行时语言：无 GC、无托管堆、无异常、无 async 运行时；内存模型仍是显式所有权 + arena/固定表（见 §2.11、§5）。
- **不是**实现：本文件不含任何编译器代码改动，任何人按本文件开工前仍须先过 §5 的立项门。

### §0.3 验收标尺（用户定的那条，原文复述）

**同样的功能逻辑，Aster 写出来要比别的语言短，才有意义；原生直出只是手段，不是目的。** 本设计的所有取舍都过这一道标尺：凡只改拼写不省行的改动（如关键字 1:1 替换），在本设计里一律标为“可读性收益、行数收益 0”，不得冒充省行；省行必须由 §6.2 列出的机制（默认初始化、四种循环、方法/类收拢样板、遍历/枚举、注解权限、闭包）兑现，并以 §6.3 的三份改写草稿实测。行数口径见 §6.1：凡估算必写“估算 + 口径”，凡实测必写 `wc -l` 数，单点假精确一律不给。

### §0.4 与旧线的关系总表（细表见 §4）

旧线解决的是“让现有 Aster 程序员用中文写出同样的程序”；新设计解决的是“让中文开发者按中文思维写出更短的程序”。前者以兼容为上，后者以中文原生与简洁为上，兼容为代价——两条线目标不同，所以分开，不存在谁对谁错。

# §1 关键字与类型总表

## §1.0 总决定

- **D-01（双语共存，2026-11-18 用户拍板，否决中文唯一；2026-11-18 v0.1 合并重写：双语按文件隔离，不再同一文件内混用）**：语言关键字与类型名**中英双语并存、1:1 对应**：每个 Token 有中文与英文两个拼写，两者完全等价（见 §1.1 总表，每行均有英文对应词），英文拼写仍是关键字（不是普通标识符）。**但等价只在语言模式的层面成立，不在同一文件内成立**：一个源文件只能选一种结构性语法配置（`zh` 或 `en`，见 §0.1），文件内出现另一模式的结构性关键字即报错（诊断 A-27）；标识符、字符串、注释、外部 API 名、库名可跨语言，不受此限。上一轮修订曾允许“同一文件内中英混用（同一结构内混用亦可）”，**本次合并按 v0.1 §2.5 废止该允许**：混用使“同一文件一种模式”的隔离失效，诊断须逐结构判断当前拼写属于哪种模式，测试语料也要按文件模式翻倍，且 `aster translate`（AST→另一语言源码，见 §5）的前提正是“每个文件一种模式、AST 与模式无关”——混写文件无法干净地翻译。代价（诚实写出）：① 两套关键字表、两套诊断文案（诊断须按文件模式给出对应语言的提示，并写明当前文件模式）、两套测试语料（每特性至少一中文文件一英文文件两个正向用例，见 §5 各阶段验收门）；② `循环` 一词在旧线里的旧义（`for` 三段式）与新设计里的新义（条件循环，见 §2.8）仍冲突，旧线源码迁移须人工重审每一个 `循环`，工具不得自动转；③ 双语本身省 0 行（关键字 1:1 替换，旧线已验证），省行仍靠 §6.2 的机制。标准库与 AsterUI 的 API 名按 §2.15 的双语接口设计（v0.1 §14：一套实现、两套语言入口），不再是“第一版保持 ASCII、中文包装限 20 个”的收窄。
- **D-02（关键字注册表，一个 Token 一组拼写，中英共享 Token；v0.1 §4/§10）**：关键字注册表是“拼写 → TokenKind”的映射（v0.1 §10 的 `KeywordEntry { spelling, token, mode }`），中文与英文拼写映射到同一 TokenKind。**一个 Token 可有多个拼写**（中英各一）；但**一个拼写只映射一个 Token，不得例外**——`循环` 只对应条件循环（WhileLoop），不兼任范围循环（v0.1 合并时引入的“一词两用、解析层向前看判别”D-15 已随范围循环一并撤销，见 §2.8）。`逻辑型`/`bool` 是布尔类型唯一的中文/英文拼写，`布尔` 是普通标识符。

## §1.3 运算符与标点（定案）

- 算术 `+ - * / %`、比较符号 `== != < <= > >=`、逻辑符号 `&& || !`、赋值 `=` 与复合赋值 `+= -= *= /= %= <<= >>= &= |= ^=`、位运算 `& | ^ ~ << >>`、成员 `.`、索引 `[]`、调用 `()`、取址 `&`、解引用 `*`、自增减 `++ --`（语句形式）**全部保留符号形式**，与草案一致，不设中文算术别名。
- 中文比较/逻辑别名（`等于/不等于/大于/小于/不小于/不大于/且/或`）与符号形式**同语义、同优先级**，可混用；`!` 不设中文别名（草案原定，本设计保留：`不` 若作逻辑非会与 `不小于` 冲突，见 D-05；v0.1 §6.3 的 `非` 亦不采纳，见 §1.1 末段）。
- 标点：**全角与半角等价接受**（见 §2.5 D-06，2026-11-18 用户拍板回到草案原文）：代码位置的 `，`/`：`/`、` 与 ASCII `,`/`:` 等价，词法器在分词前将其归一化为 ASCII 再分词；字符串与注释内的全角标点原样保留，不归一化。本设计与草案示例的混用完全一致，不再是偏离。
- **冒号 `:`（D-16，2026-11-18 用户追加决定）**：统一的定义分隔符，三用——类型定义（`变量 a: 整数`、`方法 b(): 整数`）、类继承（`类 A : B`，B 为普通类）、类实现（`类 A : B`，B 为接口类），按句法位置区分（见 §2.9 D-16）；其余出现处（三元 `? :`、标签 `标号:`、注释指令 `// aster:language=`）各有自己的句法位置，不构成第四种定义含义，见 D-16 扫查。
- 分号 `;` 可选（见 §2.5），但**不是**“可有可无的装饰”：分号与换行是同一类语句结束符，解析器按 §2.5 的规则表处理。
- 注释：单行 `//`（采纳）；多行 `/* … */`（采纳，沿用现有规则：不嵌套，首个 `*/` 闭合，未闭合报错）——草案说“多行注释待定”，本设计直接定为沿用现有形态，不留待定。

# §2 语法与语义逐章定案（按草案第 2–12 章）

凡本节写“采纳”指按草案原文实现；“修改”指改动草案并写明理由；“暂缓”指本设计第一版不做并写明触发条件。§2 末尾有 12 项裁决（D-03–D-14）与草案逐项的对照总表——其中 D-03/D-06 已按用户 2026-11-18 拍板撤销偏离、回到草案原文（见各条“撤销版”）；§2.14 为闭包专节（同日拍板纳入）。

## §2.1 变量与常量（草案第 2 章）——采纳，带两处修改

- `变量 名: 类型` / `变量 名: 类型 = 初值`；`常量 名: 类型 = 初值`（常量必须初始化，初始化后不可再赋值，取址亦拒绝——沿用现有 `const` 规则：`&常量` 拒绝，因 `指针` 无只读位）。
- **修改 1（类型推导）**：草案 §8.3、§14 示例用 `变量 名单 = […]`、`变量 用户甲 = 用户()` 省略类型标注。本设计**采纳省略类型标注时的推导**：初值表达式类型即声明类型（数组字面量推导元素类型与长度，`类名()` 推导为 `指针<类名>`）；但推导失败（初值类型未知、空数组字面量 `[]`）时报错，不猜。无初值时**必须**写类型（`变量 年龄: 整数`），无初值 + 无类型一律拒绝。
- **修改 2（无初值 = 默认初始化代码）**：`变量 年龄: 整数` 不写初值时，编译器**插入**默认初始化代码（见 §2.3），不是“声明后等待赋值”。因此本设计不存在“未初始化读取”这一错误类——凡声明即有确定值；读取未赋值变量的问题被默认初始化规则整体消除（草案 3.4 “不得允许程序在没有确定初始化状态的情况下读取变量”以此方式兑现）。

- **数组表面语法裁决（2026-11-19）**：遍历循环与枚举循环的绑定列表和对象表达式用箭头符号分隔——**只在中文侧**：`遍历循环 (索引, 项 -> 名单)`、`枚举循环 (字段 -> 对象)`；英文侧用 `in`：`foreach (index, item in list)`、`enumloop (field in object)`。`于` 不再是关键字或保留字，可作标识符；中文 `->` 沿用现有词法 Token，不增加关键字。数组声明保留 `变量 名: 元素类型[长度]`，一维数组字面量为 `[值, …]`；空列表不能推导类型或长度。

## §2.2 方法（草案第 6 章）——采纳，带一处定案

- `方法 名(参数: 类型, …): 返回类型` / 省略返回类型 = 无返回值（等价于 `: 空`，两者可互换，语义相同）；`返回 表达式` / 无返回值方法中 `返回` 不带表达式（提前退出）。
- **定案 D-09（`方法` 一词两用）**：顶层自由函数与类成员方法**共用** `方法` 关键字，区分靠位置：写在类体内的 `方法` 是成员方法（隐式首参 `本对象: 指针<类名>`，调用时 `对象.方法名(实参)` 脱糖为 `方法名(&对象, 实参)`，纯语法糖、无虚派发——S4 前）；写在类体外的 `方法` 是顶层函数。方法名解析：`对象.方法名` 先按对象类型找成员方法，找不到时报“无此方法”并给近似名提示（复用现有 `nearestFrom` 思路）；顶层 `方法名(…)` 只找顶层方法。成员方法不得与同名顶层方法重载消歧——同名时成员方法优先于顶层方法，诊断写明。参数默认值、可变参数、引用传递、移动语义：**全部暂缓**（S4后复评，触发条件见 §5）；第一版参数一律按值传递，`结构` 按值传递即整块拷贝（沿用现有规则），大对象传参成本由程序员自担、文档写明。

## §2.3 类型与默认值（草案第 3 章）——修改为主

- **D-03（(a) `空` 的三用，裁决——2026-11-18 撤销拆分、回到草案原文；2026-11-18 v0.1 合并时用户两次追加决定：三用不变，v0.1 拆分全部不采纳）**：用户原话的道理——按语义很好区分，作为类型时就是 void，作为值时就是 null：类型位置与值位置是两种语义，`空` 一词三用不构成歧义，这是本裁决的核心理由。草案让 `空` 同时作三件事——void 返回类型（3.1、6.1）、指针默认值（3.4 表格）、引用空值（3.4 文字）。上一版设计曾以“歧义”为由将其拆分为 `空`（类型）与新词 `空值`（值），用户拍板不接受该偏离，**本修订撤销拆分、删除新词 `空值`，恢复草案原文的三用**；v0.1 §4 又提出另一拆分（`空`=void / `无`=null），**用户追加决定亦不采纳，`空` 三用不变**。**裁决：`空` 按句法位置区分角色，位置本身就是区分信息，不构成歧义**：① 冒号后的类型位置（`方法 f(): 空`、`: 空`）——`空` 是类型 `void`，仅允许作方法返回类型；② `=` 后、表达式值位置、函数实参位置、比较运算位置（`变量 p: 指针 = 空`、`如果 p == 空`）——`空` 是空指针/空引用字面量，值 0，类型为 `指针` 或上下文推导的可空类类型；③ 其他位置一律拒绝：`空` 作变量/参数/字段/数组元素类型（`变量 x: 空`、`方法 f(x: 空)`）拒绝，报错“`空` 不能作变量/参数/字段类型，请写具体类型”——沿用现有 `void` 限制。病态写法 `变量 x: 空 = 空`：解析器按位置读出第一个 `空` 是类型、第二个 `空` 是值，**角色可区分**；该写法报错的原因不是歧义，而是第一个 `空` 落在禁用的变量类型位置（规则③），诊断须写清是“类型位置非法”而不是“`空` 歧义”。草案 3.4 表格恢复原文写法：指针默认值 `空`，引用类型默认值 `空`。词法器只产生一个 `空` Token（VoidKw/NullLit 同一 Token），语义由解析器按位置赋予，不设两个 Token。**英文不对称（v0.1 合并裁决）**：英文文件里类型位置写 `void`、值位置写 `null`（英文保留 `null` 作空值字面量），中文文件里两处都写 `空`；统一 AST 里两者都是 NullLit/Void 节点，语义统一，不对称只在表面拼写（理由见 §1.1 `空` 行）。**`无` 不用（用户追加决定）**：`无` 不是保留字、不是关键字，在本设计稿里不得作为空值写法出现；中文空值只写 `空`，英文空值只写 `null`；写 `无` 作空值时报错并提示用 `空`（中文文件）或 `null`（英文文件），诊断 A-28。`无` 作标识符合法。
- **D-04（(b) `u字节` 的拉丁 u 与大小写，裁决——2026-11-18 v0.1 合并，按 v0.1 §5.1 定案，上一轮“只认小写 u”被覆盖）**：草案说无符号类型名前加 `u`，且 `u`/`U` 不区分大小写；上一轮修订裁决只认小写 `u`（`U整数` 拒绝），该裁决**本次按 v0.1 §5.1 废止**。**裁决：无符号 `u` 前缀在类型别名注册时大小写不敏感，规范拼写统一为小写**：词法器接受 `u整数` 与 `U整数` 两种拼写，注册时归一化为小写 `u` 再查表（v0.1 §5.1 原话：“大小写不敏感的规则只适用于类型别名的注册策略，最终建议统一采用小写规范拼写”）；`U整数` 不再报错，但诊断与文档、以及 `aster translate` 的输出一律用小写规范拼写 `u整数`，并可附风格提示“建议写小写 `u`”。大小写不敏感只适用于 `u` 前缀这一处类型别名注册，不扩及关键字与标识符（Aster 标识符与关键字仍大小写敏感，`src/aster.cpp` 词法按字节相等匹配；单为 `u` 前缀开注册期归一化，不污染标识符比较路径）。`u` 不得与类型名用空格分开（`u 整数` 是两个词，报错，诊断 A-04 不变）。
- **D-08（字符串 / 字符 / 视图，定案）**：字符编码定为 **UTF-8**（草案 3.3、15 章“优先考虑 UTF-8”直接定案，不留待定）。`字符串` = 拥有所有权的 NUL 结尾 UTF-8 字节串：字面量 `"张三"` 在 rodata 里生成 `__aster_string_<n>` 符号（沿用现有机制），类型为 `字符串`；长度约定在 S4 定案为 **NUL 扫描**（见 §5.1 S4）：字符串长度 = 扫描到 NUL 的字节数，字面量与运行时拼接结果均以 NUL 结尾；字符串不得内含 U+0000（字面量含 NUL 即报错）；遍历与拼接在循环/调用入口扫描一次并把长度缓存进隐藏局部槽，不逐元素重复扫描；O(n) 扫描成本写进文档，不粉饰；变量持有 `字符串` 即持有指针，赋值即指针拷贝（**不**深拷贝，与现有 `ptr` 字符串语义一致，文档写死）；释放责任在程序员（`字符串` 无析构，见 §2.11）。`字符串视图` = `{指针, 长整数}` 16 字节值类型：只能由 `字符串` 显式转换（`字符串视图(字符串值)`）或库函数返回产生，不得由字面量直接产生；视图不拥有内存，指向的串被释放后视图悬垂，责任在程序员，编译器不做逃逸分析（与闭包 env 的责任划分同一原则，见 §2.14）。`字符` = 1 字节无符号整数（复用 `char`）；“空字符” = 值 0 的 `字符`。**字符是字节还是 Unicode 字符（v0.1 §18 待定项，本设计定案）**：`字符` 是**字节字符**，不是 Unicode 标量——一个 `字符` 只装一个字节，UTF-8 多字节字符须用长度大于 1 的 `字符串` 表示；`字符串` 遍历出的是字节（`字符`），不是 Unicode 标量，遍历到多字节字符中段时程序员须自行按 UTF-8 解码（标准库在 S6 提供 `字符串.按字符遍历` 辅助，见 §2.15）。此决定与 `char` 的现有语义一致，不另设 Unicode 字符类型。
- **默认初始化规则（定案，草案 3.4 的表格逐项落实）**：标量整数/浮点 → 0 / 0.0；`逻辑型` → `假`；`字符` → 0；`字符串` → 指向编译器生成的静态空串符号 `__aster_empty_string`（rodata 里一个字节 0，不得写，写操作是未定义行为——文档写明，编译器不拦截）；`指针` → `空`（0）；`结构`/`联合` → 字段递归默认初始化（整块零填与字段递归等价时编译器可优化为零填，但语义上是逐字段默认初始化，含 `字符串` 字段时须填空串指针而非全零——实现须注意此差别，不得把含字符串字段的结构一律 `memset 0`）；`类`对象 → 只以 `指针<类名>` 出现，默认 `空`；`枚举` → 首个枚举值（若枚举无成员则该类型不得默认初始化，报错）；数组 → 元素递归默认初始化。类工厂先应用这些字段默认值，再调用显式 `@构造` 构造器；未声明构造器的类只接受零参数创建。`结构`/`联合`仍只有字段默认值，不设用户构造方法（见 D-11）。

## §2.4 运算符（草案第 4 章）——采纳，带一处裁决

- 算术、比较符号、逻辑符号、赋值全部采纳；中文比较/逻辑别名采纳。
- **D-05（(c) `不小于` / `不大于` 的解析歧义，裁决）**：`不小于` 若按“`不` + `小于`”读是逻辑非套比较，若按整体读是 `>=`，草案未给分词规则。**裁决：最长匹配 + 连写强制**。词法器在标识符位置按最长匹配优先识别 `不小于`、`不大于`、`不等于`、`不`（`不` 本身不是独立 Token，单独出现即报错“`不` 不能单独使用，逻辑非请用 `!`”）；`不小于`/`不大于`/`不等于` **必须连写、中间不得有空格**，写成 `不 小于`（带空格）时词法器报“`不 小于` 须连写为 `不小于`”。`!` 的优先级与现有 `!` 相同（一元，高于比较）；中文 `且`/`或` 与 `&&`/`||` 同优先级（`且` 高于 `或`，沿用现有 `&&` 高于 `||` 的规则）。运算符优先级完整表（本设计定案，不留待定）：一元 `! - ~ * &` > `* / %` > `+ -` > `<< >>` > `< <= > >=`（含中文别名） > `== !=`（含中文别名） > `&` > `^` > `|` > `&&`（`且`） > `||`（`或`） > `? :` > `=` 及复合赋值。类型转换只有显式 `类型(表达式)` 一种（沿用现有 `T(x)`），无隐式窄化（沿用现有拒绝规则）。

## §2.5 语句、块与换行（草案第 5 章）——修改为主

- **块闭合（按文件模式单轨，v0.1 合并；上一轮的“双轨混用”已废止）**：中文模式文件用 `结束 结构名` 闭合，英文模式文件用 `}` 闭合；结构名必须与打开的结构关键字**对应相同**（中文文件：`如果` 配 `结束 如果`，`方法` 配 `结束 方法`，`类` 配 `结束 类`，`接口类` 配 `结束 接口类`，`循环` 配 `结束 循环`，`计次循环` 配 `结束 计次循环`，`遍历循环` 配 `结束 遍历循环`（结束名须与开块关键字逐字相同），`枚举循环` 配 `结束 枚举循环`，`假如` 配 `结束 假如`；英文文件：`if/fn/class/while/for/foreach/enumloop/switch` 配 `}`）。`结束` 后一律写中文结构名，`}` 后不跟结构名。**同一文件内不得混用两种闭合形态**：中文文件里写 `}` 即报错“本文件为中文模式，块请用 `结束 结构名` 闭合”（诊断 A-27），英文文件里写 `结束 …` 同理报错。错配时报错并指出期望的结束名与实际的结束名及打开位置的行号（见 §3.2 结构栈）。上一轮修订曾允许“中文开块后误写 `}` 亦可接受”，**本次按 v0.1 §2.5 废止**：闭合形态是文件模式的一部分，混用即模式混用。
- **草案 §14 的内部笔误**：综合示例里计次循环以 `结束 循环` 收尾（原文如此，见 `SPEC-v1.0-ORIGINAL.md`）。按本设计这是**错配错误**，正确写法是 `结束 计次循环`；§6.3 的改写草稿已据此修正，并把该笔误记入 §7。
- **`否则如果` 与 `否则`**：`否则如果 条件` 后直接跟语句块，不再写 `如果`；`否则` 后直接跟语句块；两者都由最近的 `结束 如果` 闭合。`假如` 的默认分支同样用 `否则`（不另设 `默认`）。
- **D-06（(h) 中文标点，裁决——2026-11-18 撤销拒绝、回到草案原文）**：草案示例混用中文全角 `，` 与 ASCII `,`（§7.3、§8.2、§8.3、§14 用 `，`，§2.1、§6.1 用 `,`），未给规则。上一版设计曾裁决“代码位置只认 ASCII，全角报错”，用户拍板不接受该偏离，**本修订撤销拒绝，恢复草案原文的混用**。**裁决：全角与半角等价接受**。词法器在分词前做归一化：代码位置的 `，`（U+FF0C）、`：`（U+FF1A）、`、`（U+3001）一律归一化为 ASCII `,` / `:` 再分词；字符串字面量与注释内的全角标点**原样保留**，不归一化。归一化是码点到码点（1 个全角码点 → 1 个 ASCII 码点），列号按码点计的规则不受影响（见 §3.1）。收益：输入法全角误触不再报错；代价（诚实写出）：① 同一份源码可出现两种标点写法，风格检查须另立规则（本设计不强制统一，只建议项目内统一，`aster fmt` 若将来做再定）；② 归一化只发生在词法器入口，源码文件本身仍存全角字节，`grep ','` 等 ASCII 工具搜不到全角写法的分隔符，工具链须知晓此规则；③ 诊断文案引用源码片段时须写归一化后的 ASCII 形态，并在位置后注明原文全角拼写，避免用户按诊断里的半角标点在原文里找不到对应字符。
- **D-07（(g) 换行作语句结束与续行，裁决——本设计风险最大的规则）**：词法器产生显式 `换行` Token（NL），解析器按以下规则表判定，**不得**简单忽略全部换行，也**不得**把每个换行都当语句结束：

| 情形 | 判定 |
|---|---|
| 行尾最后一个有效 Token 是二元运算符（`+ - * / % == != < <= > >= && \|\| 且 或 = += …`）或逗号 `,` 或左括号 `(` `[` 或冒号 `:` | 续行：换行不结束语句，下一行继续读表达式 |
| 行尾是 `=`（赋值/初始化） | 续行（草案 5.2 的多行表达式示例即此情形） |
| 括号 `()` / `[]` 内部 | 换行一律忽略（括号内可自由换行） |
| 行首第一个有效 Token 是二元运算符 | **拒绝**：报错“表达式不得以运算符开头换行，请把运算符留在上一行末尾”；本设计**不接受**行首运算符续行（与某些语言相反），理由是行首运算符会让“上一行是否已结束”的判定依赖向前看，解析器复杂度与误诊率都上升 |
| 结构关键字行（`如果 条件`、`循环 (条件)`、`假如 表达式`、`是 值`、`方法 …`、`类 名` 等） | 行尾换行即结构头结束，进入块体；条件/表达式不得跨行（除非括号内或行尾运算符续行） |
| `结束 结构名` 行 | 换行即结束，不需分号；`结束 如果;` 的分号**拒绝**（多余分号报错，理由是结束标记自带终结语义，分号会制造“空语句”的歧义） |
| 其他完整语句行尾 | 换行即语句结束；分号 `;` 与换行等价，可互换；同一行写两个语句须用分号分隔（`变量 a: 整数 = 1; 变量 b: 整数 = 2` 合法）；连续两个分号 `;;` 拒绝（空语句不存在） |
| 字符串字面量内换行 | 拒绝（沿用现有 `newline in string literal`） |

  行尾运算符续行的判定只看**上一行末尾**，不看下一行开头——这是本设计刻意选的单向规则，解析器只需一词向前看（lookahead 1），代价是用户必须把运算符写在行尾，文档与诊断须把这条写在最显眼处。
- **冒号行尾（D-16 扫查）**：行尾冒号一律续行——`假如…是` 分支头后不跟冒号（见 §2.7），行尾冒号只出现在类型标注、类头、标签、三元内，均为续行上下文；旧版“分支头、参数冒号除外”的括号已随本次冒号统一删除（见 §2.9 D-16）。

## §2.6 方法系统（草案第 6 章）——见 §2.2（D-09）

补充：顶层方法调用 `求和(10, 20)`；实例方法调用 `用户甲.获取姓名()`；静态方法以 `@静态` 标记，并通过类名调用，例如 `用户.创建(…)`。静态字段也以 `@静态` 标记，通过 `类名.字段` 访问；它们使用共享存储，不属于对象布局。静态方法没有隐式 `this`，不得在方法体内使用 `本对象/this` 或 `父对象/super`；通过对象调用静态成员、通过类名调用实例成员均报错。全名限定调用（模块前缀 `数学库.平方根(16)`）见 §2.10。

## §2.7 条件与匹配（草案第 7 章）——采纳，带两处裁决

- `如果/否则如果/否则/结束 如果` 采纳；条件接受 `逻辑型`、数值和指针：`0`/`0.0`/空指针为假，非零数值/非空指针为真；枚举按底层整数判断。布尔逻辑运算仍须使用逻辑型操作数。字符串地址按指针空值判断，不扫描内容；结构体不接受为条件。**v0.1 EBNF 缺失说明**：v0.1 §9 的 EBNF 只给了 `如果/否则`、没有 `否则如果` 与 `假如`，那是 v0.1 EBNF 的不完整，不是本设计的删除——`否则如果` 与 `假如/是/否则` 是保留的 v1.0 草案能力，EBNF 待补（实现轮在 S3 按 §2.7 的语义补写 EBNF 产生式，见 §7）。
- `假如/是/否则/结束 假如` 采纳；执行规则采纳草案 7.4 的 1–7 条（只求值一次、自上而下、命中即执行并退出、无贯穿、`否则` 可选）。
- **D-07 续（(d) 范围匹配，裁决）**：草案 7.4 第 8 条说第一版只做精确值匹配，范围匹配（`是 0 到 17`、`是 60 及以上`）是“未来可扩展”。**裁决：第一版不进范围匹配**，`假如` 分支内出现 `到`/`及以上` 即报错“范围匹配尚未实现，请用 `如果…否则如果` 改写”（注意：`到` 在本设计里不是关键字；`假如` 分支内出现 `到` 即按本条报错，与循环无关——范围循环形态已撤销，见 §2.8）。触发条件（§5）：出现两个以上真实程序用 `如果` 链写范围判断且抱怨可读性时，在 S4 后立项范围匹配（形态仍用 `是 下限 到 上限` 与 `是 下限 及以上`，闭区间，上下限各求值一次，类型须为整数）；此决定与旧线无关。
- 多值匹配采纳：`是 6，7`（草案原文全角写法；按 D-06 归一化后与 `是 6, 7` 等价，两者皆可）；多值中重复值编译期报错；`是` 分支的值须为编译期常量（沿用现有 `switch case` 规则：整数常量、须适配被匹配表达式的类型、重复即错）；被匹配表达式第一版只支持整数与枚举类型（字符串匹配暂缓，触发条件见 §5）。

## §2.8 循环（草案第 8 章）——采纳，带四处裁决

- **条件循环** `循环 (条件)` / `结束 循环`（英文 `while (条件) { … }`）：采纳；语义 = `while`；条件遵循 §2.7 真值规则；中文形态条件可带括号或不带（`循环 年龄 < 18` 与 `循环 (年龄 < 18)` 等价，括号只起分组作用）；`退出循环`/`跳过循环` 支持标签（`标号: 循环 … 结束 循环`，标签写在结构关键字前，沿用现有标签规则）。
- **计次循环** `计次循环 ([计次变量 = ]起始值，终止值[，步长])` / `结束 计次循环`（英文 `for (变量 = 起始, 终止[, 步长])`）：采纳；**闭区间**；起始值、终止值、步长各求值一次；默认步长 1。**半开区间形态不做**：须半开区间时请用条件循环或计次循环 + 条件 `退出循环` 改写（v0.1 §8.2 要求提供半开区间形式，该要求随范围循环形态一并撤销，见 §5.4）。
  - **(f) 步长为 0**：常量 0 → **编译期拒绝**；非常量 0 → **运行时 trap**（`BRK #1`，沿用现有数组越界的 trap 形态，诊断信息由运行时日志给出，编译器在循环入口插入 `步长 == 0` 检查——该检查是否插入由编译选项控制，默认插入，`--no-count-check` 可关闭，关闭后步长为 0 是未定义行为，文档写明）。
  - **反向**：步长 < 0 时要求起始 > 终止，否则循环零次（不报错）；步长 > 0 时要求起始 < 终止，否则零次；起始 == 终止时执行一次（闭区间）；步长符号与方向矛盾（如起始 < 终止且步长 < 0）时零次，不报错——“方向由步长符号决定，区间端点只决定是否进入”是本设计的单规则，诊断不再猜用户意图。
  - **计次变量**：循环局部变量，类型按起始值/终止值/步长的**共同类型**推导（三者类型不一致时报错，不做隐式统一）；**不可改**：循环体内对计次变量的赋值、`++`/`--`、取址 `&次数` 一律语义期拒绝（检查点：赋值语句目标检查 + `++`/`--` 目标检查 + 取址检查三处，缺一不可）；计次变量在循环体外不可见，出循环后同名变量是另一变量（遮蔽规则沿用现有作用域规则）。若省略计次变量，循环仍然按照起始值、终止值和步长执行，但循环体无法直接访问计次值。
- **遍历循环** `遍历循环 (变量1[，变量2] -> 可遍历对象)` / `结束 遍历循环`（英文 `foreach 变量 in 对象` / `foreach 索引, 变量 in 对象`）：采纳形态，**收窄支持范围**：第一版只支持**数组**与**字符串**（字符串遍历出 `字符`，即字节，见 §2.3 D-08）；字典、集合、元组、自定义可遍历对象**暂缓**（触发条件见 §5：字典/集合运行时落地后）。理由：草案 8.3 建议支持的六类里，字典/集合/元组在现有编译器里**没有**对应的运行时类型，支持遍历等于先造容器；数组与字符串已有表示（数组 `T[N]`、字符串 `ptr` + 长度约定），遍历可直接 lowering 为下标循环（见 §3.4）。多变量绑定：数组/字符串只支持 1 个或 2 个绑定（2 个时第一个是 `整数` 索引、第二个是元素）；绑定数不匹配时语义期报错；遍历变量由编译器创建、类型按被遍历对象推导、循环体内不可改（同计次变量规则，取址亦拒绝）。
- **枚举循环** `枚举循环 (字段 -> 对象)` / `结束 枚举循环`：**超出 v0.1 的扩展，保留**（v0.1 无枚举循环，本设计按草案 8.4 保留，见 D-10）；只枚举公开字段（见 D-12）。
- **`循环` 与 `当`/`做` 的去留（双语拍板后定案）**：`while` 的中文拼写**只有 `循环`**，`当` **不用**——理由：双语下一词一义，`当` 与 `循环` 若同时指 `while`，同一 Token 就有了两个中文拼写，诊断与文档须处处写“`循环` 或 `当`”，旧线 `当` 的唯一价值（照顾习惯 `当` 的用户）抵不过这笔混淆成本；`当` 不是关键字，作标识符合法，作关键字使用时报错并提示用 `循环`/`while`。`做`/`do`（do-while）**不做**：须先执行一次的循环请用 `循环 (真)` + 体内条件 `退出循环` 改写，行数代价 1 行；`做`/`do` 只保留拼写、出现即报错“do-while 尚未实现”（见 §1.1）。

## §2.9 类与对象（草案第 9 章）——采纳，带三处裁决

> **实现补记（2026-11-19，枚举循环元信息表）**：结构体与类引用均可作为枚举循环对象；对象地址在循环入口求值一次，继承字段按布局顺序处理，类对象只枚举公开字段，以免绕过 `@隐藏`、`@受限` 或 `@受限.类`。类对象表达式可来自变量、字段、数组元素及返回类引用的调用；结构体枚举循环仍要求可取址左值。编译器按结构体/类类型缓存只读 `.rodata` 表和紧凑名称串，每项存名称偏移、字段字节偏移与 Kind 编号；循环体根据表项构造 `字段信息`，不再生成逐字段比较分支链。该表是枚举循环专用元数据，不提供通用反射 API。

- **D-10（(e) `对象.字段` 魔法成员，裁决）**：草案 8.4 写 `枚举循环 (字段 -> 用户甲.字段)`，其中 `.字段` 不是真实字段，是“给我全部字段元信息”的魔法成员——它与普通字段访问 `用户甲.姓名` 共用 `.` 语法，若用户真有一个字段就叫 `字段`，两者无法区分。**裁决：删除 `.字段` 写法**。枚举循环形态改为 `枚举循环 (字段 -> 用户甲)`，箭头右侧直接是对象表达式，不加后缀。字段描述对象是编译器内置类型 `字段信息`（`结构`，三字段：`名称: 字符串`、`值: 指针`、`类型: 整数`——类型用 Kind 编号，编号表见 §3.4；`值` 是指向该字段存储的指针，读值须按 `类型` 解引用，文档给示例）。`字段` 不得再作普通字段名（保留字处置：`结构`/`类` 里声明名为 `字段` 的字段即报错，避免与枚举循环绑定变量名混淆——绑定变量名本身就叫 `字段` 是允许的，那是循环变量不是字段）。
- **D-11（(i) `初始化` 与构造器，修订）**：`初始化` 仍是普通方法名，没有特殊语义；既有两段式写法继续合法。新增 `@构造` / `@constructor` 标记类实例方法作为构造器，写 `@构造 方法 构造(参数…): 空` / `@constructor fn constructor(params…): void`，方法名由声明者选择。每类最多一个构造器，必须是实例方法且返回 `空` / `void`；构造器不能被当普通实例方法手动调用。`类名(参数…)` 分配对象、递归执行字段默认初始化后调用构造器；未声明构造器的类仍只接受 `类名()`。派生构造器可把 `父对象(参数…)` / `super(args)` 写作第一句，显式向直接父类传参；参数表达式使用当前构造器参数并在各级构造开始时求值，父构造仍按祖先到子类顺序执行，虚表随构造阶段切换。缺失必需的父构造调用、参数数量不符、无父类或非首句调用均编译报错。构造器沿用类成员可见性注解。`创建 类型` 关键字仍不用。析构：**不做自动析构**；对象释放一律显式（`释放(对象)` 库函数或 `free`，见 §2.11），离开作用域不自动调任何方法。
- **D-12（(l) 权限，修订）**：默认公开；类成员 `@隐藏` = 仅本类内；类成员 `@受限` = `protected`，本类及其子类可见；`@受限.类` 保留为 `@受限` 的同义拼写。顶层声明没有继承关系，顶层 `@受限` 限定为声明源文件可见。检查点：语义期字段访问与方法调用处各一处（共两处，缺一不可）；**枚举循环只能枚举公开字段**（非公开字段不进入 `字段信息` 表，避免绕过访问控制）。
- **D-16（冒号 `:` 统一为定义分隔符，裁决——2026-11-18 用户追加决定）**：用户原话：“":"需要同时作为类继承、类实现、类型定义的符号，如：类 A : B(B可以是任何类：接口类、父类这些)，变量 a : 整数，方法 b() : 整数”。**裁决：冒号 `:` 是统一的“定义分隔符”，三种用法按句法位置区分**：① 类型定义：`变量 a: 整数`、`方法 b(): 整数`、参数 `甲: 整数`、字段 `名称: 字符串`、结构字段 `字段: 类型`（本就已有，本次确认并收进统一规则，不是新发明）；② 类继承：`类 A : B`，B 为普通类；③ 类实现：`类 A : B`，B 为接口类。继承与实现用同一形态，区分靠 B 的声明种类（普通类还是接口类），不靠第二关键字。**与 `空` 三用同一立法思路**（D-03）：位置本身就是区分信息，一个符号多用不构成歧义；旧版“不用冒号，冒号已有类型标注含义”的决定**本次废止**——类型标注的冒号在声明体内（`名: 类型`）、类头的冒号在声明头（`类名 : 基名`），解析器按位置区分，不冲突。
  - **接口类形态（S4）**：`接口类 名 [: 父接口]` 换行 { 方法签名 } `结束 接口类`（英文 `interface class Name [: Base] { … }`，两词序列整体识别）。体内**只允许方法签名行**：`方法 名(参数: 类型, …)[: 返回类型]`，返回类型省略时归一为 `空`；英文对应 `fn name(parameters)[: return_type];`，省略时归一为 `void`。接口签名无方法体、无 `结束 方法`（签名行以换行或分号终结，见 §2.5；解析器在接口类体内把 `方法` 行直接读作签名，不期待方法体，接口类体内出现 `结束 方法` 即报错）；字段、常量、嵌套类、`本对象`/`父对象`、权限注解一律拒绝（接口方法默认公开，写 `@隐藏`/`@受限`/`@受限.类` 即报错；接口类声明本身顶层的 `@隐藏` 不导出按 §2.12 通用规则处理）。接口只允许单继承，父接口须先声明；子接口继承父接口的全部方法签名，不能重复声明同名方法。接口类只以 `指针<接口名>` 出现（与 `类` 同规则）；接口类无字段、无构造、无对象创建表达式（`接口名()` 出现即报错——接口不能实例化）。
  - **实现规则**：`类 A : B` 中 B 为接口类时，A 须实现 B 的**全部**方法签名：方法名、参数个数与类型、返回类型须逐项相同（参数名可不同，按位置与类型匹配）；缺一即报错（诊断 A-33），签名不符（参数类型/个数、返回类型不同）即报错；A 多写的方法是 A 自己的方法，不报错。
  - **单基（v1）**：类仍只允许单个 B：`类 A : B, C`（多父类、多接口实现、父类+接口并列）一律拒绝（诊断 A-34）；接口也只允许单个父接口。类实现子接口时自动满足其继承的父接口契约，但类本身仍只有一个直接基类型。
  - **B 的种类检查**：`类 A : B` 中 B 须为已声明的普通类或接口类；B 为 `结构`/`枚举`/`联合`、类型别名、未声明名时报错（诊断 A-33）；B 与 A 同名（自继承）即报错。
  - **`父对象`（SuperKw）**：仅在有父类的子类方法体内合法，指父类部分；仅实现接口（无父类）的类的方法体内出现 `父对象` 即报错“本类无父类”（见 §1.1 `父对象` 行）。
  - **冒号其余出现处扫查（本次同步完成）**：除定义分隔符三类外，冒号还有三处出现，均按句法位置区分，不构成第四种定义含义——① 三元运算符 `? :`（`条件 ? 值1 : 值2`）：表达式内条件运算符，冒号只出现在 `?` 之后、表达式内部，沿用现有 Aster 形态，不改；② 标签冒号 `标号: 循环`（§2.8）：语句首位置的标签定义冒号，后跟结构关键字，与声明位置的定义分隔符位置不同，沿用现有标签规则，不改；③ 语言模式声明 `// aster:language=zh|en`：注释指令内的冒号，不是代码 Token，词法器读注释时不分词（见 §3.1）。D-07 规则表里“`假如…是` 分支头、参数冒号除外”的旧括号已删除：`假如…是` 分支头后不跟冒号（见 §2.7），行尾冒号一律续行。
  - **英文形态**：`class A : B`（继承或实现，靠 B 的种类区分）；`interface class I { … }`（方法签名 `fn name(params): Type`，见 §3.2）；`let a: i32`、`fn b(): i32`（类型定义冒号与中文一一对应）。
- **类语义（当前实现）**：类只以 `指针<类名>` 出现（值形态的类变量声明即报错）；实例对象布局按 AAPCS64 对齐，根类首字段为隐藏虚表指针，子类保持父类实例字段与虚表槽位前缀；静态字段使用独立共享存储，不进入对象布局。单继承：`类 子类 : 父类`，`父对象` 在子类方法体内指父类部分。实例方法运行时分派，子类实现须以 `@重写` 显式声明并通过精确签名校验，静态方法与构造器不参与重写；`父对象/super.方法(…)` 直接调用父类实现。类实现接口：`类 A : B`，B 为接口类时 A 须实现 B 的全部方法签名（见 D-16）；第一版只允许单个 B（`类 A : B, C` 拒绝）。继承、接口和类方法动态分派已接入 S4。

## §2.10 注解与导入（草案第 10 章）——采纳，带两处裁决

- **D-13（(j) `@受限.类` 的点号注解，裁决）**：`@受限.类` 若按通用表达式解析，`.` 会被读作字段访问。**裁决：注解名整体匹配**。词法器/解析器在 `@` 后按最长匹配识别注解名，`受限.类` 是一个注解名（含点号），不是 `受限` + `.` + `类`；它与类成员 `@受限` / 英文 `@protected` 同义。英文类成员注解使用 `@private`、`@protected`、`@static`；顶层文件私有注解也写作 `@private`，按声明位置区分。注解名表是封闭表，不在表里的 `@xxx` 一律报错“未知注解”。注解参数只允许字符串字面量或整数 literal（`@导入("数学")`、`@对齐(16)`），不允许表达式。`@静态` 修饰类变量字段或类方法，不可用于顶层声明及接口方法。
- **注解作用范围**：只修饰紧随其后的**一个**声明（采纳草案 10.4）；多注解可叠加，但冲突检测在语义期做：`@隐藏` + `@受限` 同现、`@隐藏` + `@受限.类` 同现、`@受限` + `@受限.类` 同现一律报错（权限只能取其一）；`@导入` 与权限注解同现报错（导入不是声明修饰，是文件级指令）；注解与被修饰声明之间不得插入空行以外的任何 Token（注释允许，空行允许——空行不切断修饰关系，写明）。
- `@静态`：可修饰类变量字段与类方法。静态字段不进入实例布局；标量、字符串、单个函数指针字段和单个结构体字段通过 `类名.字段` 访问，结构体字段支持结构体字面量初值、默认值及嵌套字段读写，函数指针字段可直接以 `类名.字段(…)` 调用；固定长度一维标量、字符串、结构体和函数指针数组通过 `类名.字段[下标]` 访问，字符串数组默认填充空串，结构体数组元素支持嵌套字段读写，函数指针数组元素按完整签名检查，不能通过对象读写。数组初值须是长度匹配的字面量数组。静态方法没有隐藏接收者，通过 `类名.方法(…)` 调用，不能通过对象调用，也不能使用 `本对象/this` 或 `父对象/super`。接口方法仍是公开实例方法，不接受 `@静态`。
- `@导入("模块名")`：文件顶级指令，模块名是字符串；别名写作 `@导入("数学").别名("数学库")`，调用时 `数学库.平方根(16)`。`@导入` 与 `导入` 的分工：`导入 "文件.ast"` = 文件级声明共享（沿用现有 `include` 语义，即 v0.1 §4/§9 的 `导入`/`include`，旧稿的 `包含` 已废除、统一为 `导入`）；`@导入("模块")` = 逻辑模块依赖（模块名 → 源码包名索引 → 依赖分析 → 符号导入 → 循环依赖检测，见 §3.5），是**超出 v0.1 的扩展**（v0.1 只有文件级 `导入`，无模块注解；v0.1 §18 把“模块导出、可见性和循环依赖”列为待定，本设计的 `@导入` + 权限注解即对此待定项的定案，见 §5.4）。两者不得互相替代：`导入` 不能导入模块符号表，`@导入` 不能导入任意文件。
- 注解扩展（草案 10.5 的 `@弃用/@内联/@编译期/@对齐/@布局`）：**全部暂缓**到后续阶段，触发条件见 §5；当前类成员支持 `@隐藏/@受限/@受限.类/@静态`，模块注解 `@导入` 已按 §3.5 接入。

## §2.11 表达式与成员访问（草案第 11 章）——采纳

- 表达式分类采纳；成员访问 `.`、嵌套访问、方法调用采纳；`本对象.字段`、`本对象.方法(…)` 在方法体内合法，方法体外出现 `本对象` 即报错。
- 补充（草案未写）：`本对象` 的类型是 `指针<当前类>`，不是值；`本对象` 不可再取址（`&本对象` 拒绝）；`本对象` 不可赋值（`本对象 = …` 拒绝）。

## §2.12 模块与编译组织（草案第 12 章）——修改

- 模块 = 逻辑单元，可由多个源文件组成；文件 = 编译单元。每个属于模块的源码文件以 `包名 标准库.数学 = standard.math`（英文 `package 标准库.数学 = standard.math;`）声明规范包名及可选别名；这是首个非注释声明，同一包的源码文件须声明相同名称和别名，并可位于同一搜索根下任意子目录。包名是精确的 Unicode 名称，不按文件语言自动翻译；中英文包名通过源码头部显式别名映射到同一规范名，因此 `@导入("标准库.数学")` 与 `@import("standard.math")` 可导入同一包，无需模块描述文件。当前搜索路径为调用文件目录 → `--模块目录` 指定的目录 → 项目文件所在目录，标准库源码目录暂由 `--模块目录` 显式加入；重复导入去重（同一模块导入多次只处理一次）；循环依赖在模块依赖分析期报错（须给出环上的模块名链）。
- **修改**：草案 12.1 要求编译器负责的 7 项（名称解析、搜索路径、依赖分析、符号导入、重复导入、循环依赖、编译顺序）里，前 6 项第一版（S4 阶段）实现，**编译顺序管理改为“拓扑序由编译器算出、但多文件编译仍由调用者按该顺序逐个调用编译器”**——即第一版不提供“一键编整个模块”的驱动命令，`aster build` 的多文件编排沿用现有 `aster.proj` + `导入` 机制；模块驱动命令是 S4 后的扩展，不在本设计第一版承诺内。写明此收窄，避免把“模块系统”等同于“构建系统”。
- **跨语言模块（v0.1 §13）**：同一项目允许中英文文件共存、互相调用：中文文件 `方法 求和(甲: 整数, 乙: 整数): 整数 … 结束 方法` 可被英文文件 `include "math.ast"` 后以 `求和(10, 20)` 调用，反之亦然。跨语言调用的符号规则：源标识符（中文名）与 ABI 符号分离——符号表按 §3.6 的重整规则（`__aster_cn_<hex>`）编码，DWARF 保留源原名；**不得**把中文标识符翻译成英文后作为唯一符号名。导出与可见性：类成员默认公开（见 D-12），`@隐藏`/`@受限`/`@受限.类` 管成员可见性；模块级导出第一版即“文件内顶层声明全部导出，`@隐藏` 的顶层声明不导出”。外部声明支持双语等价形态：中文 `外部("puts") 方法 输出(内容: 指针): 整数` / `外部("native_counter") 变量 计数: 整数`，英文 `extern fn puts(content: ptr): i32;` / `extern let native_counter: i32;`；中文映射字符串必须非空且只含 ASCII，外部全局不能带初值，源代码方法或变量名可本地化，参数布局、返回值和调用约定不得因语言模式而改变（v0.1 §13.2）。

## §2.14 闭包与匿名方法（2026-11-18 用户拍板纳入，S4 实现）

草案第 15 章把闭包列为后续设计，上一版设计据此“明确不做”；用户拍板不接受，**本修订将闭包正式纳入设计**，机制借鉴旧线闭包轮的独立胖指针思路，但为本设计独立重决（旧线结论不作权威，见 §4 第 13 条）。

### 语法形态（与 `结束 结构名`、双语体系自洽）

- **匿名方法就是没有名字的 `方法`/`fn`**，不另设关键字：`方法 [捕获列表] (参数: 类型, …): 返回类型` + 语句 + `结束 方法`；英文形态 `fn [captures] (params) … }`（闭合按文件模式单轨：中文文件用 `结束 方法`，英文文件用 `}`，见 §3.2）。无捕获列表时方括号可省（`方法 (甲: 整数): 整数 … 结束 方法` 即零捕获匿名方法）。捕获列表写在关键字与参数表之间，只列被捕获的局部变量名与参数名，逗号分隔（全角 `，` 亦可，归一化后等价）。
- **示例 1——按钮回调式**（AsterUI 的 `(fn, ctx)` 登记点接闭包，见互操作）：
```
方法 主函数(): 整数
    变量 计数器甲 = 计数器()
    计数器甲.初始化()
    aui_button(5, "+", 方法 [计数器甲] (用户: 指针): 整数
        计数器甲.增加(1)
        返回 0
    结束 方法, 用户)
    返回 0
结束 方法
```
  其中 `计数器甲` 是指针捕获（拷贝指针值本身，不是拷贝对象），`用户` 是登记点的 `user: 指针` 实参，与捕获列表无关。
- **示例 2——局部变量捕获式**：
```
方法 主函数(): 整数
    变量 步长 = 2
    变量 加步长 = 方法 [步长] (甲: 整数): 整数
        返回 甲 + 步长
    结束 方法
    输出(加步长(10))
    返回 0
结束 方法
```
  `加步长(10)` 得 12；`步长` 在创建时按值快照进 env，此后 `步长 = 3` 不影响已创建的闭包（见捕获语义）。

### 捕获语义（按值快照优先）

- **只支持按值捕获**：创建闭包时把捕获列表里的每个变量**按值拷贝**进编译器生成的 env 结构；env 在 arena 上分配、**永不释放**、上限 **256 字节**（超限时编译期拒绝并报出超限的捕获变量与字节数）。选 arena 永不释放的理由：Aster 无 GC、无引用计数，env 若要求显式释放则每个闭包都要配释放点，回调场景下释放点不可判定（框架持有闭包的时间长于创建作用域）；arena 的代价是闭包 env 内存只增不减，文档写明上限与“创建大量闭包会耗尽 arena”的后果，`aui_delay` 式的一次性回调与按钮回调的创建频率均在此预算内（以计数器级应用实测为准，见 §7）。
- **捕获的是值，不是变量**：闭包体内改写捕获的标量（如 `步长 = 步长 + 1`）只改 env 里的拷贝，不影响创建作用域的原变量；捕获指针时拷贝指针值，体内通过指针改写指针对象是可见的（与普通指针赋值同一语义）；捕获 `本对象` 时拷贝对象指针（见示例 1）。**按引用捕获不做**：捕获列表里写 `&变量` 即报错“闭包只支持按值捕获”；闭包体内对捕获变量取址（`&步长`）亦拒绝——取址得到的是 env 拷贝的地址，语义上极易误读，宁可拒绝。
- **捕获范围**：只能捕获创建点可见的局部变量、参数与 `本对象`；全局变量不进捕获列表（直接访问）；捕获不存在的变量、捕获 `常量` 以外已移出作用域的变量，均在语义期拒绝。

### 类型形态与 ABI（独立胖指针，普通 fn 不动）

- **闭包是独立胖指针类型**：类型写法 `闭包(参数类型, …): 返回类型` / 英文 `closure(P): R`，表示为 16 字节 `{code: 指针, env: 指针}`（`Ty` 新增 Kind `Closure`，签名由语义期登记的签名表索引携带；`Ty` 是 `(kind, index)` 对，签名索引即此处的 index，与泛型无关）。**普通 `fn` 保持瘦身 8 字节、C 兼容、AAPCS64 不变**：闭包类型与 `fn` 类型互不相同，`闭包(整数): 整数` 的值不得直接传给要求 `fn(整数): 整数` 的参数（须经 adapter，见下）；零捕获闭包**不**自动退化为普通 `fn`（第一版无此优化，退化规则若将来做须另立设计——自动退化会让“同一表达式有时是闭包、有时是 fn”的类型判定依赖捕获分析，诊断与 DWARF 都会变复杂）。
- **调用约定**：闭包值调用时编译器生成隐藏首参 `env`：`code(env, 实参…)`，`env` 经 `x0` 传递（AAPCS64 首参寄存器，与普通函数首参同规则）；闭包体内的捕获变量从 `env` 偏移取。闭包字面量在创建点生成 env 填充代码（逐个捕获变量拷贝进 arena 槽）+ `{code, env}` 对。
- **与 `(fn, ctx)` 对的互操作（thunk/adapter）**：框架登记点仍是 `fn(指针): R, 用户: 指针` / `fn(ptr): R, user: ptr` 形态时，编译器在传入闭包的调用点生成一个静态 thunk，并为这次注册分配独立的上下文结构，保存闭包 `{code, env}` 与原始用户指针；登记点收到的 `(thunk, 上下文指针)` 对保留原有用户上下文，框架侧零改动。thunk 从上下文读取 `code`、`env` 和 `user`，再调用 `code(env, user)`。适配器支持直接函数调用、类实例/静态方法调用、结构字段和定长数组元素中的闭包值，也能在局部初始化、赋值、返回值、`if/如果` 条件、`while/循环` 条件、计次循环三项、匹配主题及嵌套表达式中使用；生成的上下文由标准库 `alloc` 分配，永不自动释放，分配失败时返回对应返回类型的零值。一次性位置按源码顺序求值，循环条件在每轮开始时重新准备上下文。结构体返回值的适配器仍暂不支持；返回 `void` 的适配器不能嵌入需要值的表达式。普通函数指针不会生成 adapter。框架若直接提供闭包形态的登记 API（参数类型即 `闭包(指针): 空`），则不经过该适配器。

### 自举子集处置（stage 拒绝，复用 §3.7 模式）

- 闭包**不进自举子集**：stage 遇到匿名方法、`闭包`/`closure` 类型、捕获列表方括号在表达式位置时，干净拒绝（错误信息须写明“闭包不在自举子集中，请用宿主编译器”），`bootstrap-loop` 加拒绝测试（中文最小闭包例进 stage 应拒绝、进宿主应通过）。stage 拒绝的代价与中文语法相同（见 §3.7），不另立代价。

### 验收（S4，见 §5.1）

- 新套件 `cn-closure-checks.sh`：正向（零捕获/单捕获/多捕获/指针捕获/作回调参数/作返回值——返回值场景 env 生命周期按 arena 规则）；反向（env 超 256 字节拒绝、按引用捕获 `&x` 拒绝、捕获变量取址拒绝、闭包值传给 `fn` 参数无 adapter 时拒绝、stage 拒绝）。difftest 全绿（闭包的 C 对照是“函数指针 + env 结构 + thunk”三件套，须在 difftest 里写明对照形态，不得用 C 闭包扩展冒充）。

## §2.15 双语标准库与双语诊断（v0.1 §14/§15）

### 标准库：统一实现、双语接口

- **一套实现、两套语言入口、统一底层语义**：标准库函数只实现一次，中文与英文各一套入口名，调用同一底层实现。示例（v0.1 §14）：`字符串.长度()` / `string.length()`、`字符串.查找()` / `string.find()`、`字符串.替换()` / `string.replace()`。中文入口与英文入口是**同一函数的两个名字**，不是两个函数：符号表里同一函数登记两个拼写（中文名按 §3.6 重整，英文名恒等），DWARF 与文档同时列出两个名字。
- **命名规则**：中文入口名用中文动词 + 中文类型名前缀（`字符串.长度`、`数组.追加`）；英文入口名用既有英文名（`string.length`、`vec_push` 之类沿用现有命名，不得为双语化重命名已有英文 API——重命名会断 C ABI 与现有调用点）。新 API 立项时须同时定中英两个名字，缺一个不得合入。
- **程序入口也按源语言命名**：中文程序使用 `启动方法`，英文程序使用 `main`；中文模式把 `启动方法` 归一化到同一 AST 入口名和后端 ABI，拒绝把 `main` 当中文入口。当前没有入口类机制；若未来引入，中文入口类命名为 `启动类`，英文入口类命名另行定案。
- **ABI 稳定**：双语入口不得改变底层函数的 ABI（参数布局、返回值、调用约定）；中文入口只是名字层面的映射，不得另包一层运行时。标准库中文包装的旧收窄（“只包装常用 20 个函数以内”）**废止**：改为“常用 API 须双语齐全，清单由 S6 实现轮按使用频率定，冷门 API 可暂缓中文入口但须在文档里标明‘暂无中文名’”。
- **错误处理、内存所有权、线程安全**：双语入口共享同一套规则（返回码 + 错误值模式，无异常，见 §5.3；`字符串` 拥有语义见 D-08；线程安全随异步设计暂缓，见 §5.4）。双语文档：每个 API 的文档须中英双语，中文文档不得是英文文档的机翻——由实现轮双语撰写，S6 验收时抽查。

### 诊断：错误代码与显示文本分离

- **同一错误同一代码**：每个诊断有稳定错误代码（`DiagnosticCode`）与显示文本分离；中文文件按中文模式显示中文消息，英文文件按英文模式显示英文消息，代码相同。示例（v0.1 §15 的形态，现按 A 制）：`错误 [A-099]：变量「年龄」未定义 / 位置：main.ast:8:5` 与 `error [A-099]: undefined variable 'age' / location: main.ast:8:5` 是同一诊断。诊断语言按**文件模式**选（不是按编译器全局语言设置），跨语言项目里中英文文件的诊断可同时出现两种语言的文本，代码相同即可关联。
- **代码分段（本设计定案，已实现为 A 制）**：诊断代码采用 `[A-NNN]` 制（见文首“双语诊断增量”与 `src/cn_diagnostics.hpp` 的 `classifyDiagnostic`）：A-001–A-003 词法（含 UTF-8 非法、不支持字符、语言模式配置），A-010–A-011 解析（含代码块结构不匹配、语法位置），A-020–A-021 包/模块与注解，A-030 重复声明，A-040 访问权限，A-050 类型检查，A-060 暂未支持语法，A-099 兜底（未归入以上类别的双语前端错误）。本稿初版所写的 E1000–E5999 分段（E1000–E1999 词法、E2000–E2999 解析、E3000–E3999 语义、E4000–E4999 类型、E5000–E5999 代码生成与链接）**已被 A 制取代，不再使用**：实现输出中不存在 `E1001` 这类编号，工具与测试须匹配 `[A-NNN]`。附录 A 的每条诊断（编号 A-01…A-35 为条目号，不是错误码）在 S6 按 A 制落实错误码，S6 验收门要求附录 A 全数带码。

- **现状**：当前编译器是单文件 `src/aster.cpp`（主树 17,091 行，见 §0.1），词法、解析、语义、代码生成、DWARF 全在一文件里，无 HIR/MIR，无模块划分。v0.1 §12 的模块划分（Driver/Source/Frontend/AST/Semantic/IR/Optimization/Backend/Diagnostics/Tools）是**逻辑架构**，不是第一阶段的拆分任务——**第一阶段不要求立即拆分全部源码文件**（v0.1 §12.1 原话）。拆分按 S2–S5 的阶段边界逐步做：S2 先抽 Lexer（含 Unicode 与双语注册表），S3 抽双 Parser，S4 抽统一语义，S5 立 HIR/MIR；每抽一层须保持既有测试全绿，拆分本身不得改变任何产物哈希（基线 393 行零变化，见 §5）。
- **双 Lexer/Parser 的分工**：中文 Lexer 与 English Lexer 各一（共享 UTF-8 解码器与 Token 结构，关键字注册表按文件模式加载，见 §3.1）；中文 Parser 与 English Parser 各一（共享 AST 节点构造器，见 §3.2）。两个 Parser 不得各自实现类型检查或代码生成（v0.1 §12.3），语义与代码生成只在统一层实现一次。
- **HIR 与 MIR 各消除什么**：AST → HIR 消除三类表面差异——① 中英文关键字差异（`方法`/`fn` 已是同一 Token，HIR 只留 Token）；② 中英文类型别名差异（`整数`/`i32` 已是同一 Ty，HIR 只留 Ty）；③ 不同表面语法结构的差异（`计次循环 (…)` 在 HIR 里是 CountLoop 节点；`遍历循环 (变量 -> 对象)` 在 HIR 里是 Foreach 节点；中文 `结束` 与英文 `}` 在 HIR 里都不存在——块结构只剩节点嵌套）。HIR → MIR 消除高级结构：高级控制流（`假如` 比较链、`遍历循环` 下标循环、`枚举循环` 元信息表查表）全部 lowering 为基本块、跳转、调用、内存访问、算术、类型转换、返回指令（v0.1 §12.6）；优化器只针对 MIR 实现一次。**过渡形态**：HIR/MIR 落地前（S2–S4），AST 直接 lowering 到现有 AArch64 后端（即本稿 §3.4 的 lowering 表，AST 节点直出代码）；S5 立 HIR/MIR 时把 §3.4 的 lowering 表逐行搬到 HIR→MIR，AST→HIR 只做结构归一，不做机器 lowering——搬移期间新旧两条 lowering 路径不得并存超过一个阶段（S5 结束时 AST 直出路径删除，删除前须 difftest 全绿）。
- **后端不知道语言模式**：AArch64 后端、ELF 写出器、DWARF 写出器只读 MIR，不得读源码语言模式；模式信息在 AST→HIR 时已消除，后端若需区分中英文即架构错误（v0.1 §12.7）。

## §3.1 词法（Lexer）

- **UTF-8 解码**：源码按 UTF-8 解码为码点流；非法首字节（`0x80–0xBF` 孤续接、`0xC0–0xC1`、`0xF5–0xFF`）与截断序列一律拒绝，报错位置按字节偏移换算的行/列给出。**不做一般 Unicode 归一化**（简繁、组合字符不归一，源拼写即身份）；唯一的归一化例外是 D-06 的三处全角标点（见上条）。
- **标识符字符集**：首字符 = ASCII 字母/`_` 或 CJK 统一表意文字区（U+4E00–U+9FFF，起步范围；扩展区、假名、谚文第一版拒绝，报错提示范围）；后续字符 = 首字符集 + ASCII 数字。标识符按码点计列（列号 = 码点数，不是字节数），字符串/注释内中文按字节计列的回退规则不沿用——统一按码点计列，诊断位置全文一致。
- **语言模式确定（v0.1 §2，新增；2026-11-18 纠正：默认改为 `zh`）**：Lexer 入口先确定本文件模式，优先级：命令行显式强制 > 文件首行附近的 `// aster:language=zh|en` 声明 > `aster.proj` 的 `[language] default`（可加 `allowed` 限制）> 编译器默认 `zh`。项目强制模式与文件声明冲突时报错（诊断 A-31，代码 E1000 段）；`allowed` 不含本文件模式时报错。**禁止按字符自动猜模式**：文件里出现中文字符不等于中文模式、出现英文不等于英文模式；无声明时继承项目配置，无项目配置时默认 `zh`。**后果（诚实写出）**：默认 `zh` 后，无声明的现有英文 Aster 源码不再能直接按默认编译，须补文件声明 `// aster:language=en` 或在 aster.proj 里设 `[language] default = "en"`；现有英文测试须以显式 en 配置通过（见 §5.1 S2 验收门）。模式确定后 Lexer 加载该模式的关键字注册表（见下条）；另一模式的结构性关键字在本文件里**不是关键字**（如中文文件里的 `if`、英文文件里的 `如果`，作标识符合法，作结构关键字使用时解析器报错并提示用本模式拼写，诊断 A-27）。
- **关键字识别**：上下文无关的拼写→Token 映射，按**本文件模式**的注册表查表，中英两拼写共享同一 Token，用最长匹配（trie 或排序表）：`否则如果`/`else if` 优先于 `否则`/`else`，`枚举循环` 优先于 `枚举`，`计次循环`/`遍历循环`/`枚举循环` 各为整体，`不小于`/`不大于`/`不等于` 各为整体，`受限.类` 只在 `@` 后识别；`接口类`/`interface class` 各为整体（`interface class` 为两词序列，整体识别为 InterfaceClassKw，不得拆成 `interface` + `class`）。`循环` 只对应 WhileLoop（条件循环），不分流（v0.1 合并时引入的 D-15 解析层分流已撤销，见 §2.8）。本模式关键字一律保留字，不得作标识符（中文文件 `变量 如果: 整数`、英文文件 `let if: i32` 均拒绝）；`当`/`默认`/`default`/`函数`/`包含`/`无`/`非`/`跳出`/`继续`/`重复`/`从`/`中的`/`同时`/`次`/`计数为`/`遍历`/`于`/`继承`/`inherit`/`接口`/`interface`/`实现`/`impl` 不是关键字，作标识符合法（见 §1.1 末段）。`else if` 按两词序列整体识别为 ElseIf。
- **全角标点归一化（D-06）**：词法器分词前先扫描源码：字符串字面量与注释内的内容原样保留，其余代码位置的 `，`（U+FF0C）、`：`（U+FF1A）、`、`（U+3001）归一化为 ASCII `,` / `:` 再分词。归一化是码点到码点，列号按码点计的规则不受影响。诊断文案引用源码片段时写归一化后的 ASCII 形态，并在位置后注明原文全角拼写（见 D-06 代价③）。
- **换行 Token**：词法器产生显式 `NL` Token（行尾换行），解析器按 §2.5 规则表消费；括号 `()`/`[]` 内部换行由词法器直接丢弃（括号深度计数器 > 0 时不产生 NL）；字符串内换行仍报错（沿用现有规则）。
- **注解词法**：`@` 后按最长匹配识别封闭注解名表；`@` 后无合法注解名即报错；注解参数只在 `()` 内读字符串/整数 literal。
- **注释**：`//` 单行；`/* … */` 多行不嵌套（见 §1.3）。
- **与现有词法器的关系**：现有词法器是 ASCII 门（`docs/language-reference.md` §1：字节 > 127 在注释外即报错），中文前端须在词法器入口处先解码 UTF-8 再分流——这是词法层最大的改动点，实现轮须先写词法探针（中文关键字/标识符/非法字节/列号各一），再动解析。

## §3.2 解析（Parser）——结构栈与新 AST 节点

- **结构栈（按文件模式单轨，v0.1 合并）**：解析器维护显式结构栈，每入一个结构压入 `{结构名, 打开行号}`；中文模式文件只接受 `结束 X` 闭合（`X` 须为中文结构名），英文模式文件只接受 `}` 闭合。中文文件里出现 `}`、英文文件里出现 `结束 X`，即报错（诊断 A-27，须写明本文件模式与正确的闭合形态）；**上一轮的“中文开块后误写 `}` 亦可接受”已废止**。比对失败 → 报错“`结束 X` 与打开的 `Y`（第 N 行）不匹配，应为 `结束 Y`”，并给出栈内全部未闭合结构（行号列表），不得只报第一个错就停（嵌套错配时一次报清是诊断质量要求）。
- **语句结束**：中文模式：解析器在每条语句后消费一个终结符：`NL` 或 `;` 二选一；终结符缺失（如下一行以标识符开头而上一行未终结）时报错“上一行语句未结束”，并提示“换行即语句结束，续行请把运算符留在行尾”。英文模式：沿用既有分号与换行规则（分号强制，换行只是空白），v0.1 §7.3。两种模式的语句结束规则不得互相借用。
- **新 AST 节点（统一 AST，模式无关——v0.1 §11）**（内部名继续用英文，中文只负责前端表达——沿用草案 13.5 的决定）：`VariableDeclaration`、`ConstantDeclaration`、`MethodDeclaration`、`ClassDeclaration`、`InterfaceClassDeclaration`（接口类声明）、`IfStatement`、`MatchStatement`（`假如`/`switch`）、`WhileLoopStatement`（条件循环）、`CountLoopStatement`（计次循环）、`ForEachLoopStatement`（遍历循环）、`EnumLoopStatement`（枚举循环）、`AnnotationDeclaration`、`ImportDeclaration`、`ClosureExpression`（闭包，§2.14）。中文 Parser 与英文 Parser 生成**同一类** AST 节点：中文 `如果` 与英文 `if` 都是 `IfStatement`，中文 `计次循环 (…)` 与英文 `for (…)` 都是 `CountLoopStatement`——**不得**有 `ChineseIfStmt` 或 `EnglishIfStmt`（v0.1 §11.3）。每种结构独立节点，**不得**全部 lowering 为普通语句后再由语义猜——`假如` 不得先转为 `switch` 再检查（`switch` 的 case 规则与 `假如` 的 `是` 规则不同：`假如` 支持多值、`否则` 可选、被匹配表达式求值一次；旧 Pascal `switch` 语义两者诊断不同）。
- **解析落点**：`方法`/`fn` 解析 = 现有 `fn` 解析改关键字与闭合（中文 `结束 方法` / 英文 `}` 按文件模式单轨）+ 可选的返回类型冒号部分（`方法 名(…): 类型` / `fn 名(…): 类型`；省略时归一为 `空` / `void`，统一不用 `->`）；匿名方法（闭包）解析 = `方法`/`fn` 后无名、直接跟可选捕获列表 `[…]` 与参数表，体后按文件模式闭合，生成 `ClosureExpression`；`类` 解析 = 新声明（成员表 + 方法表 + 权限表 + 可选的 `: 基名`，基名在语义期按种类分流为继承或实现，见 §2.9 D-16）；`接口类` 解析 = 新声明（方法签名表，可选单个 `: 父接口`，无字段、无方法体）；`结构` 声明头不得带 `: 基名`（值语义、无方法、无继承，出现即报错）；`假如` 解析 = 主表达式 + `是` 分支表 + 可选 `否则`；四种循环各一解析函数，不得共用一个解析函数靠形态分流（旧线否决方案的同类错误，本设计不再犯）。

## §3.3 语义（Sema）——检查点清单

| 检查 | 检查点 | 错误示例 |
|---|---|---|
| 默认初始化 | 每个无初值 `变量` 声明处插入默认初始化；含 `字符串` 字段的结构不得全零填充 | `变量 s: 字符串` 应得空串指针而非 0 指针 |
| 类型兼容 | 赋值、传参、返回、比较、二元运算各一处；`字符串` 与 `指针` 不得隐式互换 | `变量 p: 指针 = "张三"` 拒绝（须显式转换） |
| 方法解析 | `对象.方法名` 按对象类型查成员方法表；顶层调用查顶层方法表 | 无此方法时报近似名提示 |
| 返回检查 | 所有可能执行路径：有返回值方法须每路 `返回`（沿用现有检查）；无返回值方法带值 `返回` 拒绝 | `方法 f(): 整数` 末尾无 `返回` 拒绝 |
| 循环变量 | 计次/遍历变量的赋值、`++`/`--`、取址三处检查；作用域仅循环体内 | 循环体内 `次数 = 次数 + 1` 拒绝 |
| 计次参数 | 起始值/终止值/步长类型一致；常量步长 0 编译期拒；方向与步长符号 | `计次循环 (次数 = 1, 10, 0)` 拒绝 |
| 模式隔离 | 本文件结构性关键字须属本文件模式；另一模式的结构性关键字出现在结构位置时拒绝（诊断 A-27）；标识符/字符串/注释跨语言不检查 | 中文文件写 `if (…)` 拒绝；中文文件写 `变量 userName` 合法 |
| AST 对等 | 中英文同一语义生成同一类 AST 节点（S3 验收，见 §5）；不得有按模式分叉的节点种类 | 中文 `如果` 与英文 `if` 须同为 IfStatement |
| 遍历协议 | 被遍历对象类型只接受数组/字符串（第一版）；绑定数 1 或 2 | 遍历 `整数` 拒绝；绑定 3 个拒绝 |
| 枚举元信息 | 枚举对象须为 `结构`/`类`；只枚举公开字段；`字段信息` 表在语义期生成 | 枚举 `整数` 拒绝 |
| 权限检查 | 字段访问与方法调用各一处；跨文件 `@受限` 按编译单元文件判定；子类 `@受限.类` 按继承链判定 | 类外读 `@隐藏` 字段拒绝 |
| 类继承/实现 | `类 A : B` 的 B 种类分流（普通类=继承、接口类=实现）；B 须为已声明的类或接口类；单基（`类 A : B, C` 拒绝）；实现须覆盖接口的全部方法签名（方法名、参数个数与类型、返回类型逐项相同，参数名可不同） | `类 A : 结构名` 拒绝；实现接口缺方法拒绝；方法签名不符拒绝；多基拒绝 |
| 注解合法性 | 封闭注解名表；权限注解互斥；`@导入` 只在文件顶；注解只修饰一个声明 | `@隐藏 @受限 变量 x` 拒绝 |
| 模块依赖 | 模块名解析、搜索路径、循环依赖（环上模块名链） | A 导入 B、B 导入 A 拒绝并列出环 |
| 条件类型 | `如果`/`循环` 条件接受逻辑、数值及指针真值；`假如` 被匹配表达式须为整数/枚举 | 零/空指针为假，非零/非空指针为真；结构体条件拒绝 |
| 闭包捕获 | 捕获列表只含创建点可见的局部/参数/`本对象`；按值拷贝，env ≤ 256 字节；`&x` 捕获与捕获变量取址拒绝 | `方法 [&x] (…)` 拒绝；env 超限拒绝 |
| 闭包类型 | `闭包(P): R` 与 `fn(P): R` 是不同类型；闭包值可作为结构体字段或定长数组元素调用；传给 `fn` 参数须经 adapter（编译器在调用点生成 thunk） | 闭包值直接作 `fn` 实参拒绝（须显式 adapter） |

## §3.4 代码生成（Codegen）——lowering 表

| 新结构 | lowering 到现有 AArch64 后端 | 纯脱糖 / 新运行时 |
|---|---|---|
| `变量/常量`（默认初始化） | 无初值 → 插入默认初始化代码（标量清零、`字符串` 填空串符号地址、`结构` 逐字段初始化）；有初值 → 沿用现有 `let` 代码生成 | 纯脱糖（代码生成层面） |
| `方法`（顶层） | 沿用现有 `fn` 代码生成（AAPCS64 调用、寄存器分配不变） | 纯脱糖 |
| `方法`（成员） | 脱糖为顶层函数 `方法名(&对象, 实参)`；`本对象` 即首参 | 纯脱糖 |
| `如果/否则如果/否则` | 沿用现有 `if` 代码生成（条件分支 + 标签） | 纯脱糖 |
| `假如` | 主表达式求值一次 → 存入临时槽；每分支 `CMP + B.NE` 链（沿用现有 `switch` 的比较链形态，但不复用 `switch` 节点）；命中执行分支体后 `B → 结束`；无贯穿 | 纯脱糖（比较链，无新指令） |
| 条件循环 `循环` | 沿用现有 `while` 代码生成 | 纯脱糖 |
| 计次循环 | 脱糖为：求值起始值/终止值/步长各一次 → 存入隐藏局部槽 → `循环 (步长 > 0 ? 计次 <= 终止 : 计次 >= 终止)` 形态的 while + 体末 `计次 += 步长`；步长 0 检查插在循环入口 | 纯脱糖 + 一处运行时检查（步长 0 trap） |
| 遍历循环（数组） | 脱糖为下标循环：隐藏索引 `__i` 从 0 到 `len - 1`，元素 = `对象[__i]`；2 绑定时索引即第一绑定；`遍历循环 (变量 -> 对象)` | 纯脱糖 |
| 遍历循环（字符串） | 脱糖为字节下标循环：长度在循环入口 NUL 扫描一次并缓存进隐藏局部槽（S4 定案，见 §2.3 D-08）；元素类型 `字符` | 纯脱糖 + NUL 扫描（S4） |
| 闭包（§2.14） | 创建点：arena 分配 env（≤ 256 字节）+ 逐个捕获变量拷贝进 env + 生成 `{code, env}` 对；调用点：隐藏首参 `env` 经 x0 传递；传给 `(fn, ctx)` 登记点时为每次注册分配上下文并生成静态 thunk（`(thunk, context)` 对，ABI 与手写 `(fn, ctx)` 相同） | **新代码生成**：env 填充 + 上下文/thunk 生成；普通 `fn` 不动 |
| 字符串运行时（S4） | `字符串` 拼接（`+`）、相等比较（`==`/`!=`）、字典序比较（`<`/`<=`/`>`/`>=`）和转换（`字符串` ↔ `字符串视图`）lowering 为标准库函数调用（`__aster_cn_str_concat`/`__aster_cn_str_order`/`__aster_cn_str_view` 等，S4 实现，见 §5.1）；长度一律 NUL 扫描 | **新运行时**：标准库函数（S4） |
| 枚举循环 | 编译期为每个 `结构`/`类` 生成一张只读字段元信息表（rodata：每字段 `{名称指针, 偏移, 类型编号}`，只含公开字段）；循环体每次迭代取表项构造 `字段信息` 值（`名称` = 名字符串指针，`值` = `对象地址 + 偏移`，`类型` = 编号） | **新编译器生成数据**（rodata 元信息表，无新运行时） |
| `类`（字段+方法） | 布局沿用 `结构` 布局；方法脱糖见上；对象创建 `类名()` = 分配（调用者存储或 `alloc`，见 §2.11）+ 默认初始化 | 纯脱糖（S4 前无虚表） |
| `类`（继承，S4） | 父类字段前置布局，对象头含唯一隐藏虚表指针；`父对象` = 对象指针（同一地址，类型视图为父类） | 实例方法经虚表运行时分派 |
| `类`（实现接口，S4） | 无布局变化（接口无字段）；方法签名匹配是纯语义期检查（见 §3.3），实现方法仍按普通实例方法生成、经类虚表分派；接口引用调用经生成的适配 thunk 和方法表运行时分派 | 实例方法经虚表运行时分派；接口方法经方法表运行时分派 |
| `接口类`（S4） | **零布局**：接口类本身不产生对象布局；实现类为每个（祖先）接口生成一张方法表，接口引用调用经该表运行时分派；方法签名表只在语义期用 | 实现类按接口生成方法表（运行时分派） |
| 注解权限 | **零代码生成**：权限是纯编译期检查，产物中无权限位 | 无 |
| `@导入` | 编译期模块解析；符号导入后按普通符号代码生成 | 无新运行时 |
| `字符串` | 字面量沿用 `__aster_string_<n>` rodata 符号；`字符串` 变量即指针 | 沿用现有机制 |
| `字节`/`短整数`（新 Kind） | 窄整数加载：`LDRSB`/`LDRSH`（符号扩展）+ 存储截断（`STRB`/`STRH`）；复用现有 u8/u16 的零扩展路径加符号扩展分支 | **新代码生成分支**（四层：语义、代码生成、DWARF、difftest） |

**明确写出**：S2/S3 需要新运行时的部分是**零**——枚举循环的元信息表是编译器生成的只读数据，不是运行时；步长 0 检查是编译器插入的 trap，不是运行时库。**S4 新增两块运行时**：字符串运行时（标准库拼接/比较/转换函数）与闭包 env 的 arena（永不释放，上限 256 字节/闭包）；集合、字典的运行时仍在 S6（见 §5）。类在 S4 前仍是静态派发的语法糖，不需要堆管理升级——这是本设计与旧线 OO 评估“类/事件/async 要堆 + 调度器”的不同处，但闭包的 arena 已是第一块新增的堆形态，代价见 §6.1 第 4 条。**HIR/MIR 落地前**，本表是 AST 直出 lowering；S5 立 HIR/MIR 时本表逐行搬为 HIR→MIR lowering（见 §3.0 过渡形态），搬移期间 AST 直出路径在 S5 结束时删除。

## §3.5 模块与依赖（实现落点）

模块解析器独立于 `导入`：`@导入("模块名")` → 查模块表（已加载则去重）→ 按搜索路径扫描 `.ast` 文件的首个非注释声明 `包名`（英文 `package`），建立包名到源文件集合的索引 → 解析依赖、拓扑排序 → 循环依赖报错（环上模块名链）。源码文件本身声明包名，因此不需要额外的模块描述文件；语言模式由每个文件的语言标记或项目默认值决定。符号导入：模块的公开符号进入导入符号表；`@受限` 符号不跨编译单元文件（见 D-12）。跨语言模块的符号重整与 DWARF 原名见 §2.12 与 §3.6。

## §3.6 DWARF / 调试信息与 NameMangler（本设计独立重决）

- **重整规则（本设计重决，非沿用旧线权威）**：源标识符 `S`（UTF-8 字节串）→ 若 `S` 全 ASCII 且不以 `__aster_` 开头则恒等，否则 `__aster_cn_` + 整名 UTF-8 小写 hex。用户标识符不得以 `__aster_` 开头（保留前缀，违者报错）。`extern` 声明的名字含非 ASCII 时在声明处报错（C 库符号必须是 ASCII）。此规则与旧线 `CHINESE-DESIGN.md` §3 的机制相同，是本设计**独立重决**的结果（理由相同：整名 hex 无歧义、无计数器、跨对象链接稳定）；若旧线将来改其重整规则，本设计不跟随。
- **DWARF**：`DW_AT_name` 写源原名（UTF-8 原样）；地址类属性（`DW_AT_low_pc` 补丁位点、`DW_OP_addr`）用重整名；两者在写出器里分开携带，不得共用字符串变量。类名、字段名、方法名同此规则。`字段信息` 的 `类型` 编号表：`整数 1、长整数 2、字符串 3、逻辑型 4、指针 5、…`——完整编号表由实现轮按 Kind 表编定，本设计只定“编号由编译器在语义期分配、枚举循环读表时按编号解引用”的接口。
- **中文名在 `nm`/`objdump` 里显示为 `__aster_cn_<hex>` 是有意设计**（符号表是机器契约，DWARF 是人类界面），文档须明说，不得让用户以为是 bug。

## §3.7 自举子集处置（决定：stage 拒绝，冻结规格不动）

- **决定**：中文语法**不进自举子集**。stage 编译器（`bootstrap/aster.ast`）遇到任何中文关键字/中文标识符/`结束`/`换行终结`时，干净拒绝（错误信息须写明“中文语法不在自举子集中，请用宿主编译器”），不得静默误编。`bootstrap-loop` 加拒绝测试（中文最小例进 stage 应拒绝、进宿主应通过）。**闭包同样不进自举子集**（见 §2.14）：stage 遇到匿名方法、`闭包`/`closure` 类型、捕获列表时干净拒绝，`bootstrap-loop` 加拒绝测试。**新英文形态同样不进自举子集**：stage 遇到 `foreach`/`string` 类型、`null` 值字面量时亦干净拒绝（冻结的自举子集只有旧英文语法，新英文形态与中文语法同等对待）。
- **代价**：自举编译器不能编中文程序；中文程序的自举验证链断在 stage，须由宿主编译器 + difftest + 门禁覆盖；`bootstrap/aster.ast`（主树 7,672 行）与冻结规格（PARSER/SEMANTIC/CODEGEN 三份）**一律不动**，解冻重写是S6 后的可选决策，须用户另行拍板（见 §7）。学旧线闭包轮的拒绝模式，但此处是本设计的独立决定（理由：冻结规格解冻的成本高于中文进自举的收益，且中文程序不依赖自举链交付）。
- **未核实**：主树 `bootstrap/LEXER-SPEC.md` 是否已解冻（见 §0.1）——若主树 LEXER-SPEC 仍冻结，中文词法进 stage 的拒绝测试须落在 PARSER-SPEC 的拒绝路径上，实现轮核实后写进 §7。

# §5 分阶段实施路线（按 v0.1 §17 六阶段为骨架，旧稿 P1–P6 映射进新阶段）

v0.1 §17 的六阶段（规范冻结 → UTF-8 Lexer → 双语 Parser → 统一语义 → HIR/MIR → 双语生态）是本节骨架；旧稿的六阶段（P1 前端 → P2 控制流 → P3 类型/字符串运行时/闭包 → P4 类 → P5 注解模块 → P6 运行时/标准库）按映射表落进新阶段，**阶段编号改为 S1–S6**（旧 P 编号自此废止，下文出现旧 P 编号处一律以映射表为准）。每阶段结束时复评一次“下一阶段收益是否大于成本”，任何一阶段验收不通过或收益证伪，路线即停，不硬走到底。

## §5.2 行数验收口径（各阶段通用）

- 口径 A（唯一口径）：`wc -l` 数出的源码行数，规范写法与紧凑写法分开数；“省行” = 同功能逻辑的新设计行数 − 同功能逻辑的参照行数，参照须写明（英文 Aster 现状 / HuxerUI 对照 / 草案示例原行数三者选其一，不得混用）。
- 中文关键字 1:1 替换的行数收益为 **0**，任何阶段不得把关键字替换计入省行。
- 每阶段交付时须附“行数归因表”：省的行数逐项归因到机制（默认初始化/计次循环/遍历/枚举/方法收拢/类收拢/闭包），归因不上的行数不得计入收益。

# §6 风险与诚实结论

## §6.1 五大风险（按严重度排，2026-11-18 v0.1 合并后为五条）

1. **换行语句结束规则误判（§2.5 D-07）**：换行既是语句结束符又是可忽略的空白（括号内、行尾运算符后），判定只依赖“上一行末尾”这一单向规则。风险形态：用户把二元运算符写在行首（直觉写法）时编译器拒绝且提示可能被误读为“表达式错误”；多行函数调用参数换行时括号深度计数一旦与字符串/注释内的括号互相干扰，NL 丢弃会错。缓解：S3 验收门设续行误判专项测试 20 例；诊断文案须在第一行就写“请把运算符留在上一行末尾”，不得只报“语法错误”。此风险无完全消除办法，只能靠测试与诊断压低——本设计承认这一点。
2. **`结束 结构名` 的嵌套错配与迁移成本**：八种结构各有结束名，嵌套三层以上时用户极易写错结束名；按文件模式单轨后，中文文件误写 `}` 即报错（对混写习惯的用户是摩擦）；迁移仍是人工重审（`循环` 一词在旧线与新设计里含义相反，`for` 三段式与旧 `switch` 形态在本设计下直接报错，机械替换会静默改变语义或漏报——这是迁移中最危险的一点，须人工重审，工具不得自动转）。缓解：结构栈诊断一次报清全部未闭合结构（§3.2）；迁移工具只做“拼写对照表 + 人工复核清单”，不做自动转换。
3. **双语接口与全角归一化的落差**：标准库按 §2.15 做双语接口后，用户写出的程序仍是“中英骨架 + 双语 API 调用”，与草案“中文原生”的承诺仍有落差（底层函数名、错误值、AsterUI 的 `aui_*` 登记点仍是英文）；全角与半角标点等价接受又使同一份源码可出现两种标点写法，`grep ','` 等 ASCII 工具搜不到全角写法的分隔符，风格检查须另立规则。缓解：S6 双语标准库验收抽查文档双语；本设计不承诺“全中文调用层”，此落差写进文档首页（§0.1 已写）；标点风格建议项目内统一，不强制。
4. **闭包提前到 S4 的 ABI/自举/env 成本**：闭包是 S4 里最重的增量——`Ty` 新增 Closure Kind 与签名表、代码生成新增 env 填充与 thunk 生成、stage 拒绝面扩大、difftest 须补“函数指针 + env 结构 + thunk”三件套对照；env 用 arena 永不释放，上限 256 字节/闭包，创建大量闭包（如列表每行一个回调）会持续耗尽 arena，且 env 悬垂责任全在程序员（视图悬垂同理）。缓解：S4 验收门单列 `cn-closure-checks.sh`（见 §5.1），env 超限编译期拒绝；arena 预算以计数器级应用实测为准，见 §7；若 S4 闭包验收不通过，S4 按停止规则拆分，闭包后行、类型深化先行。
5. **双前端 + HIR/MIR 的架构成本（v0.1 合并新增）**：双 Lexer/Parser 是两套前端代码，关键字注册表、诊断文案、测试语料都要按文件模式翻倍；HIR/MIR 是新增两层中间表示，AST 直出路径的搬移（S5）一旦出现产物哈希变化，定位面横跨三层（AST→HIR→MIR），比单文件编译器的定位面大得多。缓解：S3 的 AST 对等测试先行（HIR 立项前 AST 必须已对等）；S5 搬移时 difftest 全绿才允许删除 AST 直出路径（见 §3.0）；拆分按 S2–S5 阶段边界逐步做，拆分本身不得改变产物哈希（见 §3.0）。

## §6.2 行数收益诚实预判（估算口径，不给单点假精确）

- **中文关键字 1:1 替换本身省 0 行**（旧线已验证，新设计重申）：`变量 年龄: 整数 = 18` 与 `let 年龄: i32 = 18` 行数相同；`结束 如果` 与 `}` 行数相同（各占一行时）——`结束 结构名` 甚至比 `}` 更长（字符数），行数不增不减。
- **省行靠五项机制**（估算口径：以草案 §14 综合示例与计数器为底，按机制归因，区间表示不确定性）：
  - 默认初始化：每处“声明 + 赋值初值”可省约 0–1 行（无初值声明即默认值，省去显式 `= 0`/`= ""` 行）；综合示例里约 2–4 处，区间 **−2 至 −4 行**。
  - 计次/遍历循环：`计次循环 (次数 = 1, 5)` 替代三段式 `for` 头 + 循环变量声明，约每处 **−1 行**；`遍历循环 (姓名 -> 名单)` 替代“索引声明 + 下标循环 + 长度读取”，约每处 **−2 至 −3 行**。
  - `假如` 多值匹配：`是 20, 21` 一行替代两条 `如果` 分支头，约每处 **−1 至 −2 行**。
  - 方法/类收拢：成员方法省去“首参 `self: 指针<类>` 声明 + 强转”约每方法 **−0 行**（行数不变，只省行内字符——与旧线 B1 同结论）；类把 `结构 + 全局变量 + 具名回调` 收进类定义约每应用 **−3 至 −6 行**（估算，口径：以框架轮后紧凑计数器 124 行为底，见 §6.3 草稿 A 的归因）。
  - 闭包：每回调省去一个具名处理函数的样板（函数头 + `user` 强转 + `aui_state_set` + `aui_invalidate` + `return 0`，旧线实测每函数 7 行），紧凑写法下 3 个按钮回调约 **−18 行**（旧线实测口径：计数器整文件 160 行 → 紧凑闭包写法 139 行，卡片 42 行 → 21 行；该数是旧线闭包轮的实测数，本设计引用作口径，未在本设计下重测——见 §7）。闭包省的是回调样板行，不动脚手架（文件头、应用骨架、演示区约 102 行），故对框架轮后紧凑计数器 124 行，闭包最多再动其中回调部分的约 20 行，到不了 HuxerUI 32 行。
- **总预判**：综合示例（草案 §14，原文 63 行、其中非空行 48 行，见 §6.3 草稿 B 实测）新设计改写后非空行数**持平**（48 行对 48 行）——按含空行计 −15 行，但全部是空行删减，**语言机制在该示例上省 0 行**。此句是本设计的诚实结论，不得在汇报时省略。计数器整文件从框架轮后紧凑 124 行出发，新设计机制（含闭包）最多动其中约 20 行计数逻辑，脚手架（文件头、应用骨架、演示区）一分不动——**新设计靠语言机制本身到不了 HuxerUI 32 行**，到 32 行的差额在脚手架与状态模型上，不在本设计范围内。

本附录把 §2 各裁决落到一条可测试的诊断上；每条诊断须在对应套件里有一正一反两个用例。文案里的“请…”不是建议，是诊断正文的一部分。**诊断代码**（见 §2.15）：每条诊断在 S6 按 `[A-NNN]` 制落实错误码（A-001–A-003 词法、A-010–A-011 解析、A-020–A-021 包与注解、A-030 重复声明、A-040 权限、A-050 类型、A-060 暂未支持、A-099 兜底）；初版所写的 E1000–E5999 分段已被 A 制取代，工具与测试不得再匹配 `E1001` 这类编号；同一错误在中英文文件里代码相同、消息按文件模式选。

- A-01（D-03 撤销版，`空` 作变量类型）：`变量 x: 空 = 空` → `错误：'空' 不能作变量类型，请写具体类型`（第一个 `空` 是类型位置、第二个 `空` 是值位置，角色按位置可区分，本例报错是因为 `空` 不能作变量类型，不是因为歧义）。
- A-02（D-03 撤销版，`空` 作值合法）：`变量 p: 指针 = 空` 合法（`空` 在值位置是空指针字面量，值 0）；`如果 p == 空` 合法。反例：`方法 f(x: 空)` → `错误：'空' 不能作参数类型，请写具体类型`。
- A-03（D-04，v0.1 合并版，大写 U）：`变量 n: U整数 = 1` 合法，注册时归一化为 `u整数`；风格提示“无符号类型请用小写 u：'u整数'”（提示非错误，见 §2.3 D-04）。上一轮“`U整数` 拒绝”的诊断已废止。
- A-04（D-04，u 与类型名分开）：`变量 n: u 整数 = 1` → `错误：'u 整数' 须连写为 'u整数'`。
